# MIPRO：联合优化指令与示例，但额外收益取决于任务

*Reel 解读：[arXiv 2406.11695v2](https://arxiv.org/abs/2406.11695v2)，原题 **Optimizing Instructions and Demonstrations for Multi-Stage Language Model Programs**（HarnessRSI Daily 评分 64，★★）。作者依次为 Krista Opsahl-Ong、Michael J Ryan、Josh Purtell、David Broman、Christopher Potts、Matei Zaharia、Omar Khattab；前两位同等贡献。本 Reel 未提供代码链接。*

## 系统改变了自己的什么

MIPRO 改变语言模型程序中**每个模块的自由文本指令与少样本示例**，跨模块联合选择这些提示组件；它不修改模型权重，也不搜索程序控制流。优化信号是下游任务指标，而非中间步骤的金标准标签。

## 迭代回路与保留/拒绝规则

1. 在训练输入上运行程序，自举各模块的输入/输出轨迹。当最终输出达到指标阈值时，保留轨迹作为候选示例；中间步骤因整条轨迹成功而被视为有用，并未逐步独立验证。
2. 由提议模型结合训练数据摘要、程序信息、成功示例和提示技巧，生成候选指令。
3. 用多变量树结构 Parzen 估计器（TPE），跨模块选择**指令与示例集的联合组合**。
4. 在随机训练小批量上评测整个程序，按端到端得分更新代理模型；周期性地在完整训练集上评测有希望的组合，最后返回完整评测得分最高的配置（§4.3）。这是正文的描述：附录 F.1（p19）改称在 dev 上给 Bootstrap 候选打分，F.5（p21）则称在验证集上选择 MIPRO 配置；§4.1（p5）允许用训练集或其专用验证划分。因此各方法实际使用哪个选择划分仍不明确；这不是使用测试集选择或发生泄漏的证据。

留存产物是配置好的程序提示词。**0-Shot MIPRO++ 是另一变体**：它学习如何提出指令，包括摘要开关、温度、技巧、向提议者展示哪些示例；并非同时联合优化部署时的示例。**温度优化的范围尚未解决：**§4.4（p6）写的是提议模型温度，附录 B.4（p14）却称 MIPRO++ 优化 Llama 模型的温度，同时把 GPT-3.5／GPT-4 列为提议模型。仅凭 PDF 无法确定是否也调了任务模型的采样设置；我们不按任何一种解释归因收益。

### 谁提供优化信号？

任务模型为 Llama-3-8B。附录 B.4 指定一般使用 GPT-3.5 提议，在 ScoNe、HoVer 和 Iris 使用 GPT-4；§5.2 给出的是较概括的 GPT-3.5 默认说明。示例教师默认是 Llama-3-8B，在 ScoNe 和 HoVer 改用 GPT-4o。这些角色不是 LLM 评审团：选择依靠精确匹配、分类准确率、金标准文档检索指标，或精确匹配加格式检查。HotPotQA Conditional 的答案类型由 GPT-4 在作者监督下标注，供指标使用；这是上游标注依赖，不是提议模型在优化过程中给自己打分。

## 论文报告的主要结果

表 2 是**五次运行的均值**，不是最佳种子。使用 Llama-3-8B 时，联合 MIPRO 在七种设置中的五种获得最高测试均值。以下逐列比较最强的其他优化器，而不只比较未优化程序：

| 测试任务／指标 | MIPRO | 最强的其他优化器 |
|---|---:|---|
| ScoNe 精确匹配 | 79.4 | 77.4，Bayesian Bootstrap |
| HotPotQA 精确匹配 | 46.4 | 46.2，Bayesian Bootstrap |
| HoVer，3 条支持事实子集，Recall@21 | 39.0 | 37.6，Bayesian Bootstrap |
| HotPotQA Conditional 自定义得分 | 23.3 | 14.6，0-Shot MIPRO |
| Iris 准确率 | 88.6 | 94.1，Bootstrap RS |
| Iris-Typo 准确率 | 68.7 | 58.7，Bootstrap RS |
| Heart Disease 准确率 | 74.2 | 79.2，Bootstrap RS |

**HoVer 范围：**附录 A（p13）只评测有三条支持事实的样本，并非完整基准。不同事实可能出自同一文档：约 67% 的训练样本、83% 的测试样本真正需要三跳，其余为两跳。作者建议后续研究按真正的三跳需求筛选。此处 HoVer 分数及划分数量均指这一混合跳数的三条支持事实子集。

最大的正向差距集中在 **Conditional 与 Iris-Typo**。摘要的“最高 13%”可由 Conditional 相对仅优化示例的 Bootstrap RS（23.3 对 10.4）的差距取整解释；它不是相对该列更强的仅指令优化器 14.6 的差距。不必把它解释成未解决的正文／表格冲突。

## 决定收益是否可信的对照实验

- **逐个基线能优化什么。** Bootstrap RS 可以自举示例并随机搜索选择，但指令固定；Bayesian Bootstrap 可以用 TPE 搜索示例；0-Shot MIPRO 只搜索指令，0-Shot MIPRO++ 还学习指令提议设置。Module-Level OPRO 利用模块历史与程序整体代理分数生成指令；其 grounded 版本获得额外任务／程序上下文。OPRO −G 的元提示中仍有示例和指令／得分历史，并非没有任务信息。未优化程序不进行搜索。表 2 中只有完整 MIPRO 联合搜索两类部署组件。
- **联合与单组件搜索。** Conditional 上仅指令 14.6 高于仅示例 10.4，联合达到 23.3；Heart Disease 上仅示例 79.2 高于联合 74.2。联合搜索并非普遍更好。
- **Grounding 也会有害。** Module-Level OPRO 有／无额外 grounding，在 ScoNe 为 73.5 对 76.1，HotPotQA 为 39.0 对 36.0，HoVer 为 32.5 对 25.7。这不是对完整联合 MIPRO 的直接 grounding 消融。
- **学习提议策略的结果不一。** 仅指令 MIPRO++ 对 MIPRO，ScoNe 为 75.7 对 71.5，HotPotQA 为 39.3 对 36.8，但 HoVer 为 32.6 对 33.1。ScoNe 最好的仅指令均值仍是 OPRO −G 的 76.1。
- **统计检验不等于种子离散程度。** 表 2 平均五次运行，以粗体标出 Wilcoxon 显著性；§5.2 描述的是对每条测试样本跨运行平均后的得分进行检验。HotPotQA 的 46.4、46.2、45.8 在统计上可比。因此五个最高均值不等于五个显著胜出；§6 将 HotPotQA、Iris 和 Heart Disease 列为例外。表 2 没有 SD、CI 或明确的种子编号。附录 G 曲线和附录 H 提示演变仅为单次示例运行，不是方差估计。

## 数据划分、预算与成本

表 3 明确：**训练集用于训练优化器，dev 用于方法迭代，测试集用于最终报告**。训练／dev／测试数量分别为 HotPotQA 500/500/2000，Conditional 500/200/200，ScoNe 500/500/1200，HoVer 500/500/1520。Iris 为训练 75、测试 75；Heart Disease 为训练 120、测试 183。后两者没有 dev，也未用于方法迭代。这些是同一基准内的留出样本，不是冻结提示词后的跨任务迁移。我们遵循主实验声明的划分用途，但如上所述，附录 F 的 dev／验证集选择描述使各方法实际的选择划分仍未解决，不能仅凭 PDF 完整还原 dev 的隔离情况。

附录 B.3 称候选数量等默认值来自此前实验积累的直觉，而非广泛扫描；没有单独说明每个默认值由哪个划分选定。论文报告了划分用途，但没有明确的重叠／污染审计或详细的分组、随机划分协议。优化与评测针对相同任务分布，留出样本不能证明新任务迁移。附录 H 明确承认指令会过拟合元提示中的示例。

**基线搜索预算是有报告的。** 附录 B.2 按任务为优化器设定预算：HotPotQA 与 ScoNe 为 50 次完整评测试验（约对应 300 次小批量试验）；Iris、Heart Disease、Conditional 为 30 次；HoVer 为 20 次。这是部分评测预算匹配，不是总 token 或 LM 调用数相等。提议、摘要和教师生成的成本没有逐项统计；总优化 token／调用数以及美元成本均未报告。不同方法的候选数量不同，也未给出基线单独的超参数调优预算。不能把试验次数换算成已经验证的全成本比较。

## 增益缺失或较小之处

HotPotQA 的微弱领先与仅示例搜索没有显著区别。MIPRO 在 Iris（88.6 对 94.1）和 Heart Disease（74.2 对 79.2）上输给 Bootstrap RS。仅指令 MIPRO 甚至可能低于未优化程序：Iris 为 36.4 对 40.9，Heart Disease 为 25.8 对 26.8。Conditional 的规则由手写种子指令提供，实验并未证明能自主发现全部任务规则。评测使用一个任务模型设置，没有跨模型迁移研究。

## 我们的解读（Our read）

HarnessRSI 评分 **64**，档位 **★★**，证据等级 **retained**。论文报告了留存提示配置在留出测试集上的表现、多次运行及显著性检验、组件对比和部分匹配的评测预算；没有确立跨任务迁移、全成本优化开销、泄漏审计结果或种子离散程度。已有判定将 variance 证据标为存在；更准确地说，公开证据是重复运行均值与显著性检验，**并非 SD／CI**。最有用的实践启示是：除了指令，也要优化示例，但应检查联合搜索的额外收益是否真的出现在当前任务上。
