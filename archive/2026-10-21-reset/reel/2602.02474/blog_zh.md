# MemSkill：强化学习控制器挑选记忆技能，LLM 设计器改写技能——收益的方向成立，但没有方差、也没有算力匹配对照

*Reel 解读：[arXiv 2602.02474v2](https://arxiv.org/abs/2602.02474v2)（HarnessRSI Daily 评分 70，★★★）。代码：[ViktorAxelsen/MemSkill](https://github.com/ViktorAxelsen/MemSkill)。*

## 系统改变了自己的什么

MemSkill 把 LLM 智能体固定的记忆操作（增、改、删、跳过）换成一个**技能库**：每个技能是一段短文本指南，包含描述、目的、何时使用、如何应用和约束。被学习或被编辑的有两样：

- **控制器**（三个小型 MLP）：对对话的每个片段给技能库中所有技能打分并选出 Top-K，用 PPO 训练；
- **技能库本身**：由一个固定的**设计器** LLM 编辑。论文没有说明设计器用的是哪个模型。

执行器 LLM 读入该片段和所选技能，一次调用写出记忆更新。基础 LLM 的权重始终不变。技能库从四个基本技能开始：INSERT、UPDATE、DELETE、SKIP。

## 信号与保留/拒绝规则

1. 控制器为每段训练对话构建记忆库；随后用该记忆回答这段对话的训练问题，得分（F1 或成功率）作为 PPO 的奖励。
2. 答错的问题连同标准答案、预测和失败次数进入滑动窗口的困难案例缓冲区。奖励低且反复失败的案例排名最高；它们被聚类，各簇的代表案例交给设计器。
3. 每 100 个训练步，设计器分析这些案例，最多提出 3 处修改（改写已有技能或新增技能）。删除和空操作技能不参与进化。案例按难度分数排序；按论文所印公式（d = 1 - r × c），失败次数越多分数越低，与正文相矛盾，因此我们只依据正文。
4. 保留/拒绝：系统保存最佳技能库的快照（回滚时控制器权重如何处理，论文没有说明）。一个周期的得分是该周期训练步最后四分之一的平均奖励；若未超过历史最佳，则在下一次进化前回滚到最佳快照；在固定耐心（数值未给出）内没有改善就提前停止，返回最佳快照。每次更新后，控制器会在 50 步内被推向新技能。

因此，选择信号是训练集上的奖励，而不是留出集的得分。

## 决定收益是否真实的对照

- **消融（表 2，LoCoMo L-J，LLaMA / Qwen，单次运行）。** 完整 MemSkill 为 53.82 / 54.14。随机选技能（w/o Ctrl）48.43 / 42.84。关闭设计器、技能库固定为四个基本技能（w/o Des）46.50 / 36.15。只改写不新增（Ref.-only）47.45 / 48.88。按论文数字，每个组件都有贡献。在 LLaMA 上，三个消融变体都低于 A-MEM（49.71）和 LightMem（51.95）；在 Qwen 上，Ref.-only（48.88）低于 CoN（50.96）。论文没有说明每个变体是否重新训练了控制器，也没有说明表 2 用的是哪个数据划分（完整模型一行与表 1 相同，大概率是测试集）。
- **迁移。** LongMemEval 使用 LoCoMo 上训练出的技能库评测，但 LongMemEval 的验证集被用来调整数据集相关的配置（附录 B.1），测试样本约 100 道题。HotpotQA（图 3，LLaMA L-J，技能来自 LoCoMo，50 / 100 / 200 篇拼接文档）：K = 7 时，MemSkill 在三种长度下都高于 MemoryOS 和 A-MEM，200 篇文档时优势更大。图中只有 MemoryOS 和 A-MEM；论文称它们是表 1 中"对话基准上最有竞争力的方法"，但在 LLaMA 上 CoN 的对话平均分（49.08）高于 MemoryOS（44.24）和 A-MEM（43.88），而 CoN 和 LightMem 都没有出现在图中。这些柱状数值只出现在图中，因此列在 SOURCE.md 和海报上。
- **成本（表 3，LoCoMo，仅运行时）。** 片段长度为 512 时（默认值；L-J 与表 1 相同，为 53.82），MemSkill 用 249K 输入 token、18K 输出 token、215 次 LLM 调用；MemoryOS 为 1013K / 165K / 1288 次（L-J 48.64），A-MEM 为 2850K / 362K / 1548 次（49.71），LightMem 为 789K / 209K / 685 次（51.95）。其他片段长度（128、256、1024、2048）的 L-J 分别为 53.14、51.61、48.11、50.46：主结果采用的是同一次 LoCoMo 运行中五种长度里最好的一个，论文没有说明为何选 512。论文称学习并进化技能库属于部署前成本、可被摊销，并未报告该成本（只提到训练使用 A6000 GPU）。
- **未做的对照。** 论文没有说明基线获得了哪些训练、调参或进化；没有报告基线的调参预算、算力匹配对照或基线方差。设计器只与"无设计器"和"只改写"比较，没有与另一种记忆技能进化方法比较（ExpeL 和 AWM 作为额外基线出现在表 4 至表 6，仅限 ALFWorld / AppWorld）。

## 收益缺失或很小的地方

- **Qwen 上的 LongMemEval F1：MemSkill 不是最好。** 25.29，而 CoN 为 29.19，Mem0 为 27.36（其 L-J 为 60.40，遥遥领先）。在 LLaMA 上，F1 相对 CoN 的优势为 31.12 对 30.78。
- **其他地方优势很薄。** LLaMA 上 LoCoMo L-J 为 53.82，LightMem 为 51.95（差 1.87‡；表 3）。LLaMA 上 ALFWorld Unseen 为 83.58 对 81.34（Mem0）；论文没有给出测试集规模，但若使用官方的 140 个 Seen / 134 个 Unseen 任务（我们的推断），Seen（77.14 对 75.00）和 Unseen 的差距各为 3 个任务，Qwen Unseen（76.87 对 71.64）为 7 个任务。在 AppWorld 带上下文示例的设置下（LLaMA，平均通过率），MemSkill 为 47.32，AWM 为 47.11，Mem0 为 47.03，No-Memory 为 46.41；论文自己也指出该设置"部分饱和"。去掉示例后为 26.71 对 AWM 的 25.42（差 1.29‡；Mem0 为 24.32）。8B 模型上（表 7），LoCoMo L-J 为 27.23，LightMem 为 26.85。
- **HotpotQA 依赖 K。** K = 3（训练时的取值）下，MemSkill 在 50 篇和 200 篇文档时都低于 MemoryOS 和 A-MEM（图 3 的柱标数值，列在 SOURCE.md 中）；K = 5 在 50 篇文档时同样低于二者（100 和 200 篇时高于二者）。100 篇文档时 K = 3 高于 K = 5，所以"增大 K 通常提升性能"并非单调，"一贯优于基线"只对 K = 7 成立。正文没有说明 K 是如何选的。
- **ALFWorld 差距的表述。** 附录 A.1 称 MemSkill 超过"最强基线 LightMem 5.53 分"（80.36 对 74.83），在 Qwen 上超过"Expel 7.61 分"（81.29 对 73.68）。若理解为"新增基线中最强"，这是对的；在表 1 中，LLaMA 上 Mem0 的平均值为 77.82，Qwen 上 CoN 为 74.02，因此相对整体最强基线的差距是 2.54‡ 和 7.27‡。
- **测试集小、没有区间。** LoCoMo 按对话切分（10 个样本，6/2/2），测试集约为两段对话（按每段约 200 个问题估算，剔除对抗性问题之前约 400 个问题；我们的推断）。论文没有给出置信区间或重复运行。
- **局限性一节。** 论文的局限性段落只谈隐私和部署。

## 我们的看法

HarnessRSI 评分 **70**，★★★，证据等级 **improver**：改进机制本身（设计器、控制器）被消融并作了比较，LoCoMo 上训练的技能还在另一个基准、另一类数据集和另一个基础模型上做了测试。论文报告了留出迁移、跨任务迁移、消融和运行时成本对比。论文没有报告跨种子或多次运行的方差、与基线的算力或调参匹配对比、训练并进化技能库的成本，也没有泄漏测试。因此，主结果建立在小测试集上的单次运行数字之上；方向在各模型和基准上一致，也有若干列没有收益。

*标有 ‡ 的数字由我们根据论文中的数字计算得出，详见 SOURCE.md。*
