# M⋆：让编码智能体改写 LLM 智能体的记忆——收益有多大，要看你读哪一条对照

*Reel 解读：[arXiv 2604.11811v2](https://arxiv.org/abs/2604.11811v2)（HarnessRSI Daily 评分 90，★★★）。代码：[wbopan/mstar](https://github.com/wbopan/mstar)。*

## 系统改变了自己的什么

M⋆ 把智能体的**记忆框架（memory harness）**当作一段程序来搜索。一个记忆程序是接口固定的 Python 模块，由三部分组成：**Schema**（用 dataclass 规定存什么、怎么查）、**Logic**（`write()` / `read()`，可调用 SQLite、向量库或 LLM）、**Instruction**（告诉任务智能体如何提取、查询、解读记忆的提示词常量）。三者被一起修改——搜索对象是记忆框架本身，而不是设计者预先指定的几个模块。

## 迭代回路与保留/拒绝规则

1. 从三个简单的种子程序出发。
2. 按静态验证集得分做 softmax 采样（τ = 0.15）选出父程序。
3. 在 5 条轮换验证样本上运行父程序，把成功与失败的轨迹、以及此前各轮的变更日志交给编码智能体（GPT-5.3-Codex），由它写出代码补丁。
4. 做编译与运行时检查（输出 ≤ 3000 字符、≤ 60 秒、冒烟测试）。失败的子程序送回自动修复，最多 3 次，仍失败则丢弃。
5. 子程序在静态验证集上打分并加入程序池。

迭代 20 轮后，取验证集上最好的程序，在留出的测试集上评测一次。任务智能体为 GPT-5.4 Mini。模型权重没有任何改动，被保留下来的是代码。

## 论文报告的主要结果

在四类基准（七种配置）和九个基线上，M⋆ 在 8 项指标中的 7 项取得最好成绩（表 1），相对每列最强基线的提升"最高 31%"。

| 基准（测试集） | M⋆ | 最强基线 |
|---|---|---|
| LoCoMo token F1 | 0.459 | 0.373（Mem0） |
| HealthBench Data | 0.390 | 0.327（GEPA + Vector Search） |
| PRBench Legal | 0.660 | 0.568（GEPA） |
| PRBench Finance | 0.586 | 0.449（GEPA） |
| ALFWorld Unseen 成功率 | 0.881 | 0.857（GEPA） |

各任务进化出的程序有所不同（最优程序均使用 SQLite，差别在向量检索与读取时的 LLM 调用）：ALFWorld 最优程序是紧凑的 SQLite 动作缓存，读取时调用一次 LLM；LoCoMo 最优程序把 ChromaDB 语义检索与 SQLite 词法、元数据打分结合起来。

## 决定收益是否可信的对照实验

- **消融（LoCoMo F1，表 2）。** 完整系统 0.459。只进化提示词、代码固定为 Vector Search 种子：0.256；固定提示词、只进化代码：0.353；总是选最高分父代而不做 softmax 采样：0.381；去掉种群、只变异当前最优：0.318。代码部分与种群都起作用。表 2 未报告方差，且完整系统的锚点（0.459）是种子 0，高于五种子均值 0.421；四个消融变体中有三个（0.353、0.318、0.256）低于 Mem0 的 0.373，仅提示词的变体与 Vector Search 同为 0.256。“− Diversity”变体还从单个空种子出发。
- **随机种子（表 3）。** 五个进化种子，但只在七种配置中的三种上做。LoCoMo 为 0.421 ± 0.042，Mem0 为 0.373（5 个种子中 4 个更高）；HealthBench Data 为 0.391 ± 0.023，对照 0.327（5/5）；PRBench Finance 为 0.561 ± 0.032，对照 0.449（5/5）。表 1 的数字对应其中的种子 0。LoCoMo 与 PRBench Finance 的五种子均值（0.421、0.561）低于表 1，HealthBench Data 则相同（0.391 对 0.390）。LoCoMo 均值只比 Mem0 高 0.048‡，而不是头条数字对应的 0.086‡。
- **跨任务迁移（图 5）。** 在某任务上进化出的程序，在该任务上胜过在其他任务上进化出的程序；六个迁移程序中有五个低于通用种子。以 LoCoMo 为例，种子 0.26，原生程序 0.459，在 ALFWorld 上进化的程序仅 0.02。
- **成本（附录 D.1）。** 一次 20 轮进化花费 $12–90（LoCoMo 为 $25.43，PRBench Legal 为 $90.19），ALFWorld 的墙钟时间约 100 小时（论文归因于环境交互）。论文称进化是一次性成本，进化出的程序每次查询额外增加 0–2 次 LLM 调用。论文列出成本的基线（No Memory、Vector Search）每次运行仅 $0.31–$1.51。论文没有报告算力匹配的基线，没有给出 GEPA（同样在验证数据上优化的基线）的调参预算，也没有报告任何基线的方差。

## 增益缺失或较小之处

- **ALFWorld Seen：M⋆ 不是最好。** 0.700，低于 GEPA + Vector Search（0.820）、Trajectory Retrieval（0.780），以及两个 0.720 的基线；与榜首相差 0.120‡。
- **小测试集上的微弱优势。** HealthBench Emergency 为 0.493 对 0.487（Dynamic Cheatsheet）；ALFWorld Unseen 为 0.881 对 0.857。测试集只有 50–100 条，论文未给置信区间；ALFWorld Unseen 在表 5 中为 50 个 episode，但附录表 10 各类别数量之和为 42，因此 0.881 对 0.857 的差距只是一个 episode。
- **LoCoMo 按问题类型。** M⋆ 在开放域问题上最强（0.51），单跳与 Mem0 持平（0.33），但时序问题仅 0.19，GEPA + Vector Search 为 0.38。开放域问题占 LoCoMo 100 条测试题中的 55 条，表 4 各类别得分加权后约为 0.41‡，而非表 1 的 0.459，论文未解释该差异。作者指出，聚合目标可能让更难的类别被忽略。
- **作者自述的局限。** 只试过一组任务智能体 / 编码智能体；进化可能滑向任务特定的启发式（如 ALFWorld 缓存里的同义词表），从而限制迁移。

## 我们的解读（Our read）

HarnessRSI 评分 **90**，档位 ★★★，证据等级 **improver**：改进机制本身（种群选择、指令与代码分别进化）被改动并做了对比，并且在留出数据上评测。论文报告了留出集评测、跨任务迁移、三种配置上的多种子方差、优化器成本与消融；没有报告对基线的算力匹配比较，也没有检验验证集与测试集之间的泄漏（LoCoMo 的二者来自同一批对话）。头条表格对应每种配置的一个进化种子；多种子结果表明增益方向成立，在 LoCoMo 与 PRBench Finance 上幅度更小。
