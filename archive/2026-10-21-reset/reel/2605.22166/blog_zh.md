# Life-Harness：演化冻结智能体外围的运行时接口——相对无 harness 的智能体提升很大，对最强基线则是一场更接近的比较

*Reel 解读：[arXiv 2605.22166v3](https://arxiv.org/abs/2605.22166v3)（HarnessRSI Daily 评分 72，★★★）。代码：[Tianshi-Xu/Life-Harness](https://github.com/Tianshi-Xu/Life-Harness)。*

## 系统改变了自己的什么

Life-Harness 不动模型。求解器（Qwen3-4B-Instruct）被冻结，环境与评分器不变，被演化的是两者之间的**运行时 harness**。它分四层，分别挂在交互回路的不同位置：

1. **环境契约层（Environment Contract）**（交互前）：把澄清后的工具描述、策略约束和常见陷阱，替换原契约展示给模型。
2. **过程技能层（Procedural Skill）**（任务条件化阶段）：由训练轨迹提炼出技能库；用 BM25 检索 top-1 技能，插入系统提示。
3. **动作实现层（Action Realization）**（执行前）：检查动作是否可执行，规范化无歧义的接口级错误，拦截必然失败的动作。
4. **轨迹调控层（Trajectory Regulation）**（反馈后）：检测重复、停滞或预算耗尽，并触发恢复提示。

论文用失败诊断来说明这样分层的动机：对 393 个 Qwen3-4B 训练集失败回合（由 LLM 标注，所有标注经人工检查）做归类，约三分之一是轨迹退化（33.6‡%），三分之一是环境契约不匹配（33.3%），23.2‡% 是动作实现失败，9.9% 是一般推理错误，各环境的构成差异明显。

## 迭代回路与保留/拒绝规则

1. 用当前 harness 在一批最多 50 个训练任务上运行冻结的求解器。
2. 演化 LLM（GPT-5.5）阅读轨迹和当前 harness，找出反复出现的失败，写出候选版本；候选可在四层中的任意一层增加、修改或删除机制。
3. 候选必须通过接口检查和训练轨迹回放；不通过则退回修复，最多三次。
4. 有效候选与当前 harness **在同一批训练任务上**用基准自带的评分器比较，仅当准确率严格提升才替换；否则保留当前 harness，下一轮换一批新任务。
5. 六轮后，保留下来的 harness 被冻结，在留出任务上评测。划分见表 5：例如 ALFWorld 训练 100、测试 109，tau-bench Airline 为 30 和 20，Retail 与 Telecom 为 74 和 40。

最终的 harness 是相当大的环境专属程序（表 7–9）：任务解析器、状态跟踪器、动作校验器，部分环境还有强制下一步动作或强制提交答案。论文自己的说法是 harness"针对特定环境、但与模型无关"。

## 论文报告的主要结果

Qwen3-4B-Instruct，测试集，Pass@1 准确率（%），每个环境一个演化出的 harness，三种演化方法都在相同的训练批次上做六轮演化（表 1）：

| 环境 | 无 harness | Meta-Harness | AHE | Life-Harness |
|---|---|---|---|---|
| ALFWorld | 16.5 | 35.8 | **89.0** | 88.1 |
| WebShop | 29.5 | 42.5 | 39.0 | **45.5** |
| OS | 21.5 | 25.7 | 37.5 | **39.6** |
| DBBench | 44.0 | 50.3 | 57.3 | **65.0** |
| tau-bench Airline | 35.0 | 11.7 | 35.0 | **60.0** |
| tau-bench Retail | 48.0 | 33.3 | 45.8 | **63.0** |
| tau2-bench Telecom | 25.8 | 50.8 | **95.0** | 90.0 |

分组均值：AgentBench 为 27.9 / 38.6 / 55.7 / 59.5；tau 系列为 36.3 / 31.9 / 58.6 / 71.0。在七个环境上，论文报告 Life-Harness 的平均准确率比 Meta-Harness 高 28.7 个百分点、比 AHE 高 7.5 个百分点（Life-Harness 均值 64.45），演化 token 分别少 8.5% 和 68.4%；七个环境中有五个取得最高准确率。更严格的 Pass3（三次运行全部成功）下，tau 均值为 12.5 / 18.3 / 44.2 / 57.5。

## 判断收益是否真实的对照

- **基线。** Meta-Harness 与 AHE 由作者用开源实现"在相同条件下"运行：相同的求解器、演化 LLM、rollout 设置、六轮、相同的训练批次。AHE 原本为编程智能体的 harness 设计（相关工作一节），这里是作者的复现。轮数和批次是对齐的，演化 token 不是（表 1：两个分组均值上 AHE 为 9.9 和 8.2（10^7 token），Life-Harness 为 2.5 和 3.5）。论文没有给出基线的调参预算，也没有重复运行。成本只统计演化 LLM 的 token，不含求解器和评测用量。
- **逐层移除消融（表 4，Qwen3-4B）。** 数值是相对完整 harness 的相对准确率下降，未报告标准差，论文也没有说明被消融的变体是重新演化的，还是直接从最终 harness 中去掉了该层。移除动作实现层，Airline 下降 61.7%、OS 下降 59.6%；移除轨迹调控层，ALFWorld 下降 86.5%、Telecom 下降 36.2%；移除契约层或技能层，任一环境下降都不超过 17.5% / 17.4%，ALFWorld 上约 1%。论文的结论是：每一层都在某些基准上起作用，影响随环境而异。
- **仅提示词演化（图 6）。** 论文正文称提示词优化相对基线有提升，且 Life-Harness 在全部七个环境的 Pass@1 都更高。该图没有标数值；从柱高大致读出，提示词演化在 ALFWorld、OS、WebShop 上与未改动模型相当或更低，在 DBBench、Airline、Retail、Telecom 上更高。正文没有给出提示词优化器的预算。
- **跨模型迁移。** Qwen3-4B 的 harness 不重新演化，直接用于另外 17 个开源模型（指令、推理、agent 训练类）：126 个模型-环境组合中有 116 个提升（图 5），加上 AppWorld 为 144 个中的 132 个。在三个前沿模型上，同一批 harness 的平均提升为 2.8（GPT 5.5）、4.4（Opus 4.8）、3.4（Gemini 3.1 Pro）个百分点，21 个组合中 18 个提升（表 2）。Qwen2.5-32B-Instruct 加上 Life-Harness 后，在 tau-bench 上比经过工具训练的 xLAM-2-32B 高 7.5 个百分点（图 7）。
- **ALIGN 与 AgentSquare（表 11）。** 评测它们公开发布的 harness，在 ALFWorld 和 WebShop 上、18 个骨干模型下比较；三者之中 Life-Harness 在每个 ALFWorld 行都最高，WebShop 大多数行最高（例外：Qwen3.6-27B 为 43.00 对 AgentSquare 47.00，Llama-xLAM-2-70B 为 42.00 对 50.00，Qwen3.5-35B-A3B 持平于 43.00）。未改动的模型在两个 ALFWorld 行上持平或更高（Qwen3.5-27B 88.99 对 88.99；Qwen3.6-27B 90.83 对 89.91）。论文说明："ALIGN 沿用其发布的任务划分；AgentSquare 使用 Life-Harness 的任务选择"。也就是说 ALIGN 并非在相同任务上评分，且两者都是公开发布的最终 harness，并未在表 1 的条件下重新演化。
- **AppWorld（表 3）。** 18 个骨干模型的平均 Pass@1 从 25.5 升到 30.8（18 个中有 16 个提升）；AppWorld 测试集为 57 个任务。

## 收益缺失、较小或在噪声范围内之处

- **并非处处最好。** ALFWorld 上 AHE 更高（89.0 对 88.1），Telecom 上也是（95.0 对 90.0；Pass3 为 87.5 对 77.5）。WebShop 与 OS 上 Life-Harness 对最强基线只领先一小截（45.5 对 42.5；39.6 对 37.5）。
- **基线的表现。** Meta-Harness 在 Airline（11.7 对 35.0）、Retail（33.3 对 48.0）和 tau Pass@1 均值（31.9 对 36.3）上低于未改动的模型；AHE 在 Retail 上低于它（45.8 对 48.0）。ALIGN 与 AgentSquare 也常低于未改动的模型（例如 Qwen3-4B 在 WebShop：18.00 和 18.50 对 29.50）。因此 Life-Harness 的部分优势，是相对于在这些运行中没能超过无 harness 智能体的基线取得的。表 12 也显示训练批次上的曲线对测试结果说明有限：Meta-Harness 在 Airline 上六轮的训练批次准确率都是 30.00，测试却只有 11.7，而未改动模型为 35.0；AHE 在 Retail 上的训练批次准确率从第 3 轮的 50.00 降到第 6 轮的 20.00，测试为 45.8。论文没有说明评测所用的是哪一轮的 harness，基线和 Life-Harness 都是如此。
- **相对 Meta-Harness 并非处处更省。** Life-Harness 的演化 token 在 WebShop（3.8 对 3.7）、Retail（2.6 对 1.4）、Telecom（4.3 对 2.1）和 tau 均值（3.5 对 3.0）上多于 Meta-Harness；8.5% 的节省是七个环境的合计值。
- **tau 测试集小，且无方差。** Airline 只有 20 个测试任务（一个任务相当于 Pass3 的 5 个百分点），Retail 与 Telecom 各 40 个。AgentBench 每个任务运行一次，tau 每个任务三次，温度 0.0；论文没有报告随机种子、标准差或置信区间，论文每个环境只给出一个 harness，未报告重复运行。
- **收益在模型和环境之间不均匀。** 较大的推理模型在某些环境上接近零或为负：Qwen3.5-27B 在 Airline 为 −3.3、ALFWorld 为 0.0；Qwen3.6-27B 在 Airline、Retail、ALFWorld 分别为 −3.3、−0.8‡、−0.9‡。同样的模型在其他环境有提升（Qwen3.5-27B 在 WebShop +7.5、DBBench +5.7‡；Qwen3.5-35B-A3B 在 ALFWorld +17.4）。126 个开源模型组合中有 10 个没有提升。前沿模型中，GPT 5.5 在 Retail 上不变（72.5 对 72.5），Gemini 3.1 Pro 在 ALFWorld 上不变（96.3 对 96.3），且在 OS 上更低（50.0 降到 48.6）；GPT 5.5 同时也是演化 LLM。AppWorld 上论文强调 18 个骨干模型平均提升 5.3 个百分点，但并不均匀：Qwen3.6-35B-A3B 从 54.39 升到 73.68，Qwen3.6-27B 从 70.18 升到 82.46，而 Qwen3-4B 从 1.75 升到 5.26，另有两个模型持平。
- **论文内部不一致。** 表 13 中 Qwen2.5-32B-Instruct 的 15.10 和 20.40 不是 1/57 的整数倍（测试集 57 个任务），却计入 25.50 和 30.76 的均值；表 10 中 Qwen2.5-72B 在 Airline 加 harness 后为 0.6034，不是 1/60 的整数倍（20 个任务、3 次试验），并进入图 5 的 +18.7‡。本文照表中印出的值引用。
- **适用范围。** 每个环境单独演化一个 harness，没有测试向未见过环境的迁移；只覆盖文本和 API 类环境（论文局限性一节）。

## 我们的判断

HarnessRSI 评分 **72**，档位 ★★★，证据等级 **retained**：在训练任务上演化出的冻结产物（harness），在留出任务和其他模型骨干上得到评测。论文报告了：留出测试数据不参与演化、演化成本对比、逐层移除消融，以及与另外两种 harness 演化方法在相同轮数和批次下的比较。论文没有报告：跨种子或跨运行的方差、跨环境迁移、泄漏检验（演化提示词要求 LLM 不读取测试轨迹，但没有给出审计），也没有对自身的接受/拒绝规则做消融。基线预算在轮数和批次上对齐，而非在 token 上对齐。主表是每个环境一个演化出的 harness，测试集规模为 20–300 个任务，所以几个百分点的差距——尤其是 tau-bench 上——相当于一两个任务就能改变的范围。
