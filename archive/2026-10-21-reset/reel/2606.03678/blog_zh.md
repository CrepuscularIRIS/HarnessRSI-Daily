# EvoDrive：进化碰撞测试生成器，而非驾驶策略——真实性必须留在回路里

*Reel 解读：**EvoDrive: Pareto Evolution for Safety-Critical Autonomous Driving via Self-Improving LLM Agents**，[arXiv 2606.03678v2](https://arxiv.org/abs/2606.03678v2)。HarnessRSI Daily 评分 **65**，档位 ★★，证据等级 **improver**。任务未提供代码仓库。*

## 系统改变了自己的什么

EvoDrive 修改的是可复用的**场景生成器**：有界参数、带类型的仿真算子图、依赖场景的选择策略，以及可复用的交互机制。进化过程中不训练自车驾驶策略，不改变仿真评分规则，也不允许任意生成的代码。所有 LLM 角色均通过 Codex CLI 使用 GPT-5.5，推理强度为 xhigh。

优化目标不是直接让驾驶更安全，而是在固定驾驶策略上找到**更有效、仍然合理的攻击场景**。MetaDrive 的 attack 是目标碰撞率；真实性综合地图/车道有效性、初始不重叠、碰撞有效性、路线进度、轨迹连续性以及有界加速度/jerk，以 RP = 100(1 − R) 报告惩罚。CARLA 的 attack 为 CR(1 − OS)，结合碰撞率与驾驶总体评分；真实性 ARS 是有效率乘以运动学、地图、交互和距离一致性的加权组合，权重为 0.40、0.30、0.20、0.10。这些都是仿真诊断指标，不是经认证的真实世界安全概率。

## 迭代回路与保留/拒绝规则

1. Actor 读取当前父代、声明的编辑接口、搜索目标与历史记忆，提出有界、带类型的补丁。
2. 结构、攻击性、真实性与隔离 critic 决定批准、修复或拒绝。确定性验证器检查 schema、父代身份、合法编辑、受保护资源与可编译性；失败即停止仿真。
3. **世界评估器**在昂贵的闭环仿真前选择、拒绝或审计候选；高不确定性可以强制触发审计，而非直接拒绝。
4. 仿真标签决定存档资格：保留攻击—真实性平面中的非支配解。活跃后继还须满足超体积增长、局部前沿推进或有界的父代权衡规则。失败会保留为负面记忆，而不是成功存档项。
5. 独立的 world agent 可以修改路由评估器的特征、校准、排序、不确定性或阈值；确定性 judge 根据此前仿真证据决定是否晋升。这个评估器不能改写仿真标签，也不能直接让候选进入存档。

MetaDrive 每条谱系进化 10 轮，每轮 20 个并行提案槽，使用轮换的 20 场景开发窗口。500 个 Waymo 来源场景中，240 个用于进化，160 个额外场景用于扩充下游训练，100 个受保护用于评测。活跃生成器和最多三个前沿后代均在**进化池**上选择，测试前冻结。存档默认要求 R ≥ 0.95，相对容差为 0.05。论文没有说明这些默认值由哪个 split（如果有）选定，也没有报告基线超参数调优预算。

## 论文报告的主要结果

表 1 是 MetaDrive 在 IDM 与 RL 自车策略上的均值。PF-Area@3 是加入最多三个合格后代后，攻击—真实性超体积的百分比增长，**不是碰撞风险的下降比例**。

| 生成器 | 父代 attack → 进化后 | 父代 RP → 进化后 | PF-Area@3 |
|---|---|---|---|
| CAT | 0.345 → 0.330 | 10.66% → 3.85% | +7.4% |
| ADV-BMT | 0.260 → 0.295 | 2.27% → 1.77% | +18.7% |
| AT | 0.231 → 0.265 | 0.09% → 1.06% | +14.9% |
| SEAL | 0.211 → 0.245 | 0.07% → 1.02% | +15.9% |

八种生成器家族的平均前沿面积均提高，但其中多种以更高真实性惩罚换取攻击性。这是**父代与后代的对比**，不是每项指标都胜过独立最强基线。表 1 没有给出方差、置信区间或进化运行次数。

CARLA/SafeBench 在八类场景、每类十条路线中进化四轮。表 3 的 attack/ARS 为：AdvSim（0.260 → 0.382 / 0.544 → 0.615）、AT（0.197 → 0.330 / 0.514 → 0.607）、ChatScene（0.394 → 0.507 / 0.729 → 0.924）、Human（0.264 → 0.301 / 0.856 → 0.927）。对应 PF-Area@3 增长为 142.5%、255.7%、143.5%、73.7%。家族—路线均衡选样减少了组间样本量不平衡的影响；表中没有运行次数或不确定性。与 MetaDrive 不同，生成器评测协议没有明确给出互不重叠的进化/测试场景划分，因此不能排除场景重叠。

## 决定收益是否可信的对照实验

- **组件消融确实有重复运行。** 表 4 只针对 RL 自车上的 ADV-BMT，报告三次独立进化：完整系统 PF-Area@3 为 **31.0 ± 4.2%**，去掉 critic/repair 为 **26.8 ± 3.8%**，去掉长期记忆为 **19.1 ± 3.5%**，非 LLM 帕累托搜索为 **10.6 ± 2.8%**，LLM 调用数匹配的 actor-only 为 **21.2 ± 4.0%**。论文未说明 ± 是 SD 还是 SE。完整系统与无 critic 的范围重叠，未报告显著性检验。这些重复不意味着表 1、表 3 也有多次运行的不确定性估计。
- **每种对照实际获得了什么。** 每个 MetaDrive 来源家族都有声明的接口，后代可以进入相同存档。Actor-only 明确匹配总 LLM 调用数。非 LLM 帕累托搜索是独立提案对照，但未明确说明预算匹配。Attack-only 与 OpenEvolve 标量搜索使用相同评测设置和指标（表 8），没有说明总仿真/调参预算。前沿报告统一限制三个后代，也不能证明与未进化父代的总仿真成本相等。
- **改进器本身得到比较。** 表 5 在相同候选序列、相同仿真预算下比较排序。达到 90% 超体积所需归一化评测量，静态与进化评估器分别为 **0.60 ± 0.04、0.51 ± 0.03**；归一化 top-10 yield 为 **1.30 ± 0.06、1.44 ± 0.05**。进化评估器只使用此前轮次的标签。该表未说明运行次数及 ± 的含义。
- **独立真实性检查。** 表 2 在进化完成后，才用留出 rollout 与动作匹配的自然交通参考比较。八家族平均运动 JSD 为 **0.073 → 0.067**，交互 JSD 为 **0.091 → 0.081**，支持域外比例为 **7.4% → 6.0%**。自然交通 split-half 参考仍更好：**0.022、0.028、1.4%**。
- **有限但存在的迁移。** 在 SAC 上选择并冻结的场景，也提高了 CARLA BasicAgent 上的攻击分：**0.0612 → 0.1434**；搜索时 SAC 为 **0.3759 → 0.4477**（表 17）。这是跨驾驶策略的场景迁移，而不是广泛跨任务或真实世界迁移。表 16 另对两个 ChatScene 家族各测试了三个参数起点。
- **成本只对应一个代表性运行。** 附录 C.5 的四轮 CARLA 运行使用 232 次角色调用、5.097M 缓存输入 token、0.159M 输出 token，端到端 13.5 小时，估算 API 成本 $5.88。这不是完整仿真算力账单，也没有匹配的基线成本对照。

## 增益缺失或集中之处

**MetaDrive 对自车策略敏感。** ADV-BMT 的前沿增长在 RL 为 **33.4%**，IDM 仅 **4.0%**；AT 则相反，IDM 为 **25.6%**，RL 为 **4.1%**（表 11）。LLM-Attacker/IDM、KING/RL、STRIVE/RL，以及偏好 w = 0.50 的 SAGE/RL，前沿增长均为 **0.0%**。CAT 的活跃 attack 下降，但真实性改善。

**CARLA 均值变好不等于每类场景都变好。** ChatScene 的 crossing 碰撞率由 **0.930 → 0.870**，攻击变弱；AdvSim 与 AT 的 turning-obstacle ARS 仍为 **0.000**（表 12–14）。

**下游安全收益集中。** 用原始或进化后的 ChatScene 场景训练 SAC，路线不重叠的测试集平均 CR 为 **0.163 → 0.106**，OS 为 **0.854 → 0.884**（表 6）。CR 下降来自直行障碍、转弯障碍和右转三类；右转为 **0.350 → 0.000**。超车 CR 反而由 **0.050 → 0.200**，无保护左转维持 **0.500**，变道、闯红灯和交叉协商场景保持零碰撞。无保护左转 OS 也由 **0.711 → 0.682**。表 6 没有运行次数、方差或 CI。三次运行的说明对应的是 **MetaDrive 下游图 7**，不能套到这张 CARLA 表。MetaDrive 下游训练有意复用进化场景并加入额外训练场景；生成器选择与后续驾驶策略训练仍是分离的阶段。

## 我们的解读（Our read）

HarnessRSI 评分 **65**，档位 ★★，证据等级 **improver**。最有力的证据是有界且留存的生成器、受保护的 MetaDrive 测试、记忆消融与调用数匹配的 actor 对照，以及相同候选序列和仿真预算下的静态/进化评估器比较。存储判定的 variance 字段不完整：全文确实报告表 4 的重复运行、表 16 的初始化敏感性和 MetaDrive 下游三次运行曲线。我们不修改判定文件，每个重复声明只适用于它自己的实验。

论文未证明所有基线比较都匹配总仿真/调参预算，没有主要结果表的 CI、实测泄漏审计或部署安全证明。验证器约束的是声明接口内的仿真可接受性，并非驾驶策略安全的形式化保证。作者明确承认仅在仿真验证，可能遗漏未见驾驶策略、平台或真实部署的失败模式；硬件在环验证仍是未来工作。
