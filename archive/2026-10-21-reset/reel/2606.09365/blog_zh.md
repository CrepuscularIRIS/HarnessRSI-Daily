# SkeMex：保留有用的医疗推理技能，而不是保存每个历史病例

*Reel 解读：[arXiv 2606.09365v4](https://arxiv.org/abs/2606.09365v4)，完整标题 **Experience Makes Skillful: Enabling Generalizable Medical Agent Reasoning via Self-Evolving Skill Memory**（经验成就技能：通过自演化技能记忆实现可泛化的医疗智能体推理）。HarnessRSI Daily 评分 **67**，档位 ★★。代码：[manglu097/SkeMex](https://github.com/manglu097/SkeMex)。*

## 系统改变了自己的什么

SkeMex 改变的是外部**技能库**，不是模型权重。它把交互轨迹蒸馏成带适用条件、具体操作的可复用指令。三个分支分别存一般推理策略、任务级流程和细粒度工具操作。固定的 ReAct 执行器查询技能库；智能体可以采用、忽略或覆盖检索到的技能。

## 迭代回路与保留/拒绝规则

1. 给新病例分配临床操作类别，结合语义相似度、估计效用和随时间衰减的记忆强度检索六个技能。每个 episode 只在开始时检索一次，技能上下文在该病例内固定。
2. 在七步智能体预算内处理病例。轨迹缓冲区过滤基础设施错误、重复循环、过于简单的成功和达到最大步数的失败；保留有信息量的成功与失败，而不是全部轨迹。
3. 每经过 30 条轨迹，处理最多 20 条保留记录。分析阶段判断技能采用情况，并提出 CREATE、PATCH 或 NONE；变更阶段生成操作指令。新颖性与质量门控把重复内容转为补丁，并要求明确触发条件和可执行步骤。
4. 用相对类别移动基线的结果奖励，结合对正向、有害或忽略采用的判断更新效用。经验积累阶段，写作者可以看到参考答案或未满足的评分标准。这是有外部正确性信号监督的记忆构建，不是无监督地自我学习。
5. 每两个窗口治理一次：合并相似技能，效用低于 0.3 的技能可淘汰，效用至少 0.75 且使用至少 15 次的技能可晋升成熟；各分支容量限制也会清除低效用条目。

因此，保留规则是**内容审核加后续效用治理**，不是每次编辑都通过留出集上的回归测试。我们的理解：技能采用归因来自 LLM 对轨迹的判断，并非技能因果贡献的随机化估计。

## 论文报告的主要结果

离线评测在训练数据上构建记忆，**测试时冻结技能库**。表 1 平均七种域内配置，其中混合了准确率和 rubric 得分：

| 骨干模型 | 无外部记忆的 ReAct | 按平均分最强的记忆基线 | SkeMex |
|---|---:|---:|---:|
| DeepSeek-V3.2 | 48.20 | GSEM 52.24 | **56.08** |
| Qwen3.6-Plus | 48.63 | CFM 56.08 | **59.22** |

论文报告相对 ReAct 提升 +7.88 和 +10.59 个百分点。Qwen 直接使用 DeepSeek 构建的技能库，不重新蒸馏或改写。这些是跨基准平均分，**不是附有种子方差或置信区间的重复实验均值**。每格运行次数、随机种子、头条结果的检查点选择规则均未说明。

增益分布不均。DeepSeek 域内相对 ReAct 的最大变化在 MMMU：**46.04 → 66.91**；MedXpertQA-Text 为 **33.51 → 35.68**，LiveClin-MM 为 **58.38 → 61.62**。平均分第一不等于每列都严格获胜。

## 决定收益是否可信的对照实验

- **离线划分与泄漏边界（附录 D/F）。** 按论文协议，技能只从训练轨迹积累；域内测试留出，域外基准没有积累样本。积累集与测试集之间会去除近重复。因此离线经验库按设计不含评测划分轨迹，但未报告量化的残余污染审计。每个病例重置对话记忆和步骤历史，持久技能库则跨病例共享。论文没有完整说明各来源配置是否合成一个总池，不能擅自称作统一混合技能库。
- **实际样本量，不靠重建（表 10）。** 域内测试数量为 LiveClin-Text 101、MedXpertQA-Text 185、HealthBench 175、LiveMedBench 310、LiveClin-MM 185、MedXpertQA-MM 148、MMMU 139。域外为 AgentClinic-Text 214、AgentClinic-MM 120、MediQ 127、MMMU-Pro 56、MedJourney 264。表 9 的类别分布属于处理后的完整子集，不是测试集分布。预处理优先难题，并删除模态无效、无法可靠评分的记录；这不是未经筛选的官方完整基准成绩。
- **同一执行器，不同记忆机制（第 4.1 节、附录 E）。** 智能体基线共享 ReAct 执行器、工具、权限以及用于积累记忆的训练划分。Reflexion 和 CRITIC 被改为跨任务检索旧反思或旧批评。基线保留自己的记忆设计；论文没有把 SkeMex 的效用/治理机制移植给它们。因此比较的是整套记忆方案，而非所有基线都得到同一新机制后的对照。
- **选择与调参边界（附录 E–G，第 27–34 页）。** 论文列出默认超参数，并在 HealthBench/LiveMedBench 上做敏感性分析，但未说明在哪个划分上选择默认值，也未交代独立验证协议。基线的调参流程和调参预算同样未说明。共同执行条件不代表各方案经过同等调参。这种不确定性**不构成已经使用测试集调参的证据**。
- **生命周期消融（表 2，在线设置）。** 每个骨干内部固定工具、提示词和推理预算。DeepSeek 的五配置平均分：完整 **53.22**，去掉写入 **45.34**，去掉效用估计 **47.16**，去掉治理 **50.02**，仅相似度检索 **47.64**。Qwen 对应为 **56.19**、**47.13**、**49.32**、**52.50**、**49.93**。这五种配置包括 AgentClinic-Text，不是离线域内表的七列均值；未给方差。
- **写入与保留对照（表 4–5、12–13）。** DeepSeek 从 **53.22** 降至：无缓冲门控 **47.56**，无草稿审核 **48.82**，单提示编码 **50.97**。最强的不完整分支组合 General + Action 为 **48.65**。去掉成熟晋升为 **47.60**，去掉淘汰 **49.27**，去掉合并 **49.67**。这些支持方案的多个部分，但不构成总优化成本匹配的机制比较。
- **冻结迁移（表 14–15）。** 域外 DeepSeek 为 **75.79**，ReAct 为 **62.01**，平均分最强的记忆基线 Evolver 为 **70.35**；Qwen-Plus 为 **78.18**，对照 **64.27** 和 Evolver **75.21**。相对 ReAct 最大的变化在 AgentClinic-Text：DeepSeek **34.11 → 68.22**，Qwen **34.58 → 65.89**。另一个固定 DeepSeek 来源技能库的迁移实验中，Claude Sonnet-4.6 平均 **60.27**，ReAct **49.59**；Qwen3.6-35B-A3B 为 **58.23** 对 **47.71**。共享技能库，只替换消费技能的模型，目标端不改写。表中有基线迁移结果，但没有确立来源端构建预算相等。
- **尚未解决的域外结果分歧。** 同一个 DeepSeek 离线域外设置中，第 7 页正文/图 3 与表 14 对竞争基线的呈现不一致。图 3 包含 Evolver，却在平均分和 MedJourney 面板将其画在 GM 下方；表 14 则将 Evolver 列为平均分最强基线和 MedJourney 的胜者。这两处比较均采用表 14，无法从 PDF 解决分歧（详见 SOURCE.md）。
- **在线是另一种证据（表 3）。** 三个 epoch 中，SkeMex 的五基准平均分为 **76.39 → 77.37 → 78.56**，交互期间持续更新记忆。流式设置中较早被评估的轨迹可以进入后续记忆，不能把这些结果当作冻结留出泛化。论文未清楚交代 epoch 级划分、重置/打乱规则，以及后续 epoch 是否重访同一批已评分病例，无法确认没有复用评测病例。在线表中其他记忆基线也按各自机制积累经验。

## 增益缺失或较小之处

- **并列与落后同样重要。** 离线表 1 中，DeepSeek 在 LiveClin-Text 与 Evolver 同为 **92.08**，在 LiveClin-MM 与 Voyager/GSEM 同为 **61.62**。MedXpertQA-Text **35.68** 对 GSEM **34.59** 的差距较小，没有不确定性估计。
- **域外并非全面占优。** DeepSeek 的 MedJourney **76.52** 低于 Evolver **78.79**；AgentClinic-MM **89.17** 对 GSEM **88.33**。Qwen-Plus 的 MediQ **97.64** 只略高于多个基线的 **96.85**。没有 CI，不能据此建立统计显著优势。
- **跨模型迁移也有例外。** Qwen3.6-35B-A3B 使用迁移技能时，LiveClin-Text **90.04** 低于 CFM **91.17**，MedXpertQA-MM **53.78** 低于 GM **54.03**。在线第三个 epoch，SkeMex 的 LiveClin-Text **96.04** 低于 Evolver **99.01**；LiveClin-MM **67.57** 与 Agent KB 并列。
- **实际使用更多计算（表 16–17）。** DeepSeek 平均每题 **4.77** 步、**116.06 秒**，ReAct 为 **3.17** 步、**54.48 秒**。HealthBench 是例外：**52.36 秒** 对 **64.19 秒**。这些是受 API 与服务影响的近似推理墙钟时间，不是包含技能库构建、来源模型调用、token 或美元的完整成本。最大预算相等不意味着实际计算相等。
- **没有重复运行的不确定性。** 论文 checklist 明确未报告统计显著性检验。敏感性分析和训练顺序实验不能当作多种子误差条。该方法没有被验证为专业临床判断的替代品。

## 我们的解读（Our read）

HarnessRSI 评分 **67**，档位 ★★，证据等级 **retained**。最强证据不是在线曲线上升，而是冻结后的持久产物帮助留出病例和未参与构建的基准，并能被其他骨干模型使用。论文报告了大量生命周期消融和部分匹配的推理条件，但没有运行间不确定性、完整记忆构建成本、总计算量相等的比较，也没有给竞争基线移植同一机制。默认值选择划分、独立验证协议和基线调参流程/预算仍未说明，因此尚不能确立评测独立于选择过程、各方案调参程度相等。

存档判断把泄漏防护留为 unclear。完整 PDF 确实写了近重复去除和训练/测试隔离，因此该字段低估了论文陈述的离线防护；我们只在 SOURCE.md 记录，不改判断文件或分数。在线评测病例复用仍交代不足。可支持的结论是：**可迁移、由反馈治理的过程性记忆，收益不均，推理成本真实存在**；不是临床安全证明，也不是改进算法自身进化的证据。
