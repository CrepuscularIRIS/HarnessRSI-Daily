# OPD-Evolver：训练智能体管理记忆，而不只是给它更多记忆

*Reel 解读：[arXiv 2606.17628v1](https://arxiv.org/abs/2606.17628v1)，论文完整标题 **OPD-Evolver: Cultivating Holistic Agent Evolver via On-Policy Distillation**。作者依次为 Guibin Zhang、Xun Xu、Yanwei Yue、Zikun Su、Wangchunshu Zhou、Xiaobin Hu、Shuicheng Yan。HarnessRSI 评分 **63 · ★★ · retained**。[代码](https://github.com/bingreeky/opd-evolver)，本次未运行。*

## 系统改变什么，保留什么

OPD-Evolver 有两类不同的改变。**快回路**固定模型权重，更新持久化的轨迹、提示、技能与可执行工具模板；同一个策略选择记忆、执行任务、写入经验，并定期合并或删除记忆。**慢回路则训练策略权重**，让这些能力变得更好。因此，它不是训练全过程都不改权重的方法，也不是编码智能体改写自己的优化器。

信号来自环境任务反馈。在同一任务组内，方法比较某记忆被检索且被选中时的结果，与被检索但未被选中时的结果，再按选择频率、记忆层级和置信度加权（§3.3）。我们的理解：这控制了候选是否可用，却不是随机干预意义上的因果效应估计。

保留规则是策略决定的写入与维护，**不是每次改动都经独立留出集验收**。附录 D.2 给出教师记忆分数阈值 **0.01**，从 **50** 个候选中最多选 **20** 个教师记忆，写入侧按分数保留生成记忆的前 **30%**，每 **30** 个任务维护一次。论文没有完全说明写入侧筛选如何对应到每一次在线仓库更新；算法 1 只是逐层写入并更新。我们不会据此编造“只有成功才保留”的门控。

特权教师是同一个演化策略在停止梯度、增加后见信息条件下的版本，而非独立的更大教师模型。它看到记忆价值、同任务组的成功轨迹、写入记忆后来的效用与仓库诊断。学生在部署可见输入下采样，再在学生自己的输出前缀上做 token 级 KL 蒸馏。执行蒸馏时学生不看记忆，教师看到有用经验；部署后学生重新进入快记忆回路。

| 评估子集 | OPD-Evolver-9B | 最强同骨干记忆基线 |
|---|---:|---|
| LifelongAgentBench DB | 84.50 | 82.50 · EvolveR |
| LifelongAgentBench OS | 65.00 | 61.00 · MemEvolve |
| MemoryArena Math | 10.88 | 8.19 · ExpeL |
| MemoryArena Physics | 11.63 | 11.05 · AWM |

这些是**流式测试评估**，不是固定仓库在完全未参与更新的测试集上作答：仓库从空开始，逐步吸收先前评估任务的经验。表 1 没给种子数、运行次数、任务顺序重复次数、标准差或置信区间，也没标明最佳种子或验证集选出的检查点。小数精度本身不能证明进行了多次运行。

## 决定收益是否可信的对照

**组件消融（表 3，明确为 OPD-Evolver-4B）。** 下列三元组依次是 Bash / CTF / SQL，单位均为百分比；这张表没有方差或重复次数。

| 变体 | Bash / CTF / SQL（%） |
|---|---|
| 完整系统 | 36.16 / 34.00 / 45.86 |
| 去掉慢进化 | 32.14 / 28.00 / 39.17 |
| 去掉记忆归因 | 31.20 / 26.69 / 38.50 |
| 去掉学习式选择 | 35.27 / 32.00 / 42.04 |
| 去掉写入蒸馏 | 34.38 / 29.00 / 41.08 |
| 去掉维护 | 35.30 / 30.10 / 43.51 |

“去掉归因”是换成基于频率校准的分数，不是取消所有评分；“去掉选择”是按相似度取前五个。论文把维护消融描述为禁用仓库更新训练。这支持生命周期训练组件的作用，但不能证明统计显著性，也不是匹配总算力后逐组件隔离效果。图 4 另在两种规模上比较训练前后**不带外部记忆**的执行，报告成功率提高、步数减少；这是执行诊断，不是完整在线记忆系统的结果。

**基线究竟得到什么。** ExpeL、AWM、Cheatsheet、Memp、ReasoningBank、EvolveR、MemEvolve 是记忆系统对照，不能统称为冻结的无记忆智能体。协议让所有记忆方法从空仓库开始，获得相同的可用环境反馈，不提供标准答案或专家解法；但没有说明给表 1 每个基线都配置了 OPD-Evolver 的统一后见蒸馏。表 2 中，SFT 用 LoRA 训练三个 epoch；GRPO 一个 epoch；Skill0（附录 D.2 称 SkillZero）有 MiniHack 专用技能集、分阶段移除技能的课程，训练一个 GRPO epoch。MemRL 使用运行时记忆 Q 值更新而不是权重更新，最多检索三个记忆，其余强化学习参数留在软件包默认值。Complementary RL 有 **Qwen3.5-9B** actor，以及独立的 **Qwen3-4B-Thinking-2507** 记忆模型和记忆 actor，训练 **512** 步；其轨迹上限 **80** 个动作，而共享默认值为 **40** 步。论文报告了相同反馈和 MiniHack 数据，但没有证明总训练／进化机制与算力可比。

**划分与泄漏。** 主训练集共 **7,000** 个任务：**3,000** 来自 Agent World Model，**2,000** 来自 nvidia/Nemotron-Terminal-Corpus，**2,000** 来自 EnvScaler。§4.1 称这些来源与评估基准不相交；表 2 明确额外在 MiniHack 内训练，各方法使用相同 MiniHack 训练数据与测试任务；论文没有描述训练／测试划分、实例是否不相交、seed 层面的重叠或额外训练集规模。附录 C.1 说明评估仓库只来自当前流，反馈是成功／失败而非答案。这排除了预装基准记忆的优势，但保留物仍能包含先前评估任务与任务专属教训，后续相关任务按设计可以受益；没有近重复或记忆内容泄漏审计。AMA-Bench 只评估 Causal Inference、State Updating、State Abstraction，不含 Recall；MemoryArena 只评估 Math 和 Physics，并非全基准。

**调参与成本。** 论文没有说明在哪个划分上选择阈值、写入比例、维护周期、检查点或其他默认值，也没有报告基线的超参数搜索预算。不要把它与缺失数值设置混为一谈：OPD-Evolver 的学习率、batch size、训练 epoch／步数和各记忆层级先验都未指定。部分基线的学习率、batch 与训练时长已有记录，因此不能说“基线参数全没给”。论文列出 **8 张 NVIDIA A800（80G）**，却没给训练／进化墙钟时间、GPU-hours、token 用量、美元成本，或总算力匹配比较。

## 增益缺失或较小之处

表 1 的增益方向较广，但幅度不均。**9B** 的 MemoryArena Physics 是 **11.63% 对 11.05%**，AMA Causal Inference 是 **47.32% 对 45.81%**；相对明显的差距包括 OS **65.00% 对 61.00%**、State Updating **53.94% 对 49.77%**、State Abstraction **52.92% 对 48.00%**。**4B** 的 Causal Inference 只有 **32.89% 对 Memp 的 32.38%**，DB 是 **74.00% 对 73.00%**。因此并非只有单个任务或模型受益，但幅度强烈依赖子集；缺少不确定性时，不能把微小优势称为统计可靠。

在**表 2**，MiniHack Room 输给 GRPO：**98.04% 对 100.00%**；Maze 高于 Skill0：**27.45% 对 25.49%**；KeyRoom 高于 Complementary RL：**9.80% 对 5.16%**，但 KeyRoom 的绝对成功率仍低。Bash 是 **64.01% 对 GRPO 的 63.69%**，CTF **59.00% 对 58.00%**，SQL **49.55% 对 Complementary RL 的 48.10%**。附录 C 列出 **MiniHack 每个环境 51 个测试任务**。若每个任务只评估一次，Room 的落后与 Maze 的领先都仅相当于 **一个任务‡**：Room **50/51 对 51/51‡**、Maze **14/51 对 13/51‡**，四舍五入后复现表中百分比。这是条件性重建，不是作者报告的运行结果；运行／平均协议未说明。Complementary RL 的 MiniHack Room / Maze / KeyRoom 百分比（**96.88 / 20.85 / 5.16%**）均不能由 51 个任务中的单个整数成功数经四舍五入得到；任何平均或其他报告规则均未说明。我们保留印刷数值，不推测原因。作者所称平均值及各组成项都没有不确定性。

**表 1** 的大模型比较也有边界：**Qwen3.5-397B-A17B** 在 DB（**86.00% 对 84.50%**）、Causal Inference（**57.21% 对 47.32%**）、State Updating（**58.73% 对 53.94%**）和 Bash（**51.34% 对 49.55%**）仍领先；**STEP-3.5-Flash (196B)** 在 Causal Inference 仍领先（**49.50% 对 47.32%**）。这是部分子集上有竞争力，不是全面替代大模型。

## 我们的解读（Our read）

**63 · ★★ · 证据等级 retained**，沿用 HarnessRSI 评分与 b03 判断。值得关注的是：训练后的策略可以改善整套记忆生命周期，再根据评估反馈构建新仓库。论文报告了跨环境评估、组件消融与不带记忆的执行诊断；没有量化 seed／任务顺序不确定性、进化成本或匹配算力后的收益，来源不相交也不是经过检验的污染审计。更强的 improver 主张需要这些对照，而不只是名字里有“evolver”。完整 PDF 中的组件消融比压缩判断里的 `retained_ablation: unclear` 更丰富；SOURCE.md 记录了这一点，没有修改评分或判断文件。

所有任务成功率百分比均直接印在论文中。‡ 任务数是我们的条件性重建，并非作者报告的结果；未使用数值化图中标签读数。计算、出处与各表协议边界见 SOURCE.md。
