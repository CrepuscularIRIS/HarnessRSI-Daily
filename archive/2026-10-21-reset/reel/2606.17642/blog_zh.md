# FinAcumen：给冻结的 8B 视觉语言模型配一个“策略与警示”记忆库——但在论文做了拆分的设定里，工具带来的增益约为记忆的两倍

*Reel 解读：[arXiv 2606.17642v6](https://arxiv.org/abs/2606.17642v6)（HarnessRSI Daily 评分 68，★★）。作者：Pianran Guo、Pengcheng Zhou、Yuchen Jian、Shuhua Chen、Zhongliang Yang、Linna Zhou（北京邮电大学；伦敦玛丽女王大学）。代码：[CamelliaLilium/FinAcumen](https://github.com/CamelliaLilium/FinAcumen)。*

## 系统改变了自己的什么

FinAcumen 不动模型权重，也不动工具集。骨干是冻结的 Qwen3-VL-8B-Instruct（温度 0），四个工具固定不变（有状态的 Python 执行器、价格/新闻/指标表查询、基于 OCR 的图表/表格解码器，以及检查来源可追溯、单位和格式的答案闸门）。不断积累的是一个文本**记忆库**。每个条目包含一道训练题、其标准答案，以及两部分提炼出的经验：**Findings**（从答对的轨迹中泛化出的策略）和 **Cautions**（从答错的轨迹中提取的防护规则）。

## 信号与保留/拒绝规则

1. **构建（离线）。** 对每个训练/验证样本，模型独立采样 K = 8 条轨迹，逐条对照标准答案打分，再由一个总结智能体写出 Findings 与 Cautions。论文描述的是每道题都写入一个新条目（“incrementally expanding the bank”）；我们在正文和附录中没有找到写入时的过滤或裁剪步骤。
2. **冻结。** 记忆库（第 5.1/5.4 节约 2,400 条；附录 K 写的是“approximately 1800-entry”）在测试时只读，测试样本不会写入。
3. **检索（每次查询）。** 对问题加上下文前 600 个字符做嵌入，保留余弦相似度 ≥ τ = 0.65 的条目，按来源去重，最多取 k_max = 5 条。标注智能体把它们改写成针对当前问题的指令，随后求解智能体带着工具运行 ReAct 循环（≤ 16 步）。
4. **回退。** 没有条目达到 τ 时，求解智能体只用工具作答。（除余弦阈值外，提示词里还有两道较软的筛选：标注智能体可以把条目标为无用（"If you cannot map entities, the entry is NOT useful"，但提示词要求仅在任务类型根本不同时才这样做），求解智能体也可以跳过不适用的条目。论文没有单独报告这些筛选。）

交给求解智能体的检索条目包含被检索训练题的标准答案（论文称之为“格式参考”）。

## 决定收益是否可信的对照实验

- **工具与记忆的拆分（关键）。** FinMMR Easy（表 2）：Base 59.17，加工具 74.08（+14.91），加工具和记忆 81.67；记忆在仅有工具的基础上增加 7.59。BizBench 的记忆库规模曲线（图 2）起点为 55.15（有工具、空记忆库），到 2400 条时为 68.65，即 +13.5；相对 Base 的 27.67，工具本身就贡献 27.48‡。Qwen3-VL-235B-A22B 在 BizBench 上（表 12）：Base 57.45，工具 69.30（+11.85），完整系统 75.10（记忆 +5.80）。三种拆分中，工具带来的增益都约为记忆的两倍。论文只对这三种设定给出该拆分；其余四种（FinMMR Medium 与 Hard、FinTMMBench、FinMME）在主结果中没有。
- **运行间波动（表 9）。** Base 与 FinAcumen 各五次独立运行，给出均值、标准差和 95% 置信区间；各设定下区间均不重叠。论文没有说明各次运行之间有什么不同（例如记忆库是否重建）。已发表的基线只有单个数字，没有方差。
- **给其他记忆方法相同的工具与数据（附录 I，表 10）。** Reflexion、ExpeL 与 FinAcumen 使用同一骨干、同一工具环境与训练数据，记忆库均冻结：FinMMR Easy 77.17 / 77.17（两者完全相同）/ 81.67；FinMMR Medium 63.58 / 60.58 / 67.00；FinTMMBench 14.52 / 16.73 / 19.98；FinMME 42.97 / 45.77 / 51.08。只有四种设定（没有 BizBench 和 FinMMR Hard），均为单个数字、无 SD，基线的调参情况也未描述。FinMMR Easy 上仅工具一行（表 2）为 74.08，因此两个基线在其上增加 3.09‡，FinAcumen 增加 7.59。
- **记忆块里哪些部分有用（附录 D，表 4）。** 在 600 题的测试子样本上（阈值为 0.60 而非 0.65；论文未说明运行次数）：仅问题 53.00，加标准答案 56.25，加经验与工具 62.00，加标注与工具但无经验 58.50，全部 67.50。前两行不带工具，因此 14.50 分的总差距混合了工具、经验与标注；Findings 与 Cautions 从未被单独消融。**这里经验是更大的一步**：有工具和标注但无经验仅增加 2.25（B 到 D），加入经验则增加 3.50（D 到 C）或 9.00‡（D 到 E；FinMMR Easy 上 64 到 81，+17‡），论文写道“Experience provides the dominant marginal improvement”。这与上文“工具的增益约为记忆的两倍”存在张力；两处设定不同（子样本、阈值 0.60、B 至 E 行含检索到的标准答案），论文没有调和。仅加入标准答案就增加 3.25（A 到 B），这与下文的泄漏问题有关。
- **更多骨干（表 11，BizBench，Base 到 FinAcumen）。** GLM-4.6V 30.40 到 75.58；GPT-4o-mini 23.60 到 59.60；Gemini-2.5-Flash-Lite 32.60 到 48.40。这里比较的是 Base（无工具、无记忆）与完整系统，均为单个数字。
- **超参数（第 5.5 节）。** τ 是在九个取值中按命中率（而非准确率）选定的，基于“test queries”计算（第 5.5 节；附录 E 对同样的九个取值在 11,379 个测试查询嵌入上做了扫描；命中率不涉及标准答案）。第 5.5 节给出 τ = 0.65、1200 条时命中率为 79.8%，而表 5 中 1200 条时的全局值为 0.71，论文未调和。k_max ∈ {1, 3, 5, 7} 在 BizBench 与 FinMMR-Medium 的 500 道题上调优（宏平均 57.80、57.85、63.11、62.17）；论文没有说明这些题是否与测试集不相交。
- **成本（附录 K）。** 构建约 1,800 条的记忆库，基于六个源样本估计为 64,200 次 API 调用、244.43 million tokens、CNY 142.97、顺序耗时 78.12 小时。推理时每题（取各设定测试样本的六分之一，带库与不带库配对运行），总 token 从 20,043.51 增至 42,523.13，费用从 CNY 0.0115 增至 CNY 0.0244。构建成本估计针对约 1,800 条的库，小于实际评测的约 2,400 条的库，因此可能低估评测所用库的成本。没有算力匹配的基线。

## 增益缺失、较小或无法解释之处

- **四列低于已发表的最佳模型。** BizBench 68.65 对 79.30；FinMMR Hard 46.10 对 50.80；FinTMMBench 19.98 对 21.53；FinMME 51.08 对 52.54（Gemini 2.0 Flash 也报告 51.85）。论文正文只列出了前三个，没有列 FinMME。FinMME 上的差距（1.46‡）小于 FinAcumen 自身五次运行的 SD（2.24）；FinTMMBench 上已发表的 21.53 略高于 FinAcumen 的 95% 置信区间 [18.88, 21.08]。
- **FinTMMBench 上增益最小：** 16.20 到 19.98（3.78‡）。该设定下另外两种记忆方法为 14.52 和 16.73，与无工具的 Base 相近。
- **记忆在图表题上触发频率约为一半。** τ = 0.65 时，FinMME 的命中率为 0.48，其他设定为 0.68 至 0.90；1.15 是对全部查询取平均的检索条数，而非仅对命中的查询（表 5）。这些数字来自按基准均匀构建的 1200 条快照，而不是主结果所用的约 2,400 条的库。主消融里没有给出 FinMME 的工具/记忆拆分，因此它的 27.84 到 51.08 中有多少来自记忆并未展示。
- **“选择性激活”的作用没有被单独隔离。** 论文自己写道，积累曲线“does not by itself isolate the effect of selective retrieval”。论文没有报告 τ 闸门与回退对比“总是注入前几条”的准确率，也没有仅 Findings 对仅 Cautions 的消融。
- **收益递减。** 区间增益逐步缩小（最后 600 条为 +1.30 分；120 到 240 条之间图 2 显示 −0.05‡ 分，附录 C 则写作每 100 条 −0.04）。论文没有说明每个快照运行几次；2400 条处的点（68.65）等于表 9 的五次均值，其 SD 为 2.45。
- **论文内部不一致。** 记忆库规模（约 2,400 对约 1800 条；第 5.1 节称库为“∼2,400 experience accumulation trajectories”，但每个样本采样的是 K = 8 条轨迹）；第 5.4 节称饱和从 1800 条之后开始，附录 C 却选 2400 作为“saturation knee”；附录 E 的测试查询数（11,379）与表 6 的测试集规模之和（8,756‡）对不上，图 10 中 FinMME 的 11,099 个样本与 2220 条测试题也对不上；算法 1 中有一个未定义的标志 ω，会在推理时安排异步写入（consolidation），与“冻结、测试时只读”不符。
- **作者自述的局限：** 构建记忆库需要前期的 LLM 调用成本；只评测了英文基准。

## 我们的解读（Our read）

HarnessRSI 评分 **68**，档位 ★★，证据等级 **retained**：由训练/验证样本构建并冻结的记忆库，对它并非由其构建的测试样本有帮助。论文报告了留出的记忆库来源、带置信区间的五次评测运行、三种配置上的工具对记忆消融、四种设定上与 Reflexion 和 ExpeL 的比较、成本估计，以及主用 8B 骨干之外的另外三个骨干（表 11）和一个 235B 模型。论文没有报告算力匹配的比较，没有报告记忆库来源样本与测试样本之间的重叠或污染检查（依赖数据划分与冻结记忆库；检索条目带有标准答案），没有报告阈值/回退的准确率消融，也没有报告记忆库的跨基准迁移（记忆库汇集了全部基准）。
