# 红皇后哥德尔机：评估器与智能体一起进化，到底证明了什么？

*Reel 解读：[arXiv 2606.26294v3](https://arxiv.org/abs/2606.26294v3)（HarnessRSI Daily 评分 70，★★★）。作者（按标题栏）：Alex Iacob、Andrej Jovanović、William F. Shen、Daniel Burkhardt、Meghdad Kurmanji、Nurbek Tastan、Lorenzo Sani、Niccolò Alberto Elia Venanzi、Jiayi Nie、Ambroise Odonnat、Zeyu Cao、Bill Marino、Xinchi Qiu、Rika Antonova、Nicholas D. Lane。论文没有给出公开代码链接（仅提到补充材料压缩包）。*

## 系统改变了自己的什么

红皇后哥德尔机（RQGM）在 Huxley-Gödel Machine 式的存档搜索上做了扩展。每个存档节点是一个共享工作区，包含任务智能体、**评估器**（以可编辑的提示词和代码形式存在的审稿人或评分器）以及负责修改工作区的元智能体。只有打分与调度框架是固定的。因此搜索改动的不只是智能体，还有给它们打分的学习型评估器。基线 HGM-H 使用同样的搜索，但评估器保持冻结。

## 迭代回路与保留/拒绝规则

1. 搜索分成若干**时期（epoch）**。每个时期内，每个评估器槽位只有一个冻结的评估器为所有任务智能体打分，因此效用在时期内是平稳的。节点得分取其成功率 Beta 后验的 5% 分位数（ε = 0.05）。
2. 在按 2 的幂设置的检查点，每个评估器槽位把现任评估器与挑战者放在**真值锚点**上比较（可执行测试、人类接受/拒绝决定、人类 IMO 评分）。只有锚点 best-belief 更高的挑战者才会替换现任；平局保留现任。对带对抗池的槽位，比较的是加权目标（正例锚点 ½、负例锚点 ¼、拒绝对抗池 ¼；附录 F.2.1、F.6.3），因此挑战者可能在锚点准确率更低的情况下获胜。图 9 的图注称只有锚点证据进入替换门槛，附录 F.2.1 则加入了对抗池项。
3. 替换时，**选择性擦除**所有依赖被替换评估器的效用记录；旧节点在需要时再重新打分。
4. 可选：被替换评估器曾接受过的输出构成**对抗池**，下一时期同时奖励拒绝这些输出（用于论文审稿与 DeepSWE 的代码审查器）。
5. 元智能体只能看到训练划分；选择与替换只用验证划分；留出的测试划分在搜索期间从未使用。编码器和评估器有锚点，按全局 best-belief 选取；论文写作者和证明器没有锚点，只能在每个时期内按该时期冻结的评估器（即系统自己的评估器）选出，再由外部评审团事后打分（第 4 节“Costs and reporting”）。DeepSWE 两组中元智能体均为高推理强度，任务智能体为低强度。

## 论文报告的主要结果

- **DeepSWE**（GPT-6 Astra，在低推理强度下搜索，28 个留出任务）：低强度下 RQGM 编码器通过率 82.1%，HGM-H 编码器 75.0%，mini-SWE-agent 中的基础 GPT-6 Astra 为 68.8%。中等强度为 85.7 / 78.6 / 76.8；高强度为 85.7 / 82.1 / 83.0（表 9）。
- **Polyglot**（GPT-5.5 低强度，166 个留出任务）：RQGM 专才与通才均为 71.7%，HGM-H 为 69.9%，超过基线通过率所需的搜索 token 少 1.35×–1.72×（表 8、图 3）。
- **论文写作**，由四位审稿人组成的评审团对每个写作者的 100 篇论文打分：平均接受率 HGM-H 写作者 21.8%，RQGM 通才 38.8%（1.78×），RQGM 专才 40.5%（1.86×）（表 2）。
- **证明写作**（20 道 IMO 题，三个评分器）：评审团平均分 RQGM 专才 4.33，静态 IMO25 证明器 4.07，HGM-H 3.73（表 3）。
- **奖励设计**（四足机器人；搜索时学走路，留出任务为跳跃）：RQGM 课程 0.365 ±0.053，静态评估器 0.306 ±0.128；5/5 与 3/5 的搜索产出了会跳的策略（表 1）。

## 决定收益是否可信的对照实验

- **每个设置只有一次运行。** 论文写明“eight headline runs: an RQGM and an HGM-H run in each of the coding, paper, and proof domains”（八次主要运行）；按三个领域各两组只有六组，若把 Polyglot 与 DeepSWE 算作两个编码领域则为八组。编码表格没有给出种子、标准差或置信区间。唯一的多次运行结果是奖励设计（每组五次搜索）。
- **搜索成本。** DeepSWE 上，RQGM 的获胜编码器在 587M 搜索 token 后得到，HGM-H 的获胜者为 429M（表 6），约为 1.37‡×。HGM-H 之后继续运行到 2532.7M token（多约 2104.1M‡），没有找到更好的编码器；完整 RQGM 运行为 2876.8M（表 14，1.14‡×）。论文称两次搜索在 token 匹配时 best-belief 相近，但没有报告恰好匹配 token 时的留出得分。论文领域中，专才写作者用了 221.8M token，HGM-H 为 42.5M（5.2‡×）；1.78× 那一行（44.6M）才是 token 匹配的。证明专才用了 88.0M，对 21.5M（4.1‡×）；通才（37.9M，为 HGM-H 的 1.76‡×，论文仍称之为匹配）在表 3 中与 HGM-H 的分数完全相同。
- **评估器一侧的证据好坏参半。** DeepSWE 上最终的协同进化审查器锚点得分为 0.48（最早几个审查器为 0.03，随后 0.12、0.19、0.22）。锚点正是替换规则所选择的依据（外加对抗池项），所以锚点上升按构造即可预期（命题 7、备注 1）。论文另做的审计（表 15）显示，最后一个之前的每个审查器都会接受 81.8%–100.0% 的失败补丁（“几乎没有信号”）；只有最终审查器能区分二者（接受 20.8% 的失败补丁，对 35.0% 的通过补丁）。在留出的 APReS 论文上（表 8），每个 RQGM 审稿人的准确率都低于 HGM-H 审稿人：专才和通才为 84%，对抗审稿人为 80%，HGM-H 为 88%。证明评分器的优势只在正文中陈述（图 6，“搜索成本低 3×”），具体数值仅在图中。
- **DeepSWE 上的归因。** 获胜编码器（587M token 时得到）是在 11 次审查器替换中的 3 次之后生成的，当时在位审查器的锚点为 0.22，属于表 15 显示“几乎没有信号”的审查器之一。摘要把收益归于协同进化的代码审查信号；获胜链条表（表 19）显示 HGM-H 链条（第三个节点）也采用了“编码器可添加新的回归测试”这一改动，RQGM 获胜者也包含它。没有编码领域的消融把审查器的贡献单独分离出来，因此把 DeepSWE 收益归因于审查器并未得到证明。
- **机制消融只覆盖论文与证明两个领域**，且用的是 Nemotron 模型而非主实验模型（附录 D.2）。论文领域中，固定审稿人会饱和（写作者在它之下达到 100.0% 的验证接受率，由同一审稿人打分），审稿人锚点准确率为 78.2 ±4.4，完整机制为 95.0 ±10.3；去掉对抗池（91.2 ±7.4）或擦除（92.9 ±10.8）都仍落在区间之内。证明领域中，完整机制的证明器得分 3.60 [2.55, 4.67]，耦合 HGM 对照为 3.05 [2.11, 4.04]；评分器与人类一致率为 67.3% 对 65.7%（区间重叠）。编码领域没有消融（关闭审查器、关闭替换）。
- **评审团部分由系统自己的评估器构成。** 论文写作评审团包含 HGM-H 审稿人和 RQGM 对抗审稿人。证明评审团包含与专才证明器共同进化的 RQGM 评分器：该评分器给出 4.95（专才）对 4.05（IMO25）。不含它时，专才为 4.03，IMO25 为 4.08，HGM-H 为 3.60（表 10、附录 D.1）。
- **数据划分。** 留出集与搜索数据互不相交（按任务、论文或仓库划分）。DeepSWE 的划分（28/57/28 个任务）由作者自建，因为该基准没有公布划分。论文没有报告基础模型对这些基准的污染检测。
- **成本核算。** 混合 token 把输出按输入的 5 倍计，并计入生成与评估调用。验证评估占 65%–70% 的 token。奖励设计与 HyperAgents 比较时称“成本低 3.85–4.33×”，但模型不同（Nemotron 3 Ultra 对 Claude Sonnet 4.5），且按标价折算。

## 增益缺失或较小之处

- **DeepSWE，高强度。** 85.7% 对基础 GPT-6 Astra 的 83.0% 与 HGM-H 的 82.1%：RQGM 与 HGM-H 只差 28 个任务中的一个‡。低强度下与 HGM-H 相差两个任务‡（28 个中的 23 对 21），差距为 7.1‡ 个百分点。这些任务数假设进化编码器每个任务只尝试一次；Astra 的数字是四次尝试的均值，论文没有说明进化编码器是否重复尝试。
- **Polyglot。** 71.7% 对 69.9% 在 166 个任务中只差三个任务‡，没有区间；主要的主张在于 token 节省。
- **论文写作，Sakana 审稿人。** 三个写作者的接受率为 1.0 / 2.0 / 5.0%，落在给出的 ±2.2 到 ±4.3 区间之内。1.86× 的专才并非 token 匹配。作者把收益归因于正则化的搜索；论文没有报告写作评审团上的消融。
- **证明写作。** 4.33 ±0.41 对 IMO25 的 4.07 ±0.42，差距在一个标准误之内；在 Pass@7 上专才（48.3%）低于 IMO25（55.0%）。论文称较高的平均分来自更多接近完整（6/7）的证明。
- **对抗审稿人。** 它接受 32% 的留出人类论文（表 8），接受同一次运行中 RQGM 写作者所写论文的 29–31%（表 2），论文以此作为校准的标志；其准确率低于 HGM-H 审稿人（80% 对 88%），论文指出了这一代价。HGM-H 审稿人对 AI 生成论文的接受率是人类论文的 1.42×–1.91×。
- **奖励设计。** 均值高 0.059‡，小于静态组 0.128 的标准差（五次运行共 30 次试验合并）；课程组使用 53.8M token，静态组为 48.3M。障碍物课程由研究者设计，并非进化得到。
- **作者自述的局限。** 假设时期内平稳；评审团是自动化的，不是人类；锚点限定了评估器进化能达到的上限。

## 我们的解读（Our read）

HarnessRSI 评分 **70**，档位 ★★★，证据等级 **improver**。论文改动了改进机制本身（评估器替换、对抗池、擦除），并在留出数据上与固定评估器搜索做了比较。论文报告了留出划分、DeepSWE 框架在不同推理强度间的迁移、token 核算，以及两个领域中的机制消融。没有报告：头条设置的重复运行或方差，DeepSWE 获胜者在恰好匹配 token 时的留出得分（完整运行总量为 2876.8M 对 2532.7M），编码领域的消融，以及污染检测。多数头条差距只有几个任务，或落在报告的区间之内。最清楚的证据是证明评分器（正文陈述）、最终 DeepSWE 审查器对通过与失败补丁的区分，以及论文写作评审团上的较大差距（该评审团本身包含系统自己的审稿人）。

*标有 ‡ 的数字由我们根据论文数字计算，详见 SOURCE.md。*
