# PAST-Bench：保留下来的经验真的能帮到个人智能体吗？Hermes+ 又加了什么？

*Reel 解读：[arXiv 2608.04003v1](https://arxiv.org/abs/2608.04003v1)（HarnessRSI Daily 评分 71，★★★）。代码：[Gen-Verse/PAST-Bench](https://github.com/Gen-Verse/PAST-Bench)。*

## 系统改变了自己的什么

PAST-Bench 主要是一个基准，而不是会自我修改的优化器。它测试个人智能体本来就有的那一层：由记忆记录、技能（skill）、用户档案和会话历史组成的持久化存储。智能体在前面的"学习"episode 中写入，在之后的 episode 中必须读取，而后者每次都是上下文被清空的全新会话。整套基准有 26 个场景、204 个 episode，分属四种能力：记忆、流程复用、信息检索和更新。所有任务都是合成的。

论文没有描述外部验证器来决定保留什么（这是我们根据其未提及作出的解读；Hermes+ 的 E5 阶段含有一个"Background Review"步骤，论文并未将其描述为过滤器）：由智能体自己选择存什么。基准衡量的是"保留是否带来了帮助"。每个评测 episode 都运行两次，提示词、评分器、工具和种子完全相同，一次允许访问同一任务族产生的状态（w/ evolve），一次不允许（w/o evolve）。二者之差 Δ 是主要指标。论文称，只有 Δ 超过该任务族控制 episode（无保留、干扰项、过期信息、错误机制四类控制）所设的上界时才算证据，并另外根据保存的产物和运行时遥测给出"机制证据分"（Mech）。论文把这种匹配设计称为"一种强的设计控制，而非因果证明"。

论文还提出 Hermes+：在 Hermes 智能体上增加五个机制，每个对应循环中的一个阶段：E1 规划时检查已存状态，E2 带类型的记忆绑定且只渲染当前值，E3 可排序、可打补丁的技能，E4 检索闸门（若尚未发生读取，则扣下一次草稿答案并注入提示，要求先查询持久化存储），E5 episode 结束时覆盖旧状态并立即刷新写入。这五个机制是通过检查 Hermes 增益低、增益不均的轨迹推出的。

## 论文报告的主要结果

- **Hermes，七个基础模型（表 2，"3 次运行平均"）。** 每个模型都从持久化中获益：Overall Δ 从 +0.13（MiniMax-M2.7）到 +0.24（GPT-5.4）。增益不均：Memory Δ 为 +0.23 到 +0.37，Update 为 +0.12 到 +0.36，Procedural 仅 +0.03 到 +0.19，信息检索为 +0.05 到 +0.11。
- **固定模型 MiniMax-M2.7，四个框架加 Hermes+（表 3）。** Overall Δ / Mech：nanobot +0.13 / 0.57，ZeroClaw +0.12 / 0.55，Agent-Zero −0.08 / 0.39，Hermes +0.13 / 0.64，Hermes+ +0.15 / 0.73。nanobot 与 Hermes 的 Δ 相同、Mech 不同，这是论文所举"相同头条增益、不同路径证据"的例子。
- **两个通用智能体（表 9，MiniMax-M2.7，3 次运行）。** Codex CLI 的 Overall Δ 为 +0.10，Claude Code 为 +0.16，四种能力上均为正。
- **MiniMax-M2.7 上的 Hermes+。** Overall Δ 从 +0.13 到 +0.15，Mech 从 0.64 到 0.73；最明显的提升在 Update，Δ 从 +0.12 到 +0.24。持久化开启时的 Overall 得分没有变化，仍为 0.66。我们的解读：Mech 的上升有一部分可能是构造使然——E1、E4 强制读取，E2、E3、E5 强制写入带类型的状态，而 Mech 的召回项只给触发了预期检索信号的 episode 记分（公式 2）；论文自己也说 Mech 衡量的是与预期持久化路径的一致性，而不是确立因果必要性。

## 决定增益是否可信的对照

- **匹配的开/关对照（全部表格）。** 两侧使用相同的模型、智能体、提示词、工具、上下文窗口与限制，只有对留存状态的访问不同（附录 E.1）。这支持把 Δ 解读为同一"模型–智能体"对内留存经验的价值；但跨系统的绝对得分仍包含各系统自身的上下文管理差异。
- **方差（表 11）。** 只有两种配置——MiniMax-M2.7 上的 Hermes 与 Hermes+——给出了三次独立运行的标准差。Overall Δ：Hermes 为 0.13 ± 0.04，Hermes+ 为 0.15 ± 0.06；作者写道 +0.02 的差异"小于运行间波动"，不把它解读为稳定的总体增益。Update Δ 从 +0.12（SD 0.01）升到 +0.24（SD 0.09）。其他模型、框架和消融行均无 SD。表 2 的标题称七个模型都是"3 次运行平均"，而附录 D.5 说只有两种配置有三次运行；论文未对此作出调和。附录 B.1 说每个 episode 运行三次独立试验，标题所指或许就是这个，但论文没有明说。论文也没有指明头条结果对应哪个种子或哪次运行；表 4 的 Base 与 Full 行等于表 11 的均值。
- **单机制消融（表 4，MiniMax-M2.7，各行非累加）。** 每个机制都改善其目标能力：E2 的 Memory 开启得分最高（0.80），E3 的单机制 Procedural Δ 最大（+0.10），E4 的 Info Δ 最大（+0.17），E5 的单机制 Update Δ 最大（+0.16）。论文未说明每行的运行次数。每个单机制行的 Overall 开启得分都低于基础 Hermes（0.62、0.60、0.51、0.55、0.55，对比 0.66）；例如仅加 E3 时 Memory 从 0.77 降到 0.46，Update 从 0.62 降到 0.35。
- **交互效应（表 5）。** 在"聚焦的 Procedural 诊断"中，去掉 E2 使 Δ 从 +0.085 升到 +0.108，去掉 E3 或 E5 则降到 +0.062 或 +0.042。论文说明这不是全基准估计。其 Base 与 Full 的数值（+0.087、+0.085）与表 4、表 11 中的 Procedural Δ（+0.05、−0.02）不同，论文未说明子集或运行有何区别。
- **其他基础模型（表 6）。** Hermes+ 是在 MiniMax-M2.7 上调出来的。迁移到其他模型后，Overall Δ（Hermes 到 Hermes+）为：DeepSeek-V4-Pro +0.17 到 +0.15，GPT-5.4 +0.24 到 +0.24，Claude Sonnet 4.6 +0.20 到 +0.22，Claude Opus 4.6 +0.19 到 +0.18。论文把五种配置中的三种算作持平或提升，称迁移"为正但不均匀"。Mech 在 MiniMax-M2.7 上从 0.64 变为 0.73；其余四个模型分别为 0.71 到 0.69、0.80 到 0.80、0.76 到 0.77、0.70 到 0.70。
- **成本（表 12）。** 在 MiniMax-M2.7 上，Hermes+ 每个 episode 用 31,859 个 token，Hermes 为 12,615（约 2.5×），墙钟时间 77.4 秒对 70.5 秒（1.10×）；论文称多出的 token 主要是加入系统提示的上下文，而非生成的输出。在其他模型上，Hermes+ 与 Hermes 的 token 之比为：DeepSeek-V4-Pro 0.90‡×，GPT-5.4 1.5‡×，Sonnet 4.6 1.84‡×，Opus 4.6 0.55‡×。ZeroClaw（43,955）与 Agent-Zero（53,100）每个 episode 用的 token 都比 Hermes+ 多，Δ 却没有更高；nanobot（10,905）与 Hermes 的 Δ 相同。论文没有 token 匹配的基线行。
- **评判模型（附录 B.4）。** 开放式评分使用 MiniMax-M2.7 作评判，它也是 Hermes+ 的调优模型；评判模型未做变化。在 48 个样本上与两位盲评人员的均值相比，评判分数在 0.25 以内的占 68.8%，在 0.5 以内的占 91.7%。

## 增益缺失或较小之处

- **Hermes+ 的总体增益在噪声之内。** +0.15 对 +0.13，SD 分别为 0.06 和 0.04；两者开启持久化时的 Overall 均为 0.66。
- **Procedural 在 Hermes+ 下更差。** 开启得分从 0.55 降到 0.38（降 0.17‡），Δ 从 +0.05 到 −0.02。论文称之为 Procedural 结果"略有下降"。
- **Update 增益主要来自一个任务族。** 按任务族（表 10，每族 7–8 个 episode），七个 Update 任务族中五个上升、两个下降。事实纠正从 −0.078 升到 +0.492（升幅最大）；SOP 补丁 01 从 +0.041 升到 +0.163，规则迁移从 +0.135 升到 +0.226，临时例外污染从 +0.034 升到 +0.235，限定范围的规则迁移从 +0.354 升到 +0.502；"回忆后修改"从 +0.347 降到 +0.190，SOP 补丁 02 从 +0.017 降到 −0.127。Update Δ 翻倍出现在 MiniMax-M2.7 上（表 6 对比表 2）；其余四个模型的 Update Δ（Hermes 到 Hermes+）分别为 0.18 到 0.13、0.34 到 0.31、0.29 到 0.33、0.28 到 0.33。
- **Agent-Zero 为负，且各框架的运行限制不同。** Agent-Zero 的 Overall Δ 为 −0.08，每任务时限 1,200 秒，而 Hermes 与 Hermes+ 为 300 秒；论文称这是"方法学脚注而非公平性调整"，同时又写道 Agent-Zero"在预算足够时得分有竞争力"。表 15 还列出：Hermes 50 次迭代，nanobot 30 次，ZeroClaw 递归上限 100；超时或崩溃的 episode 记 0 分且不重跑，论文没有报告超时次数。Hermes+ 的机制没有加到 nanobot、ZeroClaw 或 Agent-Zero 上：对 Agent-Zero 与 nanobot，论文说那会与框架自带的持久化栈重叠；对 ZeroClaw 只说没有添加；论文称这些适配器"不是逐字节的默认部署"。
- **任务生成。** 任务、评分器和预期产物由 Codex（GPT-5.4）和 Claude Code（Claude Opus 4.6）生成，并由三位作者检查（附录 A.2）；GPT-5.4 在表 2 中的 Overall Δ 也是最大的（+0.24）。论文没有检验生成器是否偏向被评测的模型。
- **作者自述的局限。** 任务是合成的、且各自独立评测；Mech 衡量的是与预期路径的一致性，而非因果必要性；Hermes+ 被视为"诊断性脚手架，而非普适改进"。
- **控制 episode 未列数值。** 论文描述了无保留、干扰项、过期信息和错误机制四类控制，以及用于"校准"的冷启动 episode，但没有表格报告它们的得分。
- **数据备注。** 表 10 中两个 Procedural 行（SOP bootstrap 05 与 06）在四个单元格中有三个相同（Hermes 为 0.488 / +0.117，Hermes+ 开启得分为 0.231），只有 Hermes+ 的 Δ 不同（+0.022 对 −0.005），论文未作说明。

## 我们的解读（Our read）

HarnessRSI 评分 **71**，档位 ★★★，证据等级 **retained**：通过匹配的持久化开/关消融，把后续会话的增益归因于留存状态。论文报告了该匹配消融、两种配置上的运行间标准差、单机制消融、轨迹级机制分、每 episode 成本，并公开了代码。论文没有报告 Hermes+ 设计所用的留出集（失败分析与评测都用 PAST-Bench）、控制 episode 的数值、算力匹配的比较，也没有把 Hermes+ 机制加到其他框架上。Hermes+ 的头条增益小于其自身的运行间波动；基准所发现的"增益在不同能力和模型之间不均匀"是证据更充分的结论。
