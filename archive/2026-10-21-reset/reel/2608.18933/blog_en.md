# SkillForge: an SWE agent practises on bugs made from the repo's own tests — a gain over the plain agent, thinner against other methods

*A Reel interpretation of [arXiv 2608.18933v1](https://arxiv.org/abs/2608.18933v1) (Silin Chen, Han Li, Xiaodong Gu, Yuling Shi, Haibing Guan; Shanghai Jiao Tong University; HarnessRSI Daily score 69, ★★). Code: [cslsolow/SkillForge](https://github.com/cslsolow/SkillForge).*

## What the system changes about itself

SkillForge does not change model weights. It builds a **repository-specific skill store** that a software-issue agent (Mini-SWE-Agent) reads when a real issue arrives. The store is built before any real issue is seen, from the repository's code and tests only:

1. **Synthesize issues.** Run passing tests under coverage, pick the critical code segments each test executes (an LLM ranks the top-k), and ask an LLM to re-implement those segments *without* seeing the original (only the lines around the segment and the test's goal). If the rewrite makes tests fail, the result is a buggy instance with a failing-test target; an LLM writes the problem statement from the failure evidence.
2. **Attempt.** The agent tries to solve each synthetic issue; the trajectory is recorded.
3. **Distill.** From successful and failed trajectories an LLM writes two kinds of entity-linked skills: a **global diagnostic set** (M_ext: what an entity is for, a playbook, related APIs) and a **local intervention set** (M_int: how to modify the entity, pitfalls; failed runs are contrasted with the reference patch). Skills are grounded by aligning trajectory file accesses to an AST index of the repository; files in the agent's submission diff, "the golden patch" and the test patch are also added as candidate entities (p4). The paper does not say whether that golden patch is the synthetic instance's reference patch.
4. **Use.** At inference the top-5 global records (BM25 on the issue text) are prepended to the prompt, and local skills are injected as an extra observation whenever the agent's shell command touches a file with a matching entry.

Keep/reject rule: a synthetic instance exists only if the rewrite makes tests fail; the paper describes no further filter on skills beyond a manual inspection (Section V) and no validation signal that accepts or rejects a skill. On Verified the synthesis is redone for each target instance on a rolled-back snapshot (see controls), so there is not one fixed store per repository; the paper describes no iteration of the pipeline.

## Headline result, as reported

Mini-SWE-Agent scaffold; DeepSeek-V3.2 and GPT-5-mini; temperature 0, 250-step budget, "default inference settings". Pass@1, "averaged over three runs" for Table I (see the variance note below).

| Benchmark | Model | Mini-SWE-Agent | SkillForge | Strongest other method in the table |
|---|---|---|---|---|
| SWE-bench Verified (500 tasks) | DeepSeek-V3.2 | 66.4% | 72.2% | 69.2% (MemGovern) |
| SWE-bench Verified | GPT-5-mini | 55.0% | 60.6% | 58.4% (EvoCoder); the text names MemGovern, 58.0%, as strongest |
| SWE-bench Pro (731 tasks) | DeepSeek-V3.2 | 28.3% | 34.1% | 32.4% (Live-SWE-agent) |
| SWE-bench Pro | GPT-5-mini | 47.6% | 51.7% | 49.1% (Live-SWE-agent) |

The paper reports +5.8 / +5.6 points over Mini-SWE-Agent on Verified and +5.8 / +4.1 on Pro. Against the best other method the margin is smaller: +3.0 (DeepSeek) and 2.2‡ (GPT-5-mini) on Verified, +1.7 / +2.6 on Pro. On Verified one task is 0.2‡ points, so +3.0 is about 15‡ tasks and 2.2‡ about 11‡ tasks; no significance test against the best other method is reported. On Pro only two baselines (SWE-Exp, Live-SWE-agent) were run.

## The controls that decide whether the gain over the plain agent is real

- **Temporal isolation (Verified).** For each target instance the repository is rolled back before the gold patch and gold test patch; synthesis uses that snapshot (577 synthesized issues in total) and the agent may use only skills whose source commits predate the target's gold commit. The paper does not say what the test-localizing LLM is shown, and describes no such protocol for SWE-bench Pro.
- **Component ablation (Table III).** Without the global set: 68.4% (DeepSeek) / 57.6% (GPT-5-mini); without the local set: 67.8% / 57.2%; full system 72.2% / 60.6%. Each ablated variant still sits above Mini-SWE-Agent (by 2.0‡ / 1.4‡ points on DeepSeek, 2.6‡ / 2.2‡ on GPT-5-mini), so both parts add, and a large share of the gain survives removal of either. Table III does not state how many runs it averages and gives no spread.
- **Same injection, different source of knowledge (Table I).** Two controlled variants keep SkillForge's skill format and injection but change where the knowledge comes from. Replacing functionality-level rewriting by SWE-Smith-style single-function rewriting gives 68.0% / 56.4%; replacing trajectory-distilled skills by an LLM summary of the repository gives 68.7% / 54.4% (the latter below Mini-SWE-Agent on GPT-5-mini). Both are below the full 72.2% / 60.6%. The variants extract their functions from the baseline agent's trajectory, so they differ from SkillForge in more than one respect.
- **Cross-model transfer (Table IV, Verified).** Skills distilled by the other model do not help in this test: DeepSeek-V3.2 reaches 65.2% with GPT-5-mini's skills (below its 66.4% baseline), GPT-5-mini 55.0% with DeepSeek's (equal to its 55.0% baseline; 0.0‡ points). The paper's wording is that knowledge distilled from one LLM "provides limited guidance for another and may even introduce irrelevant context". This is one benchmark, two models and one cross pair per resolver, with run counts not stated, so we read it as "no gain from the other model's skills here", not as a general law.
- **Cost (Avg Cost).** Defined as end-to-end cost per evaluated issue including amortized synthesis, trajectory collection and distillation. SkillForge $0.074 / $0.066 on Verified against Mini-SWE-Agent $0.049 / $0.031; Pro $0.069 / $0.087 against $0.047 / $0.063. On Verified (DeepSeek / GPT-5-mini) SkillForge is cheaper than SWE-Debate ($0.382 / $0.167) on both models, and cheaper than SWE-Exp ($0.090) and SAGE ($0.081) on DeepSeek only. On GPT-5-mini its $0.066 is above SWE-Exp ($0.065), SAGE ($0.052), EvoCoder ($0.052) and Live-SWE-agent ($0.042); on DeepSeek it is above EvoCoder ($0.064) and Live-SWE-agent ($0.050). MemGovern's cost is not given. There is no row that gives the baselines the same total spend.
- **Variance and significance.** Table I is stated to be an average of three runs, yet 19 of its 20 Verified values (and all values in Tables III and IV) are exact multiples of 0.2‡, i.e. whole task counts out of 500 (68.7 is the exception), while the paper states temperature 0 and default inference settings; the paper does not reconcile these. The Pro values are consistent with whole counts out of 731. The paper gives no standard deviations. A dagger marks p < 0.05 without naming the test or the comparison, and it does not follow the size of the gain: EvoCoder on GPT-5-mini (+3.4) has none, while SWE-Exp (+1.6) and SAGE (+1.0) do; SWE-Debate (56.4) has none while SkillForge w/ SWE-Smith (56.4) does. SkillForge carries it in all four of its cells in Tables I and II; the text states the Pro gains over Mini-SWE-Agent are significant. No significance test of SkillForge against the strongest baseline is reported; Tables II–IV do not say how many runs they average.
- **Issue-type check (Section V).** The authors compared the issue-type distribution of synthesized issues with real SWE-bench issues from the same repositories and report that the two "do not overlap", and inspected skills and problem statements manually (no counts given). This is a distribution check, not a test for overlap between the synthetic material and the evaluated instances; the paper does not discuss whether the evaluated LLMs saw SWE-bench repositories or issues in pre-training, nor whether the "golden patch" used for entity alignment is the synthetic instance's.

## Where the gain is absent or small

- **Margins over the best other method are 1.7–3.0 points in all four benchmark-model cells** (see above); on Verified-DeepSeek the other methods' gains over Mini-SWE-Agent are 0.6–2.8 points, so the 5.8 is a bigger step than any one baseline's but is measured on one benchmark of 500 tasks, with a stated three-run average and no spread.
- **Ablated components and variants overlap the baselines.** The "w/o global" DeepSeek variant (68.4%) is below MemGovern (69.2%) and SWE-Exp (69.0%); SkillForge with an LLM summary is below Mini-SWE-Agent on GPT-5-mini (54.4% vs 55.0%).
- **Per-repository results (Fig. 5).** The text says SkillForge improves over the baseline on all seven largest repositories under both backbones, up to +13.6 (Sphinx, DeepSeek) and +15.6 (Scikit-learn, GPT-5-mini). The figure's label for SkillForge on DeepSeek / Astropy reads 0.0‡ (read off Figure 5), i.e. no change. SWE-Exp, in the same figure, regresses on three repositories (for example Matplotlib −11.8 on DeepSeek), but it also matches or beats SkillForge in several cells (labels read off Figure 5‡): DeepSeek Scikit-learn +15.6 vs +9.4‡, GPT-5-mini Sympy +2.9‡ vs +2.7‡, ties on GPT-5-mini Scikit-learn (+15.6 both) and DeepSeek Pydata (+9.1‡ both); on DeepSeek Sphinx they are within one point (+12.9‡ vs +13.6). Per-repository task counts are not given; the label steps (for example 4.5 and 9.1 on Astropy) look like whole tasks out of about 22‡, which would make Astropy's 0.0‡ and SWE-Exp's −4.5 a one-task difference — our inference. The caption says "Baseline and our method" although the figure and text show three methods (Baseline, SWE-Exp, SkillForge).
- **Hyperparameter sweep (Fig. 4).** Described as Django and Sphinx with GPT-5-mini: 62.3% with no retrieved skills, 69.7% at k = 5, 67.5% with all records (the figure's "full" point looks lower than the text's value). The k = 0 and k = 5 values (62.3, 69.7; a difference of 7.4‡) coincide with the Django GPT-5-mini bars of Fig. 5 (label +7.4‡), so the plotted data may be Django alone; we cannot tell. Either way the sweep is on repositories that are also evaluated; the paper does not say how the default k = 5 was chosen.
- **Stated limits.** The method relies on repository tests; rarely tested code gives fewer learning signals. Problem statements are LLM-written and may differ from developer-written reports. The case study (one Django instance) is an illustration, not evidence.

## Our read

HarnessRSI score **69**, band ★★, evidence level **retained** (the stored artifact, a skill set, is evaluated on real issues not used to build it). The paper reports temporal isolation on Verified, an ablation of both skill sets, controlled variants with the same injection, a stated three-run average (Table I) with significance marks, per-model cost including the offline stage, and a cross-model transfer test. It does not report a matched-compute comparison against the baselines, standard deviations or the significance test used, cross-repository transfer, or an experiment that modifies the distillation loop itself. No iteration of the synthesis/distillation pipeline is described, so this is a build-then-use design rather than an iterated self-improvement loop.
