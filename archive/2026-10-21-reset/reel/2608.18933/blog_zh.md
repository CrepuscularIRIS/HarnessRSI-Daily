# SkillForge：SWE 智能体先在仓库自己的测试所造的 bug 上练手——相对普通智能体有增益，相对其他方法的优势较薄

*Reel 解读：[arXiv 2608.18933v1](https://arxiv.org/abs/2608.18933v1)（Silin Chen、Han Li、Xiaodong Gu、Yuling Shi、Haibing Guan；上海交通大学；HarnessRSI Daily 评分 69，★★）。代码：[cslsolow/SkillForge](https://github.com/cslsolow/SkillForge)。*

## 系统改变了自己的什么

SkillForge 不改模型权重。它构建一个**仓库专属的技能库**，供软件问题修复智能体（Mini-SWE-Agent）在真实问题到来时读取。技能库在见到任何真实问题之前建成，只使用仓库自己的代码和测试：

1. **合成问题。** 在覆盖率监控下运行通过的测试，选出每个测试所执行的关键代码段（由 LLM 排出 top-k），再让 LLM 在**看不到原实现**的情况下重写这些代码段（只给代码段前后的几行和测试目标）。若重写导致测试失败，就得到一个以失败测试为目标的 bug 实例；LLM 再依据失败证据写出问题描述。
2. **尝试求解。** 智能体尝试解决每个合成问题，并记录轨迹。
3. **蒸馏。** LLM 从成功与失败轨迹中写出两类与代码实体关联的技能：**全局诊断技能集**（M_ext：实体的用途、排查手册、相关 API）和**局部干预技能集**（M_int：如何修改该实体、需要避开的坑；失败的运行会与参考补丁对照）。技能通过把轨迹中的文件访问对齐到仓库的 AST 索引来落到具体实体上；智能体提交的 diff、“金标补丁”（the golden patch）和测试补丁涉及的文件也被加入候选实体（第 4 页）。论文没有说明这里的金标补丁是否指合成实例的参考补丁。
4. **使用。** 推理时，把 BM25 依据问题文本检索出的前 5 条全局记录放进提示词开头；当智能体的 shell 命令触及某个有对应条目的文件时，再把局部技能作为额外观察注入。

保留/拒绝规则：只有当重写让测试失败时，合成实例才成立；论文除第五节的人工抽查外，没有描述对技能的进一步过滤，也没有用验证信号来接受或拒绝某条技能。在 Verified 上，合成是针对每个目标实例、在回退后的快照上重新进行的（见下文对照），因此并非每个仓库只有一份固定技能库；论文没有描述该流程的迭代。

## 论文报告的主要结果

Mini-SWE-Agent 脚手架；DeepSeek-V3.2 与 GPT-5-mini；温度 0，步数预算 250，“默认推理设置”。表 I 的 Pass@1 为“三次运行的平均”（见下文方差说明）。

| 基准 | 模型 | Mini-SWE-Agent | SkillForge | 表中其余方法里最强者 |
|---|---|---|---|---|
| SWE-bench Verified（500 题） | DeepSeek-V3.2 | 66.4% | 72.2% | 69.2%（MemGovern） |
| SWE-bench Verified | GPT-5-mini | 55.0% | 60.6% | 58.4%（EvoCoder）；正文称最强为 MemGovern，58.0% |
| SWE-bench Pro（731 题） | DeepSeek-V3.2 | 28.3% | 34.1% | 32.4%（Live-SWE-agent） |
| SWE-bench Pro | GPT-5-mini | 47.6% | 51.7% | 49.1%（Live-SWE-agent） |

论文报告的相对 Mini-SWE-Agent 的提升：Verified 上 +5.8 / +5.6 个百分点，Pro 上 +5.8 / +4.1。相对其余方法中最强者，差距更小：Verified 上 DeepSeek 为 +3.0，GPT-5-mini 为 2.2‡；Pro 上为 +1.7 / +2.6。Verified 上一道题相当于 0.2‡ 个百分点，因此 +3.0 约为 15‡ 道题，2.2‡ 约为 11‡ 道题；论文没有报告对最强的其余方法的显著性检验。Pro 上只运行了两个基线（SWE-Exp、Live-SWE-agent）。

## 决定相对普通智能体的收益是否可信的对照实验

- **时间隔离（Verified）。** 对每个目标实例，仓库被回退到金标补丁与金标测试补丁之前，合成只用该快照（总共 577 个合成问题），智能体只能使用来源提交早于目标金标提交的技能。论文没有说明负责定位测试的 LLM 看到了什么，对 SWE-bench Pro 也没有描述类似协议。
- **组件消融（表 III）。** 去掉全局集：68.4%（DeepSeek）/ 57.6%（GPT-5-mini）；去掉局部集：67.8% / 57.2%；完整系统 72.2% / 60.6%。每个消融变体仍高于 Mini-SWE-Agent（DeepSeek 高 2.0‡ / 1.4‡，GPT-5-mini 高 2.6‡ / 2.2‡），所以两部分都有贡献，且去掉任何一部分后仍保留相当一部分增益。表 III 未说明平均了几次运行，也没有给出离散度。
- **相同注入方式、不同知识来源（表 I）。** 两个受控变体保留 SkillForge 的技能格式与注入方式，只改变知识的来源。把功能级重写换成 SWE-Smith 式的单函数重写，得 68.0% / 56.4%；把轨迹蒸馏的技能换成 LLM 写的仓库摘要，得 68.7% / 54.4%（后者在 GPT-5-mini 上低于 Mini-SWE-Agent）。两者都低于完整系统的 72.2% / 60.6%。变体的函数是从基线智能体的轨迹中抽取的，因此与 SkillForge 的差别不止一处。
- **跨模型迁移（表 IV，Verified）。** 在这项测试中，另一个模型蒸馏的技能没有帮助：DeepSeek-V3.2 用 GPT-5-mini 的技能得 65.2%（低于其 66.4% 的基线），GPT-5-mini 用 DeepSeek 的技能得 55.0%（与其 55.0% 的基线相同，差 0.0‡ 个百分点）。论文的说法是，从一个 LLM 蒸馏出的知识对另一个只提供“有限的指导，甚至可能引入无关上下文”。这只是一个基准、两个模型、每个解题模型一组交叉配对，运行次数未说明，因此我们只把它读作“这里另一个模型的技能没有带来增益”，而不是普遍规律。
- **成本（Avg Cost）。** 定义为每个被评测问题的端到端成本，摊入合成、轨迹收集与蒸馏。Verified 上 SkillForge 为 $0.074 / $0.066，Mini-SWE-Agent 为 $0.049 / $0.031；Pro 上为 $0.069 / $0.087，对照 $0.047 / $0.063。Verified 上（DeepSeek / GPT-5-mini），SkillForge 在两个模型上都比 SWE-Debate（$0.382 / $0.167）便宜，只在 DeepSeek 上比 SWE-Exp（$0.090）和 SAGE（$0.081）便宜。在 GPT-5-mini 上，其 $0.066 高于 SWE-Exp（$0.065）、SAGE（$0.052）、EvoCoder（$0.052）和 Live-SWE-agent（$0.042）；在 DeepSeek 上高于 EvoCoder（$0.064）和 Live-SWE-agent（$0.050）。MemGovern 的成本未给出。没有给基线同样总开销的对照行。
- **方差与显著性。** 表 I 声称是三次运行的平均，但其 20 个 Verified 数值中有 19 个（表 III、IV 的全部数值也一样）恰好是 0.2‡ 的整数倍，即 500 题中的整数题数（68.7 是例外），而论文同时说温度为 0、使用默认推理设置；论文没有对此作出说明。Pro 的数值与 731 题中的整数题数一致。论文没有给标准差。匕首符号表示 p < 0.05，但没有说明检验方法与比较对象，而且它与提升幅度并不单调对应：EvoCoder 在 GPT-5-mini 上（+3.4）没有，而 SWE-Exp（+1.6）和 SAGE（+1.0）有；SWE-Debate（56.4）没有，而 SkillForge w/ SWE-Smith（56.4）有。SkillForge 在表 I、II 中的四个单元格都带有该符号；正文称 Pro 上相对 Mini-SWE-Agent 的提升显著。论文没有报告 SkillForge 相对最强基线的显著性检验；表 II–IV 也没有说明各平均了几次运行。
- **问题类型检查（第五节）。** 作者比较了合成问题与同一仓库真实 SWE-bench 问题的问题类型分布，称二者“不重叠”，并人工抽查了技能与问题描述（未给数量）。这是一种分布检查，而不是检验合成材料与被评测实例之间是否重叠；论文没有讨论被评测的 LLM 在预训练中是否见过 SWE-bench 的仓库或问题，也没有说明实体对齐所用的“金标补丁”是否为合成实例的。

## 增益缺失或较小之处

- **相对其余方法中最强者的差距在四个基准-模型单元格里均为 1.7–3.0 个百分点**（见上）；在 Verified 的 DeepSeek 上，其余方法相对 Mini-SWE-Agent 的提升为 0.6–2.8 个百分点，所以 5.8 的一步比任何单个基线都大，但它是在一个 500 题的基准上测得的，三次运行平均仅为声称，且没有离散度。
- **消融变体与基线有重叠。** DeepSeek 上"去掉全局集"的变体（68.4%）低于 MemGovern（69.2%）和 SWE-Exp（69.0%）；使用 LLM 摘要的 SkillForge 变体在 GPT-5-mini 上低于 Mini-SWE-Agent（54.4% 对 55.0%）。
- **分仓库结果（图 5）。** 正文称在两种骨干模型下，SkillForge 在七个最大的仓库上都优于基线，最高为 +13.6（Sphinx，DeepSeek）和 +15.6（Scikit-learn，GPT-5-mini）。图中 SkillForge 在 DeepSeek / Astropy 上的标注为 0.0‡（读自图 5），即没有变化。同图中的 SWE-Exp 在三个仓库上退步（例如 DeepSeek 在 Matplotlib 上为 −11.8），但它在若干单元格里也与 SkillForge 持平或更高（标注读自图 5‡）：DeepSeek / Scikit-learn 为 +15.6 对 +9.4‡，GPT-5-mini / Sympy 为 +2.9‡ 对 +2.7‡，GPT-5-mini / Scikit-learn（均为 +15.6）和 DeepSeek / Pydata（均为 +9.1‡）持平；DeepSeek / Sphinx 相差不到一个点（+12.9‡ 对 +13.6）。论文未给出各仓库的题数；标注的步长（例如 Astropy 上的 4.5 与 9.1）看起来是整数题，约 22‡ 题中的几题，这意味着 Astropy 上的 0.0‡ 与 SWE-Exp 的 −4.5 只差一道题——这是我们的推断。图注写的是“Baseline and our method”，而图和正文展示了三种方法（Baseline、SWE-Exp、SkillForge）。
- **超参数扫描（图 4）。** 论文称其为 Django 与 Sphinx、GPT-5-mini：不检索技能时 62.3%，k = 5 时 69.7%，取全部记录时 67.5%（图中“full”点看起来比正文的数值更低）。k = 0 与 k = 5 的数值（62.3、69.7，差 7.4‡）与图 5 中 Django 的 GPT-5-mini 柱（标注 +7.4‡）吻合，所以所绘数据可能只是 Django；我们无法确定。无论如何，该扫描所用仓库同时也是被评测的仓库；论文未说明默认的 k = 5 是如何选定的。
- **作者自述的局限。** 方法依赖仓库测试；很少被测试覆盖的代码提供的学习信号较少。问题描述由 LLM 撰写，可能与开发者撰写的报告不同。案例研究（一个 Django 实例）只是说明，不算证据。

## 我们的解读（Our read）

HarnessRSI 评分 **69**，档位 ★★，证据等级 **retained**（被保存的产物——技能集——在未用于构建它的真实问题上得到评测）。论文报告了：Verified 上的时间隔离、两类技能集的消融、注入方式相同的受控变体、声称的三次运行平均（表 I）与显著性标记、含离线阶段的分模型成本、以及跨模型迁移测试。论文没有报告：对基线的算力匹配比较、标准差或所用的显著性检验、跨仓库迁移、以及改动蒸馏回路本身的实验。论文没有描述合成/蒸馏流程的迭代，因此这是“先构建、后使用”的设计，而不是迭代的自我改进回路。
