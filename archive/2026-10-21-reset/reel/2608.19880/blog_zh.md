# EnvHarness：改造练习环境，留下技能——但别漏算生成时的 rollout

*Reel 解读：**EnvHarness: Awakening Static Worlds for Agent Learning**，[arXiv 2608.19880v1](https://arxiv.org/abs/2608.19880v1)。HarnessRSI Daily 评分 **63**，档位 ★★，证据等级 **retained**。代码：[google-research/envharness](https://github.com/google-research/envharness)。*

## 系统改变了自己的什么

EnvHarness 改的是**训练环境的接口层**，而非基础模型或原生任务验证器。**Stage** 在策略开始前回放动作，改变初始状态；**Contract** 过滤动作、改写返回的转移响应，或遮蔽/增强观测；**Chain** 串接任务，要求两个原生验证器都通过。因此，保留后端和验证器不等于保留智能体看到的一切：示例会故意模拟测试工具失效，或封锁捷径。

主线技能学习流程从接受的环境组件中采集轨迹，按 ReasoningBank 风格提取技能；这些保留的技能随后用于冻结策略，在未改造的原始评测任务上使用。**Chain 不在该自动流程中**，而是另做实验。RL 分析会更新权重，是另一种学习设置，并不是本项目 retained 判定所指的非权重产物。

## 迭代回路与保留/拒绝规则

EnvRigger 先观察每题 **5** 次未改造 rollout，诊断成功和失败，编写一组 Stage/Contract 候选。再采集 **5 次新 rollout**，由**设计者模型**依据汇总成功率、失败分布和超时数作 ACCEPT / REFINE / REJECT 决策，而非只读一条轨迹。不可能完成或没有挑战的候选会被拒绝；中间状态继续修改，最多 **5** 轮写入—验证，耗尽后该题可能不产生组件（第 3 节、附录 A/E.3）。

原生基准负责判任务成功；模型负责判断成功/失败模式是不是有用的训练信号。这不是独立证明可解性，也不是要求留出集收益的接受门。设计者与策略使用相同骨干：ALFWorld/WebArena 上为 **Gemini-3.1-Flash-Lite**，其余主线任务为 **Gemini-3.5-Flash**；这些比较没有使用更强外部教师。

## 论文报告的主要结果

表 2 报告**三次独立运行的均值 ± 标准差**。下列成功率以百分数计：

| 评测 | 原始环境技能 | EnvHarness 技能 |
|---|---|---|
| ALFWorld In-Dist | 63.3 ± 2.8 | 66.2 ± 0.3 |
| ALFWorld OOD | 61.4 ± 4.3 | 70.4 ± 2.3 |
| ALFWorld 平均 | 62.4 ± 3.4 | 68.3 ± 1.3 |
| WebArena 已评子域平均 | 38.5 ± 3.1 | 41.6 ± 1.8 |

宣传的 **9.0 点**是 ALFWorld **OOD**，不是全部基准的平均收益；In-Dist 提升为 2.9 点。GenEnv 的 ALFWorld 平均为 62.6 ± 1.9；VeriEnv 的 WebArena 平均为 39.6 ± 1.4。

表 3 的 SWE-bench Verified 成功率为 **49.88 ± 2.59% → 52.58 ± 2.72%**，SWE-smith 为 **50.12 ± 1.74%**。平均步数 **55.01 ± 1.69 → 49.61 ± 2.49**；摘要的**少用 9.8% 步数**比较的是这两条 Original Envs / EnvHarness 行，不是无技能行。OfficeQA exact match 为 **54.40 ± 1.84 → 56.20 ± 2.34**，SpreadsheetBench Pass@1 为 **45.88 ± 1.19 → 49.15 ± 0.36**，均为百分数尺度。表 3 给出标准差，却没有明确重复次数，不能把表 2 的三次运行直接移植过来。主表没有置信区间，SWE/Office 的均值差与运行波动范围有重叠。

## 决定收益是否可信的对照

- **逐个基线看匹配内容。** Original Envs 提供未改造训练任务；GenEnv 在 ALFWorld 用 LLM 模拟任务、转移与成功；VeriEnv 在 WebArena 重建可执行网站，奖励由程序检查；SWE-smith 合成仓库级任务。论文为它们匹配种子任务、环境数量、模型、技能提取和检索，并统一声明 oracle 验证访问相同。但没有把 EnvHarness 的轨迹条件化组件编写/验证回路授予这些基线，没有定量匹配环境多样性，也没有统一所有交互预算。OfficeQA 与 SpreadsheetBench 没有生成式基线。
- **划分与泄漏。** 只改造训练任务，评测使用原始任务。表 7：ALFWorld 用 100 条训练任务和基准原有 seen/unseen 评测；WebArena 每个已评子域训练 20 条；SWE-bench 用 100 条 Lite 训练任务，对 **407 条不在 Lite 中的 Verified issue** 测试；OfficeQA 用 50 条训练、**172 条官方测试任务**；SpreadsheetBench 用 100 条训练、**299 条留出任务 / 897 个实例**。WebArena 报告的是 Reddit、Shopping、Shop Admin、GitLab，不是所有网站。显式实例排除降低直接重叠风险，但未报告语义近重复或预训练污染审计。SpreadsheetBench 写为 400 条已验证任务中取 100 条训练，再留出 299 条；论文未解释这组划分数量关系。
- **参数数值与调参划分是两回事。** 附录 E.3 给出各基准共享的 rollout/修订默认值，但没有说明由哪个划分选出；基线调参搜索/预算未报告。另一些缺少的具体数值包括标准回路的目标成功率区间、技能学习的解码温度/episode 步数上限，以及 RL 学习率；附录 F.1 实际给出了许多其他 RL 参数。表 12 的显式区间属于另一个目标指标诊断实验，不一定就是标准回路设置。
- **生成成本（表 11）。** ALFWorld 的设计/rollout/总 token：EnvHarness **1.46M / 226.6M / 228.0M**，GenEnv **38K / 64.2M / 64.2M**。WebArena：EnvHarness **1.58M / 135.7M / 137.3M**，VeriEnv **20K / 137.7M / 137.8M**。rollout 占主导。WebArena 总量接近，但 ALFWorld 不算力匹配；GenEnv 的模拟交互也不能等同于真实执行。没有报告 SWE-smith 或 Original Envs 对应成本总量、美元总额或墙钟时间。设计成本是每个生成环境支付一次，而非每次训练 episode 都支付。
- **组件对照不等于完整优化器消融（表 5）。** 在标准**单环境 SWE 测试 issue** 上，Chain-only 技能为 **49.63%** 成功率 / **41.96 步**，Original Envs 为 **49.88% / 55.01**；Stage/Contract 为 **52.58% / 49.61**，合并技能为 **54.30% / 43.12**。此表未给方差或运行次数，也未报告独立 Stage-only/Contract-only 或去诊断/去验证对照。
- **适应性与模型。** 扩展实验在 300 个环境、15 项技能时，SWE 成功率 **54.79%**，Original Envs 为 **52.13%**，SWE-smith 为 **50.37%**（第 5 节正文）。数量和检索匹配，但只有 EnvHarness 按当前带技能策略生成下一批环境。表 9 为每个策略用同一骨干重新生成，不是供体技能迁移。Original → EnvHarness 成功率：Gemini 3.1 Flash-Lite **36.8% → 40.0%**；Qwen3.6 27B **48.4% → 52.1%**；Gemini 3.5 Flash **49.9% → 52.6%**；Claude Sonnet 4.6 **69.2% → 72.4%**。此表报告平均结果，没有方差/置信区间。

## 增益缺失、较小或集中的地方

- **WebArena GitLab：** VeriEnv **38.9 ± 5.6%** 高于 EnvHarness **37.7 ± 3.1%**。相对 Original Envs，最大子域收益是 **Shop Admin +6.2 点**，Reddit 为 +1.9、Shopping +2.2、GitLab +2.3。部分差距相对标准差很小，没有显著性检验解决这一点。
- **ALFWorld 留一任务类型迁移（表 10）：** 平均 **60.6% → 63.7%**，但 clean **54.8% → 71.2%** 贡献最大改善（+16.4 点）；heat 从 **61.1% 降至 52.4%**（−8.7），simple 均为 **83.6%**，cool 仅 **38.5% → 39.3%**。这个迁移平均值没有方差/置信区间，不是均匀泛化。
- **RL 并非全部更好（表 4）：** Qwen3-8B-base 配 GRPO，ALFWorld In-Dist **81.4% → 87.9%**，但 OOD **89.6% → 88.8%**。WebShop score **75.6 → 79.2**，成功率 **66.0% → 67.4%**。附录 F.1 固定 seed 0，在 8 张 H100 上训练 150 个 epoch/step；未给方差/置信区间。固定种子本身不能证明完整运行次数。
- **成功率提升不一定省步数。** 表 9 的 Qwen3.6 27B 相对原始环境技能，步数 **37.1 → 40.8**；Claude Sonnet 4.6 为 **25.4 → 25.6**。只有 Gemini 3.5 Flash 同时在成功率、步数上胜过两个对照。
- **局限：** 需要可重置的文本环境。扩展实验的定性描述中，第三轮约三分之一训练任务耗尽修订仍没有接受组件。实现的 Chain 是顺序串接；更丰富路由的示意代码不是经过验证的分支任务结果。

## 我们的解读（Our read）

沿用已发布 HarnessRSI 评分 **63**、档位 **★★**、证据等级 **retained**：生成的包装组件留下有用技能，并在留出的原始任务上改善表现。完整论文实际报告了表 2 的重复运行方差、表 3 的标准差、留一类型迁移及估计生成 token；这些补充了精简判定中 variance、cross-task、optimizer cost 的 `unclear`，详记于 SOURCE.md，不改评分或判定文件。

匹配环境数量不等于全面匹配计算预算。关键缺口仍是基线调参预算、默认参数选择划分、语义泄漏审计，以及把诊断/接受机制与环境改造分离的对照。实用结论是：在可信任务评分下进行针对性练习；不是所有类别都变好，不是生成器已证明能改进自身，也不是包装环境没有成本。
