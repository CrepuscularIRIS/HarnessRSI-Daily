# AutoRef：优化调用流程，而不是图像模型权重

**AutoRef: Harness Optimization for Agentic Multi-Reference Image Generation**  
作者依 PDF 顺序：Yuta Oshima、Ku Onoda、Yusuke Iwasawa、Masahiro Suzuki、Yutaka Matsuo、Hiroki Furuta；前两位共同一作。  
[论文](https://arxiv.org/abs/2609.35530v1) · [作者公布的代码](https://github.com/KuOnoda/AutoRef)  
**我们的评分：65 / 100 · ★★ · retained 证据。**

## 改什么，按什么规则保留？

AutoRef 搜索的是包裹冻结图像生成器与推理模型的可执行 Python harness，可以改提示词、参考图处理、生成安排、诊断、候选选择与控制流，不改模型权重。提案者为 Claude Fable 5.1，运行时推理模型为 GPT-5.5，生成器为 FLUX.2 [klein] 4B，外部评分器为 Qwen3-VL-8B-Instruct。这些角色不同，不能概括为同一个模型自评。

关键是把**供改写使用的反馈**与**决定存活的反馈**分开。宽度为二的 beam 从直接生成和 GEMS 起步；五轮中，每轮提出四个新 harness。提案者可看所有训练侧代码、分数、理由、图像与轨迹，失败候选也留在历史中。独立验证集给新候选排序，前二替换整个 beam，父代不再次参与竞争。提案者只能知道存活者身份和代码，看不到验证分数或产物。最终取最后一轮 beam 中验证分数最高者。因此验证分数属于选拔信号，不是独立的结果证据。

四参考图 MultiBanana 被分为 48 个训练任务、48 个验证任务和 133 个搜索未见的测试任务。论文给出 beam 宽度、每轮提案数与轮数，但未报告单独的超参数扫描，也未交代用哪个 split 选定这些默认值。每轮新建提案会话，从文件重建历史；隔离容器不提供验证／测试评估结果，指令禁止任务特定硬编码。这是有意义的流程隔离，不等于做过参考图或内容重叠审计。

## 最后保留的程序如何工作？

每个任务生成三张图。先根据参考图为所需元素分配来源；A 草稿侧重结构化场景／主体描述，B 把背景或风格参考作为画布锚点并放到首位。没有这类参考时，B 用 A 的提示词重新采样。选择先比较硬失败数量，再将打平的候选以两个展示顺序比较，挑战者必须两次都赢才替换当前胜者。针对胜者最多提出五条参考图相关问题，改写提示词生成 C；无问题则重采样胜者的提示词。最终沿用同一选择规则。运行时选择由 GPT-5.5 执行，不是外部基准评分器。

## 主结果：更强的系统，而非同成本的一次调用

在 **133 个四参考图 MultiBanana 测试任务**上，4B 从 **5.72 提升至 7.37**（表 1）。平均方式是先合并每类的五个指标，再对四类任务等权平均，并非按任务数加权的总平均。直接生成用一张图，AutoRef 用三张并增加推理，因此这是系统级提升，不是生成器的免费升级。

四类都有提升：物体 **5.95→7.27**，局部 **6.11→7.87**，全局 **5.50→7.64**，背景 **5.34→6.70**，并非单一类别撑起结果。平均值超过所列单图专有模型，但不是逐列全胜：局部低于 GPT-Image-1.5 的 **8.12**，全局低于 Seedream 4.5 的 **7.83**；物体也低于 9B 加同一 harness 的 **7.49**。

## 哪些对照让结论更可信？

表 6 给出同生成器、同推理模型下的重要图像预算对照：

| Harness | 测试平均 | 平均生成图数 |
|---|---:|---:|
| 直接生成 | 5.72 | 1 |
| Best-of-3 | 6.01 | 3 |
| IPR | 7.02 | 3 |
| Idea2Img，预算匹配版 | 6.42 | 3 |
| Idea2Img，原始安排 | 7.12 | 9 |
| GEMS | 5.37 | 2.7 |
| AutoRef-Harness | 7.37 | 3 |

这些基线不是看不到参考图的弱化对照。Best-of-3 的选择器能看参考图和候选；GEMS 用公开提示词与默认轮数，并明确把参考图交给验证器。IPR 因没有公开代码而按公式／提示词重实现，规划器可见参考图和当前生成图。原版 Idea2Img 有多轮反馈，匹配版则是单轮三个提示词，没有迭代反馈。专有模型采用默认 API 设置。论文没有报告各基线独立调参搜索预算；相同图数不等于推理调用、token、美元或整体搜索成本相同。

搜索流程对照中，Meta-Harness 为 **6.23**，贪心搜索 **6.67**，AutoRef **7.37**。Meta-Harness 用同一提案者、模型与评分器，文中称预算相同，但在同一批任务上提供改写反馈并排名，暴露完整历史；贪心保留训练／验证分离，只留一个父代。这支持搜索设计，但没有逐一隔离全部差异，也没有测得总计算成本完全相等。这里 Meta-Harness 仅运行五轮，短于其原始流程。

保留组件的消融是实质性证据（表 4/9）：去掉多样草稿得 **7.01**，去掉问题驱动修改得 **6.99**，去掉失败感知选择得 **6.93**，完整版本 **7.37**。删除生成步骤时用同提示词重采样补足，仍保持三张图。仅做参考图 grounding 就以一张图达到 **6.91**；仅选择为 **6.15**。主提升中相当一部分已由 grounding 获得。这不是“其他组件都保留、只移除 grounding”的干净消融。问题驱动修改对物体几乎不变（**7.24** 对 **7.27**），但局部影响更大（**7.01** 对 **7.87**）。

## 迁移、失效边界与不确定性

不重新优化，同一 harness 在四参考图条件下将 FLUX 9B 从 **5.78→7.10**，Qwen-Image-Edit-2511 从 **4.44→5.69**。未见的三／五参考图设置各含 96 个任务，4B 为 **6.94→7.76** 与 **5.19→6.36**。但 Qwen 在五参考图上反而 **1.89→1.87**；附录 I 报告 **87/96** 个任务（**91%**）的三张草稿全部硬失败。这是明确边界，不支持普遍可迁移的说法。

OmniContext 未参与搜索，使用 GPT-4.1 评估；八类共 120 个任务，按提示遵循与主体一致性的几何平均计分。4B 平均 **8.30→8.85**，但单角色 **9.22→8.94**，多角色加物体 **8.68→8.59**；场景加物体 **7.47→8.89**，场景加角色仅 **9.18→9.28**。总分仍低于 GPT-Image-1.5 的 **9.41**。收益不均匀，也没有在所有基准逆转专有模型排名。

人工评估有四位评分者，每个基线比较使用 50 个保留测试任务，输出顺序随机。对 Nano Banana Pro 胜率 **46%**、负率 **40%**，远没有对原始 4B 的 **70%** 对 **17%** 那么悬殊。论文未报告置信区间、逐单元格的种子／重复次数或多次搜索方差，不能把小差距当作统计上成立，也不能无证据称为“单次运行”。定性例图挑自最大分差任务，并非随机抽样。

## Our read

**65 / 100，★★，retained。** 有保留下来的可执行程序、独立测试、按生成图数匹配的运行时对照、迁移、人工评估和组件消融。效果不只是多抽三次；但也不是优化器本身递归改进的证据。

仍缺多次搜索／种子不确定性与完整优化经济账。论文披露二十个新候选及 GPU 型号，却未报告总优化时长、GPU 小时、token、美元或总生成图数；迁移也继承了最初搜索开销。反馈隔离限制了泄漏路径，并不证明参考图／内容独立。现有判断记录低估了消融证据：全文确有保留组件消融；“预算匹配”“泄漏防护已测试”也需按上述范围理解，不修改既有评分。
