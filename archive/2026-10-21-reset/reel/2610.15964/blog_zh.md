# TeSearch：进化审核智能体自我修改的测试，而非证明这些修改让智能体变强

*Reel 解读：**Small but Mighty: Test Suites as Improvement Signals for Self-Evolving Agents**，[arXiv 2610.15964v1](https://arxiv.org/abs/2610.15964v1)。HarnessRSI Daily 评分 **64 · ★★ · retained**。代码：[ccsnow127/TeSearch](https://github.com/ccsnow127/TeSearch)。*

## 改变什么，保留什么

TeSearch 用冻结的 LLM 进化**可执行 Python 单元测试套件**。留存产物是审核后续 harness 改写的回归信号，而非模型权重。套件包含 pytest 测试函数、fixture 初始化、协作组件的桩、输入及断言。测试由 LLM 根据原始模块源码编写；提示词明确要求从源码推算期望值。繁殖阶段还提供未覆盖代码行、仍存活的搜索变异体、父代套件和失败测试的异常（附录 D）。

质量是覆盖率乘以变异杀死率，称为超体积 hv。规模是**写出的测试函数数量**，不是断言数、运行时间或 token 数。尤其要注意：覆盖率和变异得分只在套件的**通过子集**上测量，而规模仍按写出的测试计数（算法 1）。

## 迭代回路与保留/拒绝规则

1. 不指定测试数量，生成种子套件。先测量并临时存档，再建立规模网格，按网格内的 Pareto 规则重新归档。
2. 用质量门控、规模退火的 UCB 选择规模区间。在线核修正 LLM 偏离请求数量的倾向，并预测生成结果落在哪个区间。
3. 从目标规模两侧各选对数规模最近的 Pareto 前沿父代；一侧为空则从另一侧选。较强父代放在最后，请 LLM 压缩或扩展它。
4. 测量子代，按**实际写出规模**归档，各区间保留覆盖率/变异率上的非支配套件。测量失败的调用仍消耗预算。超出范围的套件进入溢出区间，不直接丢弃。
5. 交付 hv 最高的套件，同分时选更小者。提示词对压缩/扩展提出的改进要求是生成指令，不是算法 1 额外执行的接纳门槛。

后续的 **harness 改写门控**是另一层规则：从原始模块生成一次套件，若改写让原先通过的测试失败，就拒绝。对照是仓库原有测试套件，论文未逐一说明这些测试的作者。通过回归检查，不等于实际改善了延迟、token 成本或能力。

## 论文报告的主要结果

表 1 是 **129 个 TestGenEval 模块**的均值，**每模块 50 次模型调用**，搜索和评估使用不同变异体折。这是模块平均，不是论文报告的多随机种子平均；未提供每格重复搜索次数及 SD/CI。

| 模型 | TeSearch hv / 平均测试数 | hv 最高的外部基线：hv / 平均测试数 |
|---|---|---|
| GPT-5.4 | 0.916 / 38.6 | OpenEvolve：0.831 / 51.5 |
| Claude Opus 4.8 | 0.976 / 29.1 | GEPA：0.895 / 67.2 |
| Gemini 3.1 Pro | 0.908 / 36.3 | Beam search：0.838 / 52.6 |

在各模型上，TeSearch 的平均 hv 最高，平均套件也小于所有 LLM 方法。表中基线是质量领先者，不是规模最小者：Gemini 上 Cursor 已只有 37.0 个测试。Pynguin 更小，平均 20.4 个测试，但 hv 为 0.090，且只在其支持的 40 个模块上计分。

表 2 在 **mini-swe-agent** 而非 TestGenEval 上评估改写门控。GPT-5.4 根据成对的“保持/改变行为”意图，为八个 harness 模块生成改写。共生成 512 个，两个标注者确认实现了意图后，470 个进入评估（一致性 κ = 0.74）：217 个行为偏离、253 个行为等价。分母不含未确认的改写；这是经筛选的改写池诊断，不是无人值守的长期进化运行。

汇总行为偏离拒绝率为 **59.9%，仓库原有测试为 25.3%**。代价是 **4.0% 的误报，而原测试没有误报**：TeSearch 拒绝了 10 个等价改写。每次决策平均 **3.5 s，原测试为 5.9 s**，门控运行不调用模型。论文未说明这项门控实验所用的套件生成模型，不能把测试生成实验的三模型结果直接投射到表 2。

## 决定收益含义的对照

- **消融，表 1。** Claude Opus 4.8 上，完整方法 hv/规模为 0.976/29.1；去掉核为 0.917/40.8，去掉 UCB 为 0.960/34.4，去掉最近父代为 0.934/33.2，去掉规模压力为 0.954/84.6。每个模型上，所有消融都会降低平均质量并增大平均套件。未报告消融方差。
- **预算与反馈权限。** LLM 方法共享 50 次调用上限。OpenEvolve 明确使用相同反馈。Claude Code、Cursor 以工具输出接收 harness 反馈，并被要求提高质量、减小规模；Claude Code 只在自己的模型上运行。GEPA 使用覆盖率、变异率及负规模的全局 Pareto 池。Iterative refinement、best-of-N、beam search、MIPROv2 和 ACE 被列为调用数匹配的基线，但各自具体如何接入反馈并未详述。Pynguin 使用 6000 s 墙钟预算而非模型调用。基线超参数调优预算未报告，调用数相同不等于总算力相同。表 2 只对照原仓库测试，没有比较其他生成套件作为门控，也没有实测 rollout 门控。
- **划分与泄漏边界。** Cosmic-ray 使用固定种子生成变异体，再在**同一模块内**划分搜索折和留出评估折；这不是留出模块或跨任务迁移。测试编写者有意看到源码推导出的期望输出，用来约束既有行为，而不是隐藏评估任务的解答。论文描述先由原始模块生成门控套件，再检查改写；未描述把改写标签或解答作为生成输入。但未报告显式污染审计，也没有交代套件生成与改写池之间的形式化隔离协议。源码导出的测试可能保留实现细节而非仅保留预期行为——这是我们对回归目标的解读，不是实测泄漏结论。
- **默认值选择。** 核的离散程度固定为“留出集的中位数”；附录 A 明确给出 σ = 0.10、由此得到的网格比率 ρ = 1.22，以及网格上界参数 γ = 4（第 9–10 页）。但未说明是哪一留出集、如何划分、是否与评估隔离，也未交代这些设置的独立调参划分。η、α、c_e、H 及种子套件数的数值默认值未提供，无法核实调参独立于测试集。
- **成本。** 生成后执行门控便宜，但 3.5 s 不是构建套件的成本。搜索需运行覆盖率/变异检查；生成美元成本、token 数、总墙钟时间未逐项报告。变异体生成采用固定种子，也不构成多进化种子重复的证据。

## 收益较小或缺失之处

表 1 的平均质量优势出现在每个模型上，但没有逐模块明细，无法检查是否集中在 129 个模块中的少数模块。门控在全部列出模块上提高偏离拒绝率，但幅度不均：**actions_text 为 0.040 → 0.560**，**content_string 为 0.057 → 0.600**，而 **agents/default 只有 0.529 → 0.588**。缓存控制仍只能检测 0.414 的偏离改写，模型客户端为 0.421；后者误报率为 0.080，原测试为 0.000。论文未给 CI，不能确认智能体主循环小幅优势的可靠性。

汇总加速也非处处成立：actions_toolcall 为 3.1 s 对 3.0 s，cache_control 为 3.0 s 对 2.9 s，serialize 为 3.1 s 对 2.9 s，content_string 同为 2.9 s。未报告反复采用门控改写带来的下游任务成功率提升。

## 我们的解读（Our read）

**评分 64 · ★★ · 证据等级 retained**，沿用仓库最新判定。报告了：留出变异体、调用预算匹配、套件搜索消融，以及留存套件审核后续改写的诊断与执行延迟。未报告：多种子不确定性、跨任务产物迁移、污染审计、完整生成成本及长期有/无门控智能体对照。存档预算判定为 **partial**：调用数匹配明确，总算力及调参对等未证实。retained 应窄义理解：一次生成的信号能检查后续改写，不代表智能体的改进机制随代际演化而变强。

**结论：** 不只优化改写生成器，也优化回归信号。TeSearch 使信号更强、更紧凑，但仍漏检偏离改写，也误拒部分等价改写。更好的回归检测是有用证据，尚非递归性能提升的证明。
