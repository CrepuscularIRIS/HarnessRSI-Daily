# CDSE：先分清轨迹教会了什么，再决定怎样保留与调用

*Reel 解读：[From Trajectories to Differentiated Skills: Cognitive Differentiation for Self-Improving Agents，arXiv 2610.23599v1](https://arxiv.org/abs/2610.23599v1)。HarnessRSI Daily 评分 **64**，★★，证据等级 **retained**。现有记录未提供公开代码链接；PDF 提到 Software 补充材料。*

## 系统改变了自己的什么

CDSE 更新持久化的外部技能，不更新模型权重或改进协议。它将轨迹中的知识分为 **Meta**（全局规划、监控与停止规则）、**Experience**（局部条件触发的启发式与恢复策略）、**Tool**（特定能力的操作指导）、**Script**（可复用的确定性过程及其执行契约）。

输入是带评测结果的执行轨迹，包括推理、动作、观察与结果。确定性过滤器删除运行噪声，而不把轨迹替换成模型摘要。成功分析提取有证据支持的行为及脆弱成功所需的保护措施；失败分析定位有证据的错误或缺失步骤，以及最小的受支持恢复方案。每个候选“语义梯度”是附带精确轨迹行证据的自然语言行为更新，不是数值梯度。分析器输出一个核心发现、至多两条可复用经验和至多一个脚本建议。

## 迭代回路与保留/拒绝规则

路由器拒绝泛泛、无证据、样本特定或冗余的发现，再为保留项分配一个主要角色、至多一个次要角色。Meta 与 Experience 维护原子规则；Tool 按能力组织规则；Script 建议须值得确定性复用，具有明确输入/输出与错误契约、可行测试，并能比一次性工具调用节省工作。

脚本被实现或修改、自测，并在干净环境中接受独立验证，允许一次有界修复；未验证代码不被保留。协调器解决跨组件冲突与重复，再重写组件描述，说明适用范围、调用时机和预期收益。协调或描述验证失败时，不发布更新状态。**这是证据与编辑契约门控，不是“任务分数提高才接受”的门控**（附录 G）。执行时由智能体原有调用机制选择相关组件；描述在加载前已经可见，因此没有记录到加载，不等于完全未接触该组件。

## 决定收益是否可信的对照实验

- **留出，但仍是同类任务集合。** 每个选定基准集合按训练:测试 = 2:7 划分；训练部分提供轨迹，报告分数来自测试部分。这是从评测任务的同类任务学习，而非无关外部轨迹库。SWE-Pro 包含 pandas、scikit-learn、xarray，AutomationBench 包含 Sales、Marketing；论文未称划分按仓库或领域隔离。未报告准确划分规模、划分种子/分组方式以及训练/测试重叠审计。路由器排除样本特定答案，但这不等于实证泄漏审计。
- **基线权限与预算。** 每个模型—框架配置内，Trace2Skill、SkillOpt-lite、EvoSkill 与 CDSE 共用训练划分、任务实例、工具权限和上下文限制。Base 是无进化技能的同一智能体。Trace2Skill 合并 Error 与 Success 两条分析分支的更新。EvoSkill 只用错误样本，运行 1.5 个 epoch，frontier 大小为 3。SkillOpt-lite 运行 10 轮优化，batch 大小为 10。表 1 的每个技能进化方法都运行三轮外层进化。论文没有说这些基线获得 CDSE 的分化技能库、路由器或验证机制；明确拿到相同语义梯度的是**去掉认知分化的消融变体**。共享权限与接近的 token 总量有参考价值，但不是精确算力匹配。
- **机制消融，GLM-5.2/Claude Code（表 3）。** SpreadsheetBench2 / SWE-Pro / AutomationBench 上，完整方法为 **30.7 / 68.4 / 32.9**。保留相同语义梯度、但合并组件：**25.8 / 62.6 / 24.3**；共享更新器：**27.1 / 65.4 / 28.0**；去掉协调：**29.6 / 67.5 / 30.7**；去掉自适应调用接口：**26.4 / 64.3 / 27.1**。这些对照支持“组织与调用”超出单纯经验提取的作用，但没有不确定性或运行次数。
- **迁移有边界。** 固定 Claude Code，在 GLM-5.2 与 DeepSeek-V4-Flash 之间交换完整技能状态，12 个接收配置中 11 个提高；每个接收模型平均提高 4.2 点。固定 GLM-5.2，在 Claude Code/Codex 之间交换状态，全部 12 个配置提高，均值分别为 3.3、3.4 点。跨基准组件迁移更有选择性：Meta 在 10 个源—目标组合中 9 个提高，平均 3.6 点；Tool、Script 的收益不稳定（表 2、11–12）。这并未覆盖所有模型—框架组合。
- **默认值与调参划分要分开。** 附录 H 称基线参数遵循原方法建议，另有说明者除外，但未报告用于选择超参数/默认值的划分，也未报告基线调参/搜索预算。未说明独立开发集，**不等于**已证明用测试集调参。缺失的数值细节包括规则/类别容量、每题运行时间上限、技能进化解码参数；进化模型身份与初始化内容也未明确。基准评分规则、若干 turn 上限、SealQA 裁判温度与输出上限则有提供。
- **蒸馏成本，不是免费复用。** GLM-5.2/Claude Code 单轮进化中，CDSE 在 SpreadsheetBench2 使用 **50.90 百万输入 / 2.800 百万输出 token**，SWE-Pro 为 **127.80 / 5.800**，AutomationBench 为 **24.70 / 1.100**（表 5）。其他方法单轮总量接近。表 4 的每提高一个百分点所需百万输入 token 为 **7.60 / 15.04 / 2.19**，分母用的是当轮收益，不是三轮后的头条收益。未给出美元或墙钟成本、完整三轮总成本，也没有单独拆出蒸馏各阶段的成本。

## 增益缺失或较小之处

表 1 全部单元格均有利于 CDSE，但领先幅度并不一致。MiniMax-M3/Codex 的 SpreadsheetBench2 为 **29.4 对 29.1**（SkillOpt-lite），GLM-5.2/Claude Code 的 OfficeQA 为 **77.2 对 76.4**。没有不确定性，不能判断统计显著性。AutomationBench 相对 Base 的收益在 Claude Code 下更大：GLM、DeepSeek、MiniMax 分别为 **12.1、14.6、10.9** 点；Codex 下为 **4.9、8.4、5.5** 点，收益并非跨框架均匀分布。

多轮整合重复使用**同一批轨迹**。GLM-5.2/Claude Code 从第二轮到第三轮，OfficeQA 为 **77.8 → 77.2**，SWE-Pro 为 **69.0 → 68.4**，AutomationBench 为 **33.3 → 32.9**（表 8）。头条报告第三轮状态，而非声称挑出的最佳检查点。这不能证明获得新经验时会持续改进。

迁移也可能有害：DeepSeek-V4-Flash 在 SealQA 接收 GLM 技能后为 **48.5**，低于 Base 的 **51.8** 和原生状态的 **59.4**（表 11）。Spreadsheet 的 Script 迁移到 SWE-Pro 为 **−3.9** 点，Meta 迁移到 LiveMath 为 **+0.0**（表 2）。token 效率也并非处处最优：OfficeQA 每提高一点所需百万输入 token，SkillOpt-lite 为 **6.64**，CDSE 为 **7.87**（表 6）。

## 我们的解读（Our read）

最新存储判断为 **64 · ★★ · retained**。论文报告了留出任务评测、技能/组件迁移、机制消融与单轮 token 成本；预算匹配为部分满足。未报告种子方差、基线调参预算、默认值的选择划分，或训练/测试泄漏的实证审计。证据支持对留存技能进行分化维护，不支持改进协议本身不断变强，也不支持无限持续自改进。最干净的对照是“相同语义梯度、取消分化”的消融；主要未决问题是统计稳健性、划分细节与完整优化成本。
