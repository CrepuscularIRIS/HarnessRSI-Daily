# 收录范围与证据等级

## 收录范围

**Harness 级 RSI**：系统基于自身执行反馈，修改自己的**非权重**组件（prompt、skill、tool、workflow、memory/playbook、agent 代码、评测器、配置），并且改动会留存到下一轮。

- **A 类**：论文本身就是这样一个自我改进闭环。
- **B 类**：不构成闭环，但是可以直接放进闭环使用的组件，例如反思式 prompt 优化器、轨迹到技能的编译、工作流搜索、泄漏审计方法。
- **不收录**：更新模型权重的自我改进（self-rewarding、self-play 微调、自蒸馏等）；只在单次输出内自我修正、没有留存改动的方法；没有自我修改闭环的通用 Agent 框架。

## 证据等级

这三级定义沿用 [lobehub/awesome-rsi](https://github.com/lobehub/awesome-rsi#scope--terminology) 的区分。我们的工作是对**每一篇**收录做判定，并写出判定理由。

| 等级 | 需要的证据 |
|---|---|
| `task` | 任务输出或分数变好，但没有证明这是留存下来的系统改动带来的 |
| `retained` | 留存的改动在之后的任务上带来提升，最好在独立的留出任务上展示 |
| `improver` | 改动对象包括改进机制本身，并且在可比预算的对照实验中，改进后的机制产生了更有效的后续改动 |

判定规则：

1. **按证据判，不按架构判。** 架构上存在递归或自我引用，不等于已经证明了 `improver`。
2. **选择集不能当留出集。** 用来挑选候选的验证集已经参与了优化。只在选择集上报告的提升，最高判为 `task`。
3. **失败要计入分母。** 如果论文剔除了失败或未评分的 trial，诊断里要写明。
4. **作者自称与我们判定分开写。** frontmatter 里的 `evidence_level` 是我们的判定。
