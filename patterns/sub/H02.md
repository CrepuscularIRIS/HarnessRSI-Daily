# H02 — Mine Interaction Streams into Skill Packages
_parent: **Abstract Experience into Reusable Guidance** (`abstract_experience_into_guidance`) · corpus support: 16 papers (accepted 4 · rejected 1 · unlabeled 11)_

## Tactical pattern
Recurring procedures are mined from interaction histories, pooled user sessions, guides, or domain resources and
compiled into structured, versioned skill packages — instructions, scripts, metadata, and a hierarchy or relation
graph — that are portable across agents and backbone models. Extraction is followed by deduplication, merging with
neighboring skills, and a quality or execution gate before a package is published to a shared library and
activated on demand. The decisive design choice is the retention gate: which candidate skills survive (judged
durable, tested by execution, passing a multidimensional quality filter) and how a new version merges with an
existing one. Success is certified by downstream gains when packages are reused by agents or on tasks other than
those that produced them, not by counts of skills in the library.

## Step-by-Step
1. Pick the source stream and the skill grain: user-grounded durable constraints, cross-user session pools, or
   external resources; planning, functional, or atomic granularity matched to the tool schema.
2. Compile each candidate into an explicit contract (inputs, steps, scripts, metadata) that another agent can
   execute without the original context.
3. Gate retention by execution, tests, or a quality judge, and merge against neighboring skills with versioning
   rather than appending duplicates; report what fraction of mining attempts survive, not only the retained ones.
4. Track coverage — a domain tree or relation graph — so mining targets gaps instead of re-mining frequent
   procedures, and prune skills that over-imitate or hurt weaker consumers.
5. Evaluate reuse on tasks and agents disjoint from those that produced the skills, with a controlled downstream
   comparison. Stopping refinement on test performance, building on-demand skills for the very workflows used for
   evaluation, or reporting library statistics instead of downstream gains are the gaps members themselves admit.

## Differentiation within parent
H02 produces portable, structured skill artifacts from many sources and maintains them as a shared library. H00
distills one agent's own outcomes into free-form lessons, mainly by appending. H01 runs an edit policy over a
single memory in place; H02 also merges and versions, but its unit is an executable package meant to leave the
agent that made it.

## When to pick this one
The tell: the same procedures recur across many users, sessions, or agents, and the payoff is reuse by a different
consumer (another model, another user, a weaker agent). Pick H00 when one agent's own trajectories are the only
source and the guidance can stay informal; pick H01 when the problem is keeping one growing memory consistent.

## Tactical failure mode
The signature failure is evaluating the library instead of its use: reporting skill counts, qualitative examples,
or retained-skill validity while the downstream comparison is missing, uncontrolled, or contaminated by building
and tuning skills on the evaluation tasks. The single rejected member is a low-fit variant that splits monolithic
prompts into a domain-invariant shared part plus small per-task adaptations, with no retention gate;
one member cannot establish a rejection pattern. The root assumption that fails is that a well-structured,
versioned artifact transfers by construction — portability across agents and tasks has to be measured, and it can
backfire when weaker consumers over-imitate.

## Lessons
### From accepted work
- Versioned, judge-controlled merging lets recurring user requirements become behavioral skills rather than only
  retrievable facts.
- Multi-source extraction plus multidimensional quality filtering turns fragmented experience into evaluated,
  interconnected assets.
- A coverage-tracked domain map, with execution and synthetic tests gating retention, keeps mining aimed at gaps.
- Separating planning, functional, and atomic skills by tool granularity supports transfer across agent models.
- Watch weaker consumers: some skill combinations hurt them through over-imitation.
### From rejected work
- Factoring prompts into a shared part and per-task adaptations is reuse of structure, not mined experience;
  without a retention gate it reads as prompt engineering.
