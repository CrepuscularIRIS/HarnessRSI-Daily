# H05 — Retrieve Only When Needed
_parent: **Index Raw Experience for Reuse** (`index_experience_for_reuse`) · corpus support: 9 papers (accepted 3 · rejected 0 · unlabeled 6)_

## Tactical pattern
Turn memory access into a decision instead of a fixed pre-task injection. A controller or the agent itself
decides, at each step, whether to consult the store — triggered by uncertainty (for example step-type
specific entropy thresholds), confusion, memory pressure, or an explicit reasoning-time retrieval call —
and whether a cheap summary suffices or deeper, iterative search is warranted. Weakly matched memories are
suppressed and the agent falls back to unaided reasoning. The decisive design choice is the trigger signal
and its calibration: experience is spent only where it changes the decision, which keeps context small and
avoids distraction. Success is certified by comparing gated retrieval against always-inject and
never-inject on the same store, on held-out tasks, with the trigger's own cost counted.

## Step-by-Step
1. Keep the store fixed and move the intervention to the access policy, so any gain is attributable to
   timing and gating rather than to new content or structure.
2. Choose a trigger signal and calibrate it per step type — model uncertainty, a controller judgment, or a
   learned retrieval action — and check that it actually discriminates steps that go wrong; a weakly
   discriminating signal is a stated limitation of accepted work.
3. Add a relevance gate with a fallback: when the best match is weak, retrieve nothing rather than inject a
   distractor, and let the policy choose between summary and full history.
4. Count the overhead. Report extra inference calls, runtime, and any training compute for a learned
   trigger; unlabeled members repeatedly note added calls, runtime, or unaccounted training cost.
5. Test across backbones and domains. Gating policies that rely on strong instruction-following or
   function-calling degrade with smaller models; show where the policy stops paying off, and evaluate
   beyond the single task family the thresholds were fit on.

## Differentiation within parent
H05 changes the timing and gating of memory use. H03 changes what is reused (near-raw precedent cases,
matched and adapted) and H04 changes how the store is shaped and indexed. Abstraction-family patterns
outside this parent change the content written to memory; H05 can sit on top of any of these stores.

## When to pick this one
Pick H05 when a useful store already exists but injecting it up front hurts: long tasks whose needs shift
mid-execution, prompts bloated by mostly irrelevant experience, or failures that cluster at identifiable
uncertain steps. The tell is that always-on retrieval helps on some steps and harms on others. If the
matched experience itself is wrong or unadaptable, fix the cases (H03); if relevant items cannot be found
at all as history grows, fix the structure (H04).

## Tactical failure mode
The root assumption that fails is *"the agent can tell when it needs help."* The trigger is only as good as
the confidence signal or the base model's self-management: one accepted member reports that its entropy
signal weakly discriminates incorrect steps and that thresholds depend on training data, and 4 of 9
members state dependence on base-model strength — instruction-following, function-calling ability, or
model scale (accepted 1 · unlabeled 3). The second failure is hidden cost: 5 unlabeled members state added
inference calls, runtime, test-time or training compute, or upfront memory construction cost. A third is
that compressed or summarized fallbacks can omit decision-critical details.

## Lessons
### From accepted work
- A controller that decides both whether retrieval is needed and whether a summary suffices limits
  distracting history without touching model weights.
- Triggering guidance at uncertain intermediate steps, with thresholds set per step type, beats a single
  pre-task injection — and the accepted version backs it with held-out and cross-task checks.
- Iterative, learned retrieval over entity-centric episodic and semantic memories handles streams too long
  for one-shot lookup.
- Retained-store ablations (2 of 3) and released code (3 of 3) accompany the accepted members.
### From rejected work
- No labeled rejections in this sub-pattern; the cautions below come from unlabeled members' stated
  limitations, not from rejection outcomes.
- Gains that depend on strong base models should be scoped as such.
- Extra calls and runtime from gating can offset the context savings; report both.
- Upfront memory construction cost and untested online accumulation leave the "improves with use" claim open.
