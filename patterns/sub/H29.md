# H29 — Value Memory Entries by Measured Utility
_parent: **Gate Retention on Measured Evidence** (`evidence_gated_retention`) · corpus support: 16 papers (accepted 2 · rejected 3 · unlabeled 11)_

## Tactical pattern
Every stored experience carries a utility estimate learned from what happened after it was used, not from how
similar it looks to the current query. The value comes from outcomes: reward-updated action values, bandit
statistics, the generator's own citations of the entries it relied on, a memory-on versus memory-off contrast, or
credit propagated backward through the provenance of entries that were built from other entries. Retrieval
ranking, admission and suppression then read that value, usually after a cheap semantic pre-filter. The decisive
design choice is the counterfactual behind the credit: who is credited when several entries are retrieved
together, and against which no-memory or unguided baseline. Success is certified when value-ranked memory
beats similarity-only memory and an ablation that strips the value signal loses the gain.

## Step-by-Step
1. Pick the unit that earns credit (raw episode, distilled rule, graph edge or triplet, path, strategy) and keep
   its content human-readable so a demotion can be audited.
2. Define the counterfactual that produces the credit: a paired run without the entry, an unguided rollout, or an
   explicit usage signal. Credit from an untested self-grade inflates wrong entries and compounds them through
   reuse; check the grader with an answer-free audit before trusting it.
3. Decide how credit is shared when entries are co-retrieved and whether it flows to ancestor entries; per-entry
   values that ignore the retrieved set are an approximation, so say so.
4. Feed the value into ranking, admission or demotion, behind a semantic gate, and add decay so stale entries
   lose weight under distribution shift.
5. Report a value-stripped ablation against similarity-only retrieval on held-out tasks. Letting memory evolve on
   the evaluation stream itself, or pushing the utility signal into policy, prior or embedding training without
   isolating the memory effect, is the boundary rejected members crossed.

## Differentiation within parent
H29 assigns credit to individual entries and changes how they are ranked or shown. H30 decides which entries
belong in a shared library at all (admission tests, retirement, size bounds). H31 decides whether a whole-system
change replaces the incumbent. An H29 system can still keep every entry; it only re-weights them.

## When to pick this one
The tell: memory already exists, retrieval returns plausible but unhelpful neighbours, and outcomes for each use
are observable cheaply. Pick H30 when the store must stay bounded or harmful entries must be removed for good;
pick H31 when the thing changing is the agent itself rather than its memory.

## Tactical failure mode
The root assumption that fails is that the observed outcome is a clean signal of the entry's contribution.
Rejected members turned measured utility into a learning signal for something beyond the memory (graph-edge
policy gradients that guide policy learning, online embedding updates, value estimates that refine the model
prior), so the memory's own effect is never isolated. Across unlabeled members the recurring gaps are ambiguous credit under multi-entry retrieval,
self-graded rewards that inflate wrong memories, provenance that records exposure rather than causal influence,
and memory that keeps evolving during evaluation episodes or is built from test queries.

## Lessons
### From accepted work
- Use the generator's own reliance on an entry (which memories it cites) as free online feedback for a light
  reranker, avoiding labeled relevance data.
- Credit memory with an explicit memory-on versus memory-off contrast and let that contrast both reweight entries
  and revise the rules for compiling guidance.
- Gate updates on significance so noise does not churn the store, accepting that subtle heuristics arrive later.
- State the extra cost of the contrastive or online-learning step as a limitation rather than hiding it.
### From rejected work
- Routing entry utility into training of a policy, prior or embedding blurs the claim; the memory effect must be
  separable from the learning effect.
- Paired guided and unguided rollouts are expensive; without a budget account the gain is hard to credit.
- Retrieving too many strategies adds noise; show the retrieval width at which value ranking still helps.
- Online embedding updates from task-success feedback tune the retriever, not the entries; that is retrieval
  adaptation, not utility-valued memory.
