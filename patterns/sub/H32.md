# H32 — Isolate Effects with Controlled Interventions
_parent: **Diagnose Whether Self-Improvement Is Real** (`diagnose_self_improvement`) · corpus support: 13 papers (accepted 5 · rejected 1 · unlabeled 7)_

## Tactical pattern
Take an existing self-improving system whose end-to-end score rises and ask *where the gain lives*. The move is
to cut the causal chain with a matched or frozen condition: perturb the content of retained memory while keeping
its form, freeze the system at one generation and inject chosen feedback subsets, cross the model that writes
updates with the model that consumes them, or give the baseline the same search and verification budget. The
decisive design choice is which variable is held fixed. The intervention has to separate the retained artifact
from extra search, superficial prompt effects, and reuse of benchmark feedback. Success is certified by a
measured isolated effect, often a null or negative one, that is reported as the finding itself rather than buried
as a failed ablation.

## Step-by-Step
1. Name the confound in the headline curve: extra attempts, reused verifier feedback, prompt length, task priors,
   or the executor's own strength. Write the alternative explanation down before designing anything.
2. Choose the cut that kills exactly that explanation: content perturbation (raw vs. condensed memory), a frozen
   generation with feedback subsets, an updater × user model cross, or a compute- and feedback-matched baseline.
   Comparing optimizer/task-model pairings end to end is a sweep, not a cut. Skipping the matched control is
   what sinks the one rejected member.
3. Hold evaluation apart from the improvement loop. Use held-out or separated tasks, and test whether gains survive
   once task-level search is no longer available.
4. Measure marginal and interaction effects, not only the total, and keep the raw evidence: raw episodes next to
   consolidated ones, typed failure records next to the edits they motivated.
5. Report the negative branch explicitly (noisy memory degrading performance, poor transfer of evolved artifacts,
   personalization gains that are not significant) and state the conditions under which the effect is conditional.

## Differentiation within parent
H32 is an analysis protocol run *on* existing systems. H33 builds reusable stream benchmarks for persistence and
transfer. H34 benchmarks the agent's ability to do the improvement work itself. H35 targets adversarial or
safety-relevant persistence. H32 builds no new benchmark and no attack. Its product is an attribution.

## When to pick this one
The tell is a system that already reports a rising score, plus a plausible cheaper explanation (more compute,
feedback reuse, memorized tasks, the executor being strong) that nobody has ruled out. Pick H32 when one targeted
intervention can falsify that explanation. If the real gap is that no benchmark can separate persistence from
episode success, H33 fits better. If the worry is harm rather than inflation, use H35.

## Tactical failure mode
The root assumption that fails is that one controlled cut generalizes beyond the conditions it was run in.
Members' own limitations show the ceiling: attribution holds only at frozen generations, there is a single
evolution run per setting, analysis is restricted to successful cells, mechanism explanations are post hoc,
mitigations are tested mainly on one stream, and some regression tests reuse the problems that produced the
memory. The one rejected member (low fit) shows the other failure: it compared pairings end to end, with no
isolating intervention. So its claim that optimization "still helps" stayed
confounded with budget.

## Lessons
### From accepted work
- Perturb what the memory *says*, not just whether memory exists. Presence and benefit do not prove semantic use.
- Keep raw episodes beside consolidated summaries and gate consolidation, because repeated lossy rewrites compound.
- Freeze state at a generation and inject feedback subsets to get marginal and coalitional attribution, with
  variance and matched budgets reported.
- Match feedback and inference budgets, and evaluate on held-out tasks with leakage tested, to tell task-level
  search apart from transferable artifact design. Report the poor transfer too.
- Route edits from typed failure records as falsifiable predictions, and let later rollouts reject unsupported ones.
### From rejected work
- An end-to-end sweep over model pairings is not a controlled intervention, so it cannot say where a gain comes from.
- Claims that optimization remains useful need a compute-matched baseline. Without one, the claim restates the score.
- One rejected member is too few to generalize. Treat these as cautions, not evidence.
