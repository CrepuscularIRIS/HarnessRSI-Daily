# H34 — Benchmark Agents Doing AI R&D
_parent: **Diagnose Whether Self-Improvement Is Real** (`diagnose_self_improvement`) · corpus support: 10 papers (accepted 2 · rejected 2 · unlabeled 6)_

## Tactical pattern
Treat the agent as a researcher, not a task solver. Inside an isolated, budgeted workspace it must produce an
artifact that changes how *something learns*: a training pipeline, a data strategy, an agent harness, a learning
algorithm, or a policy-training loop. The decisive design choice is the boundary between what the agent may edit
and what stays protected. Edit scopes are calibrated against a baseline. Reset, verification, and scoring
interfaces are immutable. A frozen post-submission evaluator reruns the submitted artifact from scratch under a
matched budget. Success is certified only when that independent rerun, ideally across several settings, shows the
artifact itself improves learning. A high score on the feedback the agent saw during development does not count.

## Step-by-Step
1. Specify the research deliverable (training source, harness, data recipe, or learning objective) and the budget
   in compute, time, and queries.
2. Protect the evaluation surface. Constrain the editable scope, make reset and verification immutable interfaces,
   and keep the scorer outside the workspace. Edits must not reach the protocol.
3. Separate development feedback from held-out scoring. Repeated grading on the same subset, or proxy and final
   evaluations that share samples, invites adaptive overfitting.
4. Rerun the submitted artifact from scratch under a matched budget, across more than one setting, and when
   possible check that a successor inherits the gain.
5. Run more than one trajectory per cell and keep incomplete runs in the denominator. A single evolution trajectory
   per creator-runtime cell, with stopped pairs excluded, is what weakens the rejected high-fit member.

## Differentiation within parent
H34 evaluates the *capability to perform* self-improvement work. H33 evaluates whether improvements *persist and
transfer* across a stream. H32 attributes the gains of an existing system with interventions. H35 audits
persistent state for adversarial or safety failures. H34's artifact is code or data that is rerun, not retained
memory.

## When to pick this one
The tell is a claim that agents can automate parts of ML research or engineer their own scaffolds, where the
evidence is a visible benchmark score the agent was allowed to iterate against. Pick H34 when you can build a
workspace where the evaluator is frozen and reruns the artifact. If the question is whether a deployed agent keeps
improving across tasks, H33 fits better.

## Tactical failure mode
The root assumption that fails is that the scoring loop the agent iterates against is independent of what it
optimizes. Limitations across members repeat it: the main protocol exposes evaluation settings during iteration,
selection and official evaluation reuse the same subset, proxy and final evaluations share samples, and repeated
grading permits adaptive overfitting. A second failure is attribution. Researcher identity confounds model,
scaffold, and reasoning effort, and full-stack outcomes mix several capabilities. Single runs per configuration
recur. The low-fit rejected member scores learning only through repeated open-ended competition, with no evident
limitations recorded.

## Lessons
### From accepted work
- Calibrate edit scopes against a baseline and protect the protocol, so a score change can be attributed to a
  method change rather than tuning or evaluator exploitation.
- Probe transfer by evaluating the same submitted method across multiple settings, with leakage explicitly tested.
- Make the costly parts of the loop (reset, verification) repeatable immutable interfaces. That turns them into a
  closed feedback loop instead of a human bottleneck.
- Report optimizer cost honestly, including costs that grow super-linearly with scale.
- State the scale ceiling: results at reduced scale cannot establish behavior in larger regimes.
### From rejected work
- One evolution trajectory per cell, with stopped or incomplete pairs excluded, leaves the artifact claim without variance.
- Held-out evaluation confined to a single benchmark undercuts a claim that harness-building is a general capability.
- Open-ended tournament scoring measures relative standing, not whether the produced artifact improves learning.
- Separating creator and executor roles is necessary but not sufficient without repeated runs and improver comparisons.
