信任分拦不住高置信的毒：
记忆投毒防御在现实设定下塌成置信度过滤器

EHR agent 记忆投毒实测：换到真实记忆库设定，攻击效果大打折扣——但作者提出的信任评分防御更值得警惕：它放行的恰是表达最自信的毒条目。

2601.05504v1
arXiv 预印本
本项目重绘 · 非作者海报

攻击面

MINJA 式注入：普通用户权限、纯查询通道，无记忆直写权；把恶意指示埋进会被记忆功能持久化的"合法"查询里。理想化设定下 ISR>95%、ASR>70%（Dong et al. 2025）。

现实设定

记忆库预先存有真实交互史（正当地占住检索位）、攻击者只发 50 条合成指示、检索参数可调——比理想化设定接近部署。

防御设计

两段式：输入/输出审核（静态启发＋关键词＋LLM 语义分类合成信任分）＋记忆清洗（trust-aware 检索＋时间衰减＋模式过滤）。

核心发现 · 信任门的失效路径

候选记忆条目

混有毒条目与正常条目，逐条过信任门

→

信任评分门

多信号合成 trust∈[0,1]，阈值放行/拒绝；时间衰减只作用于存量分

→

塌缩成置信度过滤器

放行的依据≈"模型自己多确信"，而非"内容多安全"

毒条目并不低声下气——表达自信的投毒拿到满分 1.0 通行；检索侧过滤因被接受条目清一色 1.0 而完全无从下手。trust 与 security 是两个轴，此防御把两者焊死了。

实验一 · GPT-4o-mini：全拒之门

0/2323 条候选全部拒收——记忆库为空，无毒，但也彻底没用了
  • 过严的另一面：把可用性一起牺牲，防御目标漂移成"拒绝一切"。
  • 安全姿态与功能同时归零，说明门的设计没有可用的校准点。

实验二 · Gemini-2.0-Flash：满分毒条目

54/82被接受的 82 条里 54 条是毒条目，且 trust 一律 1.0
  • 被拒的 69 条平均 trust 0.35——拒的是不自信，不是毒。
  • 检索侧 trust 过滤全失效：82 条全是 1.0，无梯度可滤。

单攻击族单域

仅 MINJA、仅 EHR/MIMIC-III；两模型完整（Llama-3.1-8B 仅摘要提及）。

一对 victim/target

1 对身份、50 条合成指示；检索参数扫描的定量结果缓存未见具体数值。

无自适应攻击者

攻击固定不针对防御调优；对信任门的白盒绕过未测。

结论仍成立的部分

trust 与 security 解耦的必要性由两个模型的对偶失败支撑，不依赖扫描数字。

信任分测的是"像不像真话"，投毒攻击造的恰是"最像真话的话"。

现实设定削弱了攻击，但也暴露了防御：一个把置信度当安全性的门，会在两端同时失败——全拒（0/23）或放毒（54/82）。安全需要独立于置信度的证据轴。
