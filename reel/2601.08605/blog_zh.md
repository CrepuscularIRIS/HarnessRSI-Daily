# ExpSeek：熵升高时再寻求经验，而不是只在任务开始前注入

*Reel 解读：**ExpSeek: Self-Triggered Experience Seeking for Web Agents**，[arXiv 2601.08605v2](https://arxiv.org/abs/2601.08605v2)。HarnessRSI 评分 **63**，档位 ★★，证据等级 **retained**。代码：[WYRipple/ExpSeek](https://github.com/WYRipple/ExpSeek)。*

## 系统改变了自己的什么

ExpSeek 构建可复用的**经验库**，并在选定的推理步骤改变智能体的上下文。它不训练智能体权重，也没有描述一个在每道评测题后改写自身的在线优化器。

离线阶段，Qwen3-8B 或 Qwen3-32B 对每道训练题采样五条轨迹。Qwen3-235B-A22B-Instruct-2507 工具模型对比成功与失败轨迹，读取训练答案、标注步骤正确性，并为错误步骤提取 **Behavior / Mistake / Guidance（行为／错误／指导）**三元组。构建时可以复用、修改或创建主题，过程步骤与答案步骤的经验分开存储。论文没有报告以验证分数决定三元组接受或回滚的门控。

## 触发信号，以及什么被保留

触发信号是**智能体响应分布的平均 token 熵**，不是模型用文字自报的置信度。论文分别针对过程步骤和答案步骤，用逻辑回归关联熵与工具模型在训练轨迹上给出的正确性标签，再通过 bootstrap 得到决策边界区间。低于下界不指导，高于上界指导，区间内按线性上升的概率触发。一次干预后的下一步禁止再次干预。

触发后，经验模型读取当前交互历史，选择最相关的三个主题，并根据其中的三元组生成情境化指导。过程步骤把指导附在工具观察之后；答案步骤则加入新的观察，让智能体修改答案或继续调用工具。指导保留在**当前历史**中；方法没有描述把新寻求的测试时指导或测试轨迹写回持久经验库。因此，留存的产物是经验库和拟合阈值，而不是不断增长的测试时记忆。推理提示词禁止直接给答案或线索，但这条指令本身不等于泄漏审计。

## 论文报告的主要结果

表 2 报告的是**五次独立运行的平均准确率**，不是最好的一次。Avg. 列中，Qwen3-8B 从 **32.23 升至 41.50**，Qwen3-32B 从 **37.79 升至 45.32**，即论文四舍五入后报告的 **9.3 和 7.5 个百分点**。该 Avg. 列最强的经验基线 ReasoningBank+ 分别为 34.80 和 39.33。

| 基准 | 8B：无经验 → ExpSeek | 32B：无经验 → ExpSeek |
|---|---:|---:|
| WebWalkerQA Avg. | 38.47 → 48.25 | 45.01 → 51.09 |
| GAIA | 29.13 → 36.89 | 36.50 → 43.88 |
| SEAL-HARD | 23.23 → 30.16 | 27.80 → 32.76 |
| xbench-DeepSearch | 25.60 → 37.20 | 27.40 → 42.00 |

**聚合口径提醒：**我们的表 2 算术解读是，Avg. 对 WebWalkerQA Easy、Medium、Hard 分别计权，再加 GAIA、SEAL、xbench，共六‡列等权；不是四个基准平均值的宏平均。收益不只出现在某一个基准，但最大的已报告增幅在 **32B xbench，为 14.6 个百分点**；32B WebWalkerQA Hard 则提升 4.8。

智能体使用非思考模式，temperature 为 1.0、top-p 为 0.95，配备 Search 和 Visit，ReAct 步数上限为 30，超出即失败。主要经验模型是 **235B**；经验构建、裁判和 Visit 摘要也由同一型号提供。因此这些结果不是孤立的小模型系统。表 2 没有给 SD、SE 或置信区间，没有列运行种子，也没说明每次运行是否独立重建经验库。划分种子 0 不能误作评测运行的种子。

**评测规则提醒：**准确率由 Qwen3-235B-A22B-Instruct-2507 作为 LLM 裁判判定（附录 C，PDF 第 17 页）。其提示词接受包含标准答案的预测，即使附有额外解释也可判对（表 19，PDF 第 29 页）。论文未报告独立裁判或人工评分验证。这些是该规则下的模型判分，不足以据此认定比较存在偏差。

## 决定收益是否可信的对照

- **过程指导与答案指导（表 2）。** 完整／仅过程／仅答案的 Avg.：8B 为 **41.50 / 36.59 / 39.06**；32B 为 **45.32 / 40.81 / 41.20**。两类指导都有助于聚合分数。这些行适用表 2 的五次均值说明，但没有方差。
- **可比的指导权限（表 3）。** 规则触发与 Claude-sonnet-4-20250514 触发均能使用生成式经验模型，并有相同的一步冷却。8B GAIA 上，熵触发 **36.89**，低于规则的 **38.81** 和 Claude 的 **39.47**；但每题只需 **127.57 秒**，另两者为 **329.71 秒**和 **370.82 秒**。xbench 上为 **37.20**，另两者为 **36.40** 和 **36.60**。所以熵触发是效率与准确率的折中，不是处处最高准确率。表 3 没有单独注明运行次数，也没有不确定性。
- **检索与生成（表 3）。** 保留熵触发，以 text-embedding-v4 检索最近三元组并直接使用，GAIA 为 **30.92**、xbench 为 **27.80**；生成指导则为 **36.89** 和 **37.20**。这是比只对比无经验更有力的检索对照。
- **头条基线的经验权限不同（§5.1）。** Training-Free GRPO 用语义优势从离线轨迹迭代提炼经验，再全局提供；ReasoningBank+ 在线积累经验，检索后放入系统提示词，且经验生成器明确升级为 **235B**。论文没有证实它们得到 ExpSeek 完全相同的三元组或步级生成式导师，具体数据／重置协议也未充分交代。不能把这个权限限制扩展到表 3 的触发器对照——后者确实能使用导师。
- **经验库贡献与迁移（§6.3、图 7、表 4）。** 移除经验库会降分，但无库的导师仍有帮助；不能把全部提升归于留存经验。跨模型规模交换经验库后仍优于无经验，但低于各自原生经验库：32B GAIA **43.88 → 40.33**、xbench **42.00 → 37.20**；8B GAIA **36.89 → 35.60**、xbench **37.20 → 36.00**。这里交换的是库，并没有证明整套校准触发器也能一起迁移。

## 数据划分、调参与泄漏

经验库和熵阈值全部来自 **170 道 WebWalkerQA 训练题**：用种子 0 从各难度抽取 25%，剩余部分作为 WebWalkerQA 测试集。GAIA、SEAL-HARD、xbench 检验这些经验的跨基准复用。寻求经验时会读取当前测试上下文，但推理提示词没有提供评测标准答案。

这一明确的训练／测试分离有价值，但随机按题划分并不证明相关题目或来源网页互不重叠。全文及附录没有报告近重复／跨基准污染审计；ReasoningBank+ 在线记忆如何重置也未充分说明，所以仅凭论文无法还原该基线对评测任务的暴露情况。

阈值明确在训练标签上拟合，使用 1000 次 bootstrap 和 scikit-learn LogisticRegression 默认设置。论文没有指出选择三个主题、冷却或其他默认项的独立划分；阈值／间隔敏感性扫描在 **8B GAIA** 上进行，也没有说明默认值由独立调参集选出。缺少的基线数值设置包括 Training-Free GRPO 的迭代次数／组大小、ReasoningBank+ 的检索数量／记忆容量，基线调参或搜索预算也未报告。这与“阈值拟合划分缺失”不同——后者是明确的。

## 收益缺失或较小之处，以及寻求经验的代价

- **SEAL 上增加过程指导的额外收益很小。** 完整对仅答案：8B 为 **30.16 对 30.08**，32B 为 **32.76 对 32.52**。32B WebWalkerQA Hard 上，完整 **45.89** 也接近仅过程的 **45.56**。没有不确定性时，这些只能称为小差异，不能称为已证实稳定的胜出。
- **熵触发在 GAIA 准确率上输给**上文更昂贵的规则与 Claude 触发。ExpSeek 胜过表 2 的头条基线，不等于胜过全文所有变体。
- **额外交互是真实成本（表 3，仅 8B）。** GAIA 从无经验的 **4.47 步 / 66.94 秒**变为 **5.75 / 127.57 秒**；xbench 从 **3.31 / 51.06 秒**变为 **5.73 / 143.81 秒**。共同步数上限不等于实际算力匹配。论文未报告头条基线的 token 或墙钟匹配对照、token／美元核算，也未报告完整的离线轨迹与三元组构建成本。单独的阈值回归每种步骤类型只需数秒，但那不是总准备成本。

按最新匹配判断（b16）：**63 · ★★ · retained**。论文报告了留出评测、跨基准及跨模型经验库复用、指导／检索消融和五次运行均值；**未报告**运行方差、头条比较的算力匹配、污染审计或完整构建成本。判断记录中的 `optimizer_cost: unclear` 不应遮蔽表 3 的在线步数与时间：它们衡量部署开销，不是完整离线成本。

可辩护的结论是：**通过条件触发的导师复用错误指导三元组，可以改善网页推理，但要支付可测量的推理成本**。这不是“自我改进算法自身变得更好”的证据，也不能证明熵触发总能最大化准确率。
