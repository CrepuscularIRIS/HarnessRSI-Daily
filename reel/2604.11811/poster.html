问题

记忆设计在“设计时”就被定死了

对话需要人物与事件的语义索引，具身规划需要可复用的动作模式，专业推理可能需要结构化数据库。Mem0、ReasoningBank、GEPA 等固定设计各自擅长某些任务——论文 Table 1 中最强基线随任务而变。问题是：能否针对给定任务自动找到合适的存储、检索与使用方式，以及一种任务上找到的设计能不能直接搬走。

研究动作

把“记忆”写成一段可执行程序，再演化它

每个候选是一个固定接口的 Python 模块，同时规定 Schema（存取的数据格式）、Logic（read / write 后端，可用 SQLite、ChromaDB、LLM 调用）和 Instruction（代理如何抽取、查询与使用记忆的提示常量）。编码代理读执行轨迹与失败样例后打补丁，程序池按验证分数抽样父代。最后拿各任务的最佳程序交叉测试。

机制

程序池 + 反思式代码演化：每轮读失败样例、打补丁、过编译检查、回池

程序池3 个种子起步：向量检索 / LLM 摘要 / 经验学习
softmax 抽父代按静态验证分，τ=0.15；低分程序仍有机会
轮换验证集每轮 5 题，收集读写轨迹与失败样例
编码代理打补丁GPT-5.3-Codex 诊断根因，同改代码与提示
编译 / 运行检查超时、调用超额等违规退回修复，3 次不过即丢弃
静态验证评分32–60 题固定子集（k-means 选点），入池
20 轮后按验证分选最佳
→ 留出测试集只测一次
♜
Schema　dataclass 规定写入与查询字段。LoCoMo 最佳程序 7 个字段，PRBench-Legal 22 个。
♞
Logic　read() / write() 实现。ALFWorld 最佳程序只用 SQLite 并加精确匹配加分；LoCoMo 用 SQLite + ChromaDB 混合打分。
♝
Instruction　抽取、查询、作答提示常量与常驻知识，随代码一起改。

限制 · 这盘棋只下了这些格

  • 迁移棋盘只有 3 个目标任务、每格一个最佳程序，没有给出重复或误差；结论是“这几个程序不可迁移”，不是“任何记忆设计都不可迁移”。
  • 全部实验只用一组模型：GPT-5.4 Mini（任务代理、评委、工具 LLM）+ GPT-5.3-Codex（反思）；作者未测程序对这组模型的依赖程度（附录 J）。
  • 和固定基线的比较不含搜索成本：每个基准演化一次约 $12–90，ALFWorld 约 100 小时墙钟（附录 D.1）；LoCoMo 测试集 100 题，时间与因果类问题仍是 Mem0 / GEPA+VS 更强（Table 4）。
