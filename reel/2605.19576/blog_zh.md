# 库漂移：冻结的 LLM 自己管理技能库——哪些治理开关起作用，消融没有测什么

*Reel 解读：[arXiv 2605.19576v3](https://arxiv.org/abs/2605.19576v3)（HarnessRSI Daily 评分 74，★★★）。代码：[amazon-science/Self-Evolving-Agents-Ratchet](https://github.com/amazon-science/Self-Evolving-Agents-Ratchet)。研讨会论文（FAGEN @ ICML 2026）。*

## 系统改变了自己的什么

论文研究 **Ratchet**：冻结的 LLM（Claude Opus 4.7）自己撰写、检索、整理并淘汰自然语言**技能**，权重不变。作者把一种失效模式命名为**库漂移（library drift）**：技能不断累积却没有基于结果的生命周期管理，检索质量下降、过时技能被注入，智能体停滞甚至低于不用技能时的通过率。

每一轮循环包含五步：在留出任务上做路由（Router 选择一个技能或 NONE：先用 tf-idf 与向量检索各取候选，再由 LLM 把关）；在训练任务上跑同一流程以收集失败样例；由 Critic LLM 给每个失败打上 HELPED / HURT / NEUTRAL / INAPPLICABLE 标签并标注模式；由 Synthesizer 对同一规范化模式下至少 3 个失败组成的簇写出新技能；由 Curator 更新各技能得分并淘汰技能。

## 保留/拒绝规则

信号是每个技能的**贡献分** ĉ(s) =（成功数 − 失败数）/ 试验数，只统计该技能被注入的任务。"修复"由三个治理机制构成：

1. **基于结果的淘汰。** 技能累积至少 N_min = 100 次试验且 ĉ ≤ −0.10 时被淘汰。
2. **活跃数量上限。** 最多 50 个活跃技能；合成会超出上限时，淘汰贡献最低的技能。
3. **元技能写作先验。** Synthesizer 提示词中的一份文档，使新技能风格一致。

## 论文报告的主要结果

MBPP+ hard-100：从 378 题的 MBPP+ 测试划分中，去掉 Claude Opus 4.7 在 5 个基线种子上全部答对的任务，再从余下任务中抽 100 题（60 训练 / 40 评测，固定种子）。求解器只做一次 LLM 调用，无执行反馈、无工具。每次运行 100 轮，结果为 3 个种子的均值 ± 标准差（表 1）。

| | Default（完整治理） |
|---|---|
| 基线（第 0 轮留出集 pass@1） | 0.258 ± 0.047 |
| 后期窗口均值（摘要） | 0.584 |
| 峰值 | 0.658 ± 0.042 |
| 增益 = 末 10 轮均值 − 首 10 轮均值（每次运行内部计算） | +0.328 ± 0.018 |

分种子看，Default 的增益为 +0.303、+0.340、+0.343（表 3）。注意 0.584 − 0.258 = 0.326‡，并不等于 0.328：论文的增益是在每次运行内部计算的。

## 决定收益是否可信的对照实验

所有对照都是论文自身系统的消融；每个条件 3 个种子，评测集为同一固定种子划分中的 40 题（第 6.1 节；表 1、表 3）。

- **A1，不注入技能**（Router 强制选 NONE；论文称 synthesizer、critic、curator 照常运行）：+0.002 ± 0.005。这是论文所称的无技能下限：关闭注入后，循环没有增益。论文内部有一处不一致：表 1 中 A1 的 Critic 调用为 0，却在第 100 轮有 42 个活跃、15 个已淘汰技能，而技能产生于 Critic 标注的失败簇、淘汰又需要注入试验，因此这一下限不如正文所示那样干净。
- **A2，仅检索路由**（去掉 LLM 把关）：+0.077 ± 0.065（分种子 +0.148、+0.095、−0.010）。
- **A3，去掉元技能：** +0.187 ± 0.036，比 Default 低 0.141；论文称元技能是单个最有价值的组件。
- **A4，激进淘汰**（同时改了两个旋钮：N_min 由 100 降到 20，τ 由 0.10 降到 0.0，尽管论文称每个消融只改一个旋钮；论文把损害归因于证据下限，但无法区分二者）：−0.019 ± 0.010（分种子 −0.005、−0.027、−0.025）。技能库塌缩到 2 个活跃技能，路由参与率降到 19%。这是论文中漂移到无技能基线以下的例子，它由过度激进的治理造成，而不是由技能库无限增长造成。
- **A5 去掉规范化 +0.374 ± 0.023，A6 去掉覆盖保护 +0.363 ± 0.033，A8 每 10 轮刷新元技能 +0.372 ± 0.017**（峰值 0.725；墙钟 10.1 小时对 6.5 小时）。三者数值上都高于 Default；论文称 A5/A6 "在 n = 3 时处于 ±2σ 之内"，并得出结论：在此规模上显式去重并非必要。
- **A7，上限 = 100：** +0.317 ± 0.110，分种子 +0.172、+0.340、+0.440。均值相近，波动大得多；论文称上限"主要控制方差而非均值"。
- **成本。** Default 每 100 轮约 14.5k 次 LLM 调用（10k 求解 + 4.3k 评判 + 152 合成），比 A1（10k）多 43%（论文的说法；按其自身的调用分项相加约为 45%‡），墙钟 6.5 小时对 2.3 小时。求解器调用次数相同，多出的是评判与合成调用。

## 增益缺失或证据较薄之处

- **没有任何一行去掉了淘汰或上限。** 表 1 有八个变体，没有"不淘汰"的，没有"不设上限"的，也没有让技能库无限增长的。"膨胀（bloat）"这一子模式被归因于已有系统，并被描述为在 Default 中已被阻止，但并未运行。因此"淘汰和上限是承重部件"这一说法，依据的是 A4（更激进的淘汰有害）、A7（更宽松的上限：均值相近（+0.317 对 +0.328）、方差更大）以及元技能消融 A3。
- **没有外部基线。** 没有运行其他技能库系统（Voyager、ExpeL 等），也没有人工整理的技能；+0.0pp 对 +16.2pp 的 SkillsBench 数字引自另一篇论文。论文也没有报告算力匹配的无技能对照。
- **评测集小，数字有噪声。** 评测只有 40 题（一题 = 0.025‡）。同一流程在第 0 轮的基线在不同条件的均值间从 0.200 到 0.300 不等（分种子为 0.175 到 0.350，表 3），论文将其归因于 40 道评测题的采样噪声。A4 的损害（−0.019）小于一道题。峰值是带噪声各轮的最大值：从不注入技能的 A1，峰值为 0.375，而基线为 0.283。
- **A2 幅度小且噪声大**（+0.077 ± 0.065，有一个种子为负）。A5、A6、A8 三个变体高于 Default，所以 Default 并不是表中得分最高的配方。
- **证明较松。** 命题 1 给出的通过率下界为 E[p0] − 0.35；论文自己也说该界在此规模上较松。另外，论文给出的 Hoeffding ε ≈ 0.20（N_min = 100）与 0.44（N_min = 20），按我们的重新计算对应于取值范围为 1、δ = 10⁻³ 的界，而 ĉ 的取值范围是 [−1, 1]；并且 A4 并未检验该界，尽管论文称其"validates Prop. 1"。
- **范围。** 一个基准、一个模型、阈值凭经验设定；作者认为漂移更突出的多步智能体留待未来工作。论文没有说明 Default 的元技能如何撰写、Default 的各旋钮取值如何选定，除固定的训练/评测划分外也没有描述泄漏检查。

## 我们的解读（Our read）

HarnessRSI 评分 **74**，档位 ★★★，证据等级 **retained**：被保留的产物（受治理的技能库）在留出评测划分上有增益。技能由训练划分的失败样例写成（附录 A），但论文没有说明评测任务的结果是否也进入 Curator 的贡献分，因此这一留出结论没有看上去那么干净。论文报告了留出划分、带分种子表的 3 种子方差、对治理机制的八项消融以及优化器成本；没有报告向其他任务或模型的迁移、与其他技能库系统的对比、完全算力匹配的比较（我们的判断：部分）或泄漏检查。由于只有一个基准、40 道评测题，且缺少"不淘汰 / 不设上限"的对照，对漂移的诊断以及"淘汰与上限必不可少"的结论，更多依赖 A1 与 A4 两个触发实验，而不是一次直接的无上限技能库运行。
