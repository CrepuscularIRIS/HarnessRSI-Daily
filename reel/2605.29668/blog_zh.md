# 智能体自己改写“技能说明书”：只有不破坏已会任务的修改才保留

*GRASP（arXiv 2605.29668）用均衡留出探针为每一次技能编辑把关*

让大模型智能体自我改进，一种常见做法是让它在失败后给自己写笔记，比如“回答前先检查单位”“先查询记录再作答”，下次把这些笔记放进提示词里。这种方法便宜，也不需要更新模型权重，但有一个不易察觉的问题：为修复某个失败任务写下的笔记，可能改变智能体在原本已经做对的任务上的行为，而只增不减的记忆从不检查这一点。

Johannes Moll 等人提出的 GRASP（Gated Regression-Aware Skill Proposer，门控回归感知技能提议器）正是从这个问题出发。智能体仍然自己撰写指导内容，形式是一个小型 Markdown“技能库”（skill library）。不同之处在于，对技能库的每一次修改都要先通过检验：在一组均衡的留出样例上，修好的必须多于弄坏的，才会被保留。

## 系统改变的是什么

GRASP 唯一会改动的是技能库：一份份简短的 Markdown 文档，每份包含“何时使用”说明以及正确与错误示例。底座模型的权重保持不变。技能库最多容纳 10 条学到的技能，每一轮对话最多向提示词注入 3 条相关技能。驱动修改的信号来自智能体自己的轨迹：哪些开发集任务失败了，哪些成功了。

## 编辑如何提出、如何评判

每处理完一批开发集任务，失败轨迹会按失败模式分类、分组。随后由一个撰写模型采样 K 个候选编辑，每个编辑要么新增（ADD）一条技能，要么修改（MODIFY）已有技能，要么删除（REMOVE）一条技能。技能库满额时，除非同一编辑同时删除一条技能，否则不允许新增。

每个候选都被应用到技能库的副本上，并在一个探针集（probe）上测试：一半是此前失败的开发样例，一半是此前成功的开发样例，均取自更早的批次。同一探针也用当前技能库跑一遍，因此比较是因果意义上的，而非绝对分数。候选的得分是修复数减去回归数，两者都相对这次基线运行计算。只有得分为正、且不引入超出基线的回归时，最佳候选才会被应用；若没有候选达标，技能库保持不变。训练结束时，恢复验证集表现最好那一轮的技能库。

## 论文报告的结果

主要测试场景是临床：智能体在 MedAgentBench、MedAgentBench-v2 和 FHIR-AgentBench 上调用 FHIR 电子病历接口。作者使用五个底座模型，并与五种自我改进方法对比（Sequential 与 Batch memory、ExpeL、Evo-MedAgent、SkillX）。测试集与分布外（OOD）划分从不参与训练、检查点选择或超参数选择。结果以均值 ± 标准差报告：gpt-oss-120b 和 DeepSeek 各 5 个随机种子，其余模型各 3 个。

**表1 MedAgentBench，gpt-oss-120b，准确率（%，均值 ± 标准差，5 个种子），根据作者公开的逐种子结果重新计算。**

| **方法**          | **测试集**  | **OOD**     |
|-------------------|-------------|-------------|
| No skills         | 40.6 ± 3.9  | 8.7 ± 3.2   |
| Sequential Memory | 41.2 ± 5.5  | 16.7 ± 15.6 |
| Batch Memory      | 34.4 ± 8.0  | 13.0 ± 8.1  |
| ExpeL             | 49.1 ± 6.3  | 12.0 ± 5.2  |
| SkillX            | 53.1 ± 4.6  | 21.3 ± 3.6  |
| Evo-MedAgent      | 67.8 ± 14.1 | 31.3 ± 21.7 |
| GRASP             | 88.8 ± 5.8  | 56.3 ± 14.5 |

在 MedAgentBench 上使用 gpt-oss-120b 时，GRASP 的测试准确率为 88.8%，不使用技能时为 40.6%，最强基线 Evo-MedAgent 为 67.8%。在 OOD 划分上，两者分别为 56.3% 和 31.3%，但不同种子间波动较大。提升并不均匀：在 FHIR-AgentBench 上，GRASP 为 54.5%，不使用技能为 52.0%，有两个基线略高于 GRASP。在医学以外的四个 AgentBench 环境中（gpt-oss-120b），GRASP 将 ALFWorld 从 23.3% 提升到 51.7%，WebShop 从 20.7% 提升到 41.3%，DBBench 从 65.6% 提升到 70.6%；在开放式的 OS 环境中基本持平（48.6% 到 49.5%）。

## 起作用的是门控，还是写技能本身？

消融实验把两者分开了。如果每次只提出一个编辑并且不经检验直接应用，MedAgentBench 测试准确率为 40.1%，与完全不用技能相当；提出四个候选但仍不设门控，为 63.5%。保留门控、去掉其他部件（失败聚类、回归项、修改与删除能力）的变体都在 80% 到 84% 之间（在另一组 5 个 epoch 的预算下）。这表明，单靠撰写技能解释不了提升，关键在于验证这一步。

另外两点关系到复用。冻结的技能库可以在共享同一工具调用约定的模型和基准之间迁移，接口不一致时效果下降。更强模型写出的技能库能帮助较弱的模型，反过来则不行。门控也有代价：GRASP 每批次的训练期 LLM 调用比最简单的记忆基线更多，几乎全部来自探针验证。

## 我们的解读

HarnessRSI-Daily 给这篇论文的评分是 84/100（★★★），证据等级为 retained（留存的技能库在留出任务上带来提升）。论文报告了留出测试集与 OOD 划分、种子间方差、训练期调用成本，并公开了代码、逐种子结果和学到的技能库。论文对门控的等算力对照只做了一部分；除保持数据划分分离外，没有报告针对探针与测试数据泄漏的专门检验。最大的提升集中在 MedAgentBench，其他基准上提升较小或没有提升。
