# EvoRubric：不仅学习回答，也学习评分清单——有独立评判，但算力账仍不完整

*Reel 解读：[EvoRubric: Self-Evolving Rubric-Driven RL for Open-Ended Generation](https://arxiv.org/abs/2605.29847v2)，arXiv 2605.29847v2。HarnessRSI 评分 63，档位 ★★；记录的证据等级为 improver。未提供代码链接。*

## 系统改变了自己的什么

EvoRubric 同时修改**模型权重**与**给回答提供奖励的评分细则**。一个 Qwen3 策略分别扮演 Reasoner（回答者）与 Rubric Generator（细则生成器）。非权重产物是附属于每个训练问题的记忆池，而不是通用于推理阶段的统一清单。Medical、Writing、Science 分别训练各自的策略，模型规模为 8B 与 14B。

细则包含可观察的正向要求、负向的主动错误约束，以及有正负号的分值；生成器模板允许 −10 到 10 的整数权重。论文的胰岛素储存案例中，新细则关注制剂特定的储存时长、操作方法、设备说明与来源核验。冻结的训练前 Qwen3 一次性写出基础细则；训练中的共享策略读取当前回答、基础细则与历史记忆，提出新增标准。

## 回路与保留/拒绝规则

1. 每题进化记忆池从空开始，基础细则单独保存且不变。
2. 每题采样 8 个回答与 4 组候选细则。
3. **冻结的初始同规模 Qwen3** 检查细则有效性与冗余；同样冻结的 **GPT-OSS-120B** 按通过检查的细则为回答评分。
4. 候选组必须产生非常量的回答分数向量，且与其他候选组的留一共识相关系数超过 **0.2**，才有资格参与。所有合格组都参与当前回答奖励，但**仅共识最高的合格组**可在精确文本去重后向记忆池添加细则。空组或全部被拒绝的组不添加内容。
5. 删除饱和细则：所有回答都满足的正向要求，或所有回答都避开的负向错误。历史细则若分数零方差，则不参与当前历史评分。每题最多保留 10 条进化细则，超出后先进先出淘汰。
6. 两个角色分别标准化优势，再用 GRPO 更新共享权重。下次访问该题时使用新策略和新记忆。

回答者奖励为归一化基础细则得分，加上历史与合格当前组均分（两个记忆池项权重均为 **0.5**），再减长度惩罚。生成器奖励结合有效性、区分力与同伴一致性，并施加数量、长度、权重集中度惩罚（附录 C）。这**不是仅终局结果奖励的 RL**；论文没有这样的 RL 对照。记忆准入也不是留出集性能门控：同伴一致不等于正确。正文与算法 1 的空初始化和准入规则一致。

## 论文报告的主要结果

表 1 对 RL 方法报告**三个训练种子**的均值与标准差；Base 则是**三次回答采样运行**。五项基准的无权宏平均如下。

| 骨干模型 | Static Rubric-RL | External Evolving-RL | EvoRubric | 论文报告的相对最强匹配平均值的分差 |
|---|---:|---:|---:|---:|
| Qwen3-8B | 52.90 | 53.19 | 56.28 | 3.09 |
| Qwen3-14B | 59.05 | 59.07 | 61.13 | 2.06 |

**宏平均没有报告方差或置信区间。** 两种规模下，EvoRubric 在表 1 各基准的均值都最高，但这不等于显著性结论。8B 相对提升最大的是 HealthBench（**14.2%**）与 Creative Writing（**8.4%**）；收益不均匀，但并非仅一个基准有提升。

训练在每个领域分别从 HealthBench、Long-writer-zero、ResearchQA 采样 3,000 题。评测包括 **500 条留出的 HealthBench 样本**、中文 LLMEval-Med、WritingBench、Creative Writing 和留出的 ResearchQA 问题。其他评测样本数与详细划分构造未给出。最终评判器为 **claude-sonnet-4-6**：保留基准原有评价标准，但替换模型评判器。它与 Qwen3 验证器、GPT-OSS 训练评分器属于不同模型家族，降低直接耦合，却不能证明评判偏好不会有利于本方法。论文未报告多评判器稳健性实验。

## 决定收益是否可信的对照

- **显式训练生成器有贡献（表 2，Medical，Qwen3-8B）。** 完整版 HealthBench/LLMEval-Med 为 **45.13 / 53.75**；移除生成器损失后为 **41.58 / 49.93**。该变体仍生成细则，并保留验证、评分、记忆和选择；生成器仍可因共享的回答者权重更新而间接改变。移除区分力反馈为 **38.92 / 51.11**，移除共识为 **40.80 / 50.16**，移除历史记忆为 **42.26 / 52.41**，移除元验证器为 **43.13 / 47.81**。无记忆变体仍使用当前轮细则。这些是 **3 次匹配运行的平均值，没有各变体方差或 CI**，不能据此认定其他领域与两种规模都具有同样效应。
- **各基线获得了什么。** Static 使用冻结基础模型通过少样本提示写出的固定细则；External 使用独立、未优化的同规模生成器。两者与 EvoRubric 共享策略骨干、训练数据与策略侧配置。仅在 Medical 的 Qwen3-8B 上测试的 GPT-4.1 变体读取当前回答与现有细则提出新标准，得分 **42.25 / 52.92**，EvoRubric 为 **45.13 / 53.75**（表 3，3 次运行均值，无 SD/CI）。这是**在本文训练配置内**采用 DR-Tulu 风格生成，而非包含搜索与引用训练的完整 DR-Tulu。论文未逐一列全各 External 基线共享哪些验证器、共识、准入及生成预算设置，因此不能推断它们完全没有防护。论文也未确立端到端算力匹配或可比的奖励模型训练预算。
- **初始化（表 4）。** HealthBench-8B 上，专家细则让 Static 从 **38.89 升至 41.83**；专家初始化 EvoRubric 达到 **44.64**，模型初始化为 **45.13**。论文报告的 **0.49** 分差在此没有方差/CI，不能证明模型编写的先验更优。
- **人工有效性审计不是泄漏审计。** 三位有经验的标注者检查 20 个 Medical 问题。最终 8B 无效细则为 **8/157（5.10%）**，无验证器为 **75/192（39.06%）**；14B 为 **6/139（4.32%）**（表 5）。另一项固定回答比较在 100 条 HealthBench 问题上，以 **72% 对 28%** 偏好 EvoRubric 细则（附录 G，Claude 评判）。这些审计/比较问题属于哪个划分未说明；它们不是已经证明的留出细则迁移测试。
- **划分与调参。** 算法 1 在训练问题上进化记忆池，最终评测包括明确留出的集合。但超参数/默认值由哪个划分选择、检查点如何选择，均未说明；基线调参试验预算也未报告。训练数值本身**有提供**：表 7 给出 4 个 epoch、学习率、批大小、解码设置、采样数和裁剪边界；附录 C 给出共识阈值与惩罚项。最终评判器使用“默认设置”，没有明确数值化的解码参数。通读附录未发现提示重叠或污染审计；不能声称在评测题上进化，但也没有详细泄漏审计支持。
- **算力。** 表 7 列出 **8 × NVIDIA H20**、4 个 epoch、每题 8 个回答与 4 组细则。未报告 EvoRubric 总成本、GPU 小时或墙钟时间。附录 H 仅报告 GPT-4.1 生成器 API 用量，三次运行均值为 **81.20 百万输入 + 2.91 百万输出 token**，合计 **84.11 百万**，约 **每次 USD 185.70**。不含其他基线成本，也不是 EvoRubric 成本对比。训练评分器保持冻结；没有另行训练的基线奖励模型及其可比优化预算记录。

## 增益缺失或较小之处

**LLMEval-Med 的提升较小。** EvoRubric-8B 为 **53.75 ± 0.84**，Static 为 **52.95 ± 0.47**；14B 为 **59.23 ± 0.91** 对 **58.30 ± 0.25**。报告的增益 **0.80 / 0.93** 与 EvoRubric 的种子标准差相近，未给显著性检验。移除验证器后，8B LLMEval-Med 降至 **47.81**，低于 Base **49.25**。

**人工偏好收益集中在简洁与相关性，并非事实质量全面改善。** 50 个 Medical 问题上，以下所有三元组均为逐问题胜/平/负百分比（%），不是题数。相对同规模 External 的总体质量为 **42/30/28**，相对 GPT-4.1 变体为 **48/14/38**。完整性更偏向基线：**20/52/28** 与 **36/18/46**；事实正确性接近：**40/22/38** 与 **42/14/44**；安全性大多平局（表 6）。未报告 CI。

**细则质量仍会漂移。** 有验证器时，8B 无效率仍随 epoch 末快照从 **1.08% 升到 5.10%**，有效多样性从 **89.19% 降到 75.16%**；14B 多样性从 **91.62% 降到 76.26%**（表 9–10）。多样性指标汇总 20 题的计数，仅在每题内部去重，并非跨题去重。冻结验证器降低错误，而非消除错误。
