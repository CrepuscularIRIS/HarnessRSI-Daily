# 重新审视 harness 进化评测：留出集均值持平，但针对当前游戏的适应有效

*Reel 解读：**Rethinking the Evaluation of Harness Evolution for Agents**，[arXiv 2607.12227v4](https://arxiv.org/abs/2607.12227v4)。HarnessRSI Daily 评分 **63**，★★。[代码](https://github.com/rethinking-harness-evolution/code)；我们未运行。*

## 改变什么，以及这篇批评论文实际检验了什么

论文追问：分数提高，究竟来自可复用的 harness 改进，还是仅仅在被评测的任务上花了更多推理和反馈预算？引言批评了 **Meta-Harness、Agentic Harness Engineering（AHE）和 AEVO** 的评测方式，但**没有逐一独立复现这些系统**。Terminal-Bench 实验采用的是**关闭外部 explore agent 的 AHE**，保留基于反馈的编辑循环。该 explore agent 原本会从外部检索面向基准的 harness；关闭它，隔离的是较窄的机制，不是完整原版 AHE。

四种方法均不更新模型权重。**Parallel Sampling（并行采样）**在固定 harness 下独立尝试；**Sequential Refinement（顺序修正）**根据上一条轨迹的摘要修改解法，harness 仍固定；**Harness Evolution** 跨一批任务编辑共享 harness；**Harness Scaling** 则为每个评测任务单独编辑 harness。可修改的产物包括提示词、工具、中间件和记忆；信号来自执行轨迹，有正确性结果时也利用该结果。

## 迭代循环与保留／选择规则

共享 Harness Evolution 的元智能体读取累积的 harness／轨迹记录，提出下一个 harness。没有单元测试时使用最后一个 harness；有测试时按聚合结果选择最优 harness，留出实验明确在验证任务上选择。任务专用的 Harness Scaling 根据任务、上一个 harness 和轨迹更新，有结果时还读取结果；没有测试时返回最后一条轨迹，有测试时可以返回成功的尝试。

基线同样获得相应反馈：Parallel Sampling 无测试时由模型自选，有测试时用测试作 oracle 选择；Sequential Refinement 读取上一条轨迹摘要，有测试时还读取其结果。二者不能修改 harness。这是在比较**额外搜索花在哪里**，而不是把相同的 harness 更新机制授予所有基线。

## 主要结果：保留指标和测量方式

在全部 **89 道 Terminal-Bench 2.1 任务**上，所有方法从相同的、仅有 bash 工具的最小 harness 出发。模型为 **Claude Opus 4.6、GPT-5.4、GPT-5.4 mini**。默认预算 **K = 5**，每个 harness 在每个任务上采样一条轨迹；第 4 节结果为两次独立运行的均值，表中没有标准差或置信区间。

| 方法 | 无单元测试：平均 pass@1（%），表 1 | 有单元测试：平均 pass@1 / pass@5（%），表 2 |
|---|---:|---:|
| 初始 harness 直接采样 | 68.2 | 67.6 / — |
| Parallel Sampling | 72.3 | 82.0 / 82.0 |
| Sequential Refinement | 69.3 | 76.9 / 87.1 |
| Harness Evolution | 67.4 | 69.7 / 79.0 |
| Harness Scaling | 71.8 | 75.5 / 85.6 |

附录 A 把 pass@1 定义为**所有轨迹的平均奖励**，pass@5 为至少一次成功的任务比例。因此不能把每个 pass@1 单元格都理解为 oracle 选出的最终答案成功率。不同表中的初始对照值并不相同，上述比较只在各表内部进行。

更直接检验可复用改进的是**表 3**：在 **45 道训练任务**上进化，在 **10 道验证任务**上选择 harness，最后在 **34 道不重叠测试任务**上测量。初始和进化后的平均 **pass@1 均为 63.2%**。各模型初始 → 进化结果分别为：Claude Opus 4.6 **63.3 → 64.5**，GPT-5.4 **72.1 → 72.1**，GPT-5.4 mini **54.4 → 53.0**（单位均为 %）。这支持该实现和该划分下泛化有限的结论；论文没有提供显著性检验或区间。

正面结果针对的是另一目标：**当前任务内的适应**，而非把共享产物迁移到未见游戏。

- **全部 25 个公开 ARC-AGI-3 游戏、2,000 次环境动作（表 4）：**固定 **VISTA*** → 仅记忆进化 **VISTA** → **完整 harness**，在 **Claude Opus 4.8** 上为 **43.3 → 59.3 → 77.5 RHAE**，在 **GPT-5.6 Terra** 上为 **21.1 → 25.9 → 38.2 RHAE**。论文给出的相对 VISTA* 提升分别为 **79.0%** 和 **81.0%**。RHAE 同时衡量动作效率与完成情况，不是胜率百分数。作为参考，普通 Claude Code 和 Codex 分别平均 **44.3** 和 **4.6 RHAE**。
- **EdgeBench 的五道 Interactive Games & Simulators 编写游戏 bot 任务，而非整个基准（表 5）：**固定 harness 的 Sequential Refinement → Harness Scaling，在 **Claude Opus 4.8** 上为 **48.3 → 54.7**，在 **GPT-5.4** 上为 **45.9 → 49.8**，均为 **0–100 分量表**。论文报告相对提升 **13.3%** 和 **8.5%**。这些是两次运行中 **12 小时窗口内最高分**的均值，不是新留出测试集上的分数。

## 决定结论边界的对照

- **预算匹配因场景而异。**Terminal-Bench 匹配轨迹预算和反馈，但附录 A 明确排除了 harness 编辑成本，只称其较小而未测量。ARC 匹配环境动作数；内部推理和只读检查不计入该协议，因此不是 token／美元匹配。EdgeBench 的墙钟预算包含摘要、编辑以及智能体暂停期间的空闲时间。
- **ARC 对照有信息量，但捆绑了多个变化。**VISTA* 保留视觉观察、检查工具和上下文重置续跑，关闭 GUIDE.md、WORKING.md；VISTA 恢复可进化记忆，完整 harness 再开放技能、工具和 hooks。这不是逐项隔离新增组件的因果消融，也没有一个拥有相同可写接口、但采用其他更新规则的基线。附录 B 的产物操作计数测量的是使用量，不是价值。
- **更大预算的例外（附录 A.3）。**在 **K = 10**、有测试、且**仅 Claude Opus 4.6** 的表 8 中，Harness Scaling 为 **90.5% pass@1 / 94.4% pass@10**，Sequential Refinement 为 **89.6% / 93.1%**。作者称差距在运行间方差内，但未列出数值方差。共享 Harness Evolution 仍为 **73.6% / 86.5%**；表 9 的留出测试为 **63.0%**，初始为 **63.3%**。负面结论不等于任务专用 scaling 从不取得最高单元格。
- **产物选择与超参数调优不是一回事。**Terminal 配置固定自参考运行快照（表 6）；验证集选择最终 harness，而非有记录的超参数搜索。ARC 的模型／推理配置为保留可解、但未饱和的任务空间而选，未指明独立调参划分。Edge 更新默认每三次提交或 120 分钟触发。没有报告单独的基线调参／搜索预算。尚未列出的数值设置包括 Terminal 采样温度、数据划分种子／任务分配，以及 ARC 内部 token 上限；这些缺失不能作为测试集调参的证据。
- **重复与失败处理。**Terminal 第 4 节及其更大预算附录均报告两次独立运行，Edge 表 5 也明确如此；ARC 未说明运行次数。这些比较没有标准差、置信区间或跨条件种子配对协议。Terminal 的基础设施故障计为失败，而非剔除。
- **游戏反馈不等于未见任务迁移。**Edge 显式提交返回 judge 反馈，定期宿主快照的结果不向智能体展示；最高分统计同时包含两者。harness 改动通过验证才安装，否则保留原版本，但验证判据未说明。论文没有报告留出游戏或跨模型产物迁移实验。

## 哪里没有收益、收益不均，或尚不能确立

Terminal 留出均值持平是核心负面结果。没有测试时，共享进化尤其损害 **GPT-5.4：75.3 → 69.7%**（表 1）。但任务专用 scaling 在 **Claude Opus 4.6** 上最高，为 **76.0%**，并行采样为 **74.7%**；无测试结论本身也因模型而异。

ARC 收益不均，并非每个游戏都改善：**GPT-5.6 Terra** 的完整 harness 在 **tr87** 达到 **100 RHAE**，VISTA* 为 **11.8**；但 **sk48** 为 **0.0**，VISTA* 为 **0.8**，**vc33** 为 **0.0**，VISTA* 为 **0.6**。**Claude Opus 4.8** 在 **tn36** 上从 VISTA* **18.5** 降到完整 harness **3.6 RHAE**。不能把较大的聚合提升理解为每个游戏都均匀提高。

Edge 同样依赖任务与模型：**Claude Opus 4.8** 的 NetHack **44.3 → 61.3**，但 Wesnoth **88.0 → 86.0**；**GPT-5.4** 的 OpenRCT2 **36.2 → 50.0**，但 NetHack **50.4 → 49.0**、OpenTTD **51.6 → 50.5**（表 5，均为相同 0–100 量表上的分数）。缺少不确定性估计，无法确立哪些较小的任务差异可靠。

## 我们的解读（Our read）

HarnessRSI 评分 **63**，档位 **★★**，证据等级 **task**（最新判断批次 b12）。论文报告了匹配轨迹预算的比较、明确的留出测试、仅记忆与完整 harness 对照，以及正负两面的结果。游戏正面结果说明同任务适应有效，而共享 harness 的留出测试持平。它没有确立更强的改进器、广泛迁移、严格总算力等价，或小差异的统计确定性。

我们的榜单也应接受这套批评：预算匹配必须注明资源和计入的开销；留出证据要区分“做了评测”与“取得可迁移的正收益”；留存产物消融不能悄悄替代接口等权的基线；两次运行均值不等于报告了方差。评分是本榜单证据量表的汇总，不是对论文批评的反驳，也不是对 harness 进化普遍效用的评级。SOURCE.md 记录这些限定，不改动判断文件。
