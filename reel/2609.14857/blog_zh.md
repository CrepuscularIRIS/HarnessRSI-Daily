# ModularRSI：把 harness 拆成五个模块、依据对比轨迹分别进化——在 TerminalBench 2.0 上有报告的增益，但每种设置只做了一次进化

*Reel 解读：[arXiv 2609.14857v2](https://arxiv.org/abs/2609.14857v2)（HarnessRSI Daily 评分 72，★★★）。代码：[IQuestLab/ModularRSI](https://github.com/IQuestLab/ModularRSI)。*

## 系统改变了自己的什么

ModularRSI 改写的是 **CLI 智能体 harness 的代码**（Harbor 框架中的 Terminus-2）。harness 被拆成五个模块——Agent Loop、Observation Management、Tool Use、Context Management、Task Completion Detection——每个模块从同一个初始 harness 出发独立进化，彼此不共享中间修改。沙箱初始化、并行执行和 LLM 通信不在进化范围内。模型权重不变，被保留的是 harness 代码。被进化的智能体（DeepSeek-V4-Flash-Preview）同时也是分析轨迹、写补丁的 Code-Modify Agent。

## 信号与保留/拒绝规则

- **信号。** 每个进化任务跑 3 次 rollout，奖励为 0/1。部分成功、部分失败的任务属于*对比组*：智能体比较同一任务的成功与失败轨迹。全部失败的任务，若轨迹记忆里有更早的成功则与之配对；全部成功的任务则用来找出浪费的步骤。
- **选择改什么。** 相近的诊断合并为候选修改，候选的票数等于支持它的不同任务数，取前 K = 10 个实施，因此反复出现的问题优先于一次性的失败。过往修改记录在进化历史中，用来避免自相矛盾的改动。
- **保留/拒绝。** 每个函数更新必须依次通过三道门，否则按记录的 diff 回滚：静态程序检查；同一智能体对 diff 做审查，查找任务特定的取巧写法；在当前批次随机抽取两个任务执行检查。
- **进程安排。** 每个模块进化 3 轮，然后用一轮跨模块整合去除重复或冲突的机制（合计 16 轮）。此后函数库冻结。评测时由基于 LLM 的 composer 挑选与任务相关的函数子集。
- **进化数据。** 作者从外部来源（GitHub、Hugging Face、Kaggle、Linux 内核文档）构建了 2,000 个可执行任务，经人工审核，并用 LLM 与基准做相似度筛查；从中取出两个相互独立的进化集——120 个 TB 相关任务和 120 个 SWE 相关任务，各自得到一个进化后的 harness。

## 论文报告的主要结果

DeepSeek-V4-Flash-Preview，harness 在与基准不相交的数据上进化，在 TerminalBench 2.0（89 个任务）和 SWE-Bench-Verified（500 个任务）上评测，每个任务 3 次 rollout（表 1）。

| 评测基准 | 未进化 | 在另一类任务上进化 | 在同类任务上进化 |
|---|---|---|---|
| TerminalBench 2.0 准确率 | 47.57 | 49.44（SWE 相关） | 52.43（TB 相关） |
| TerminalBench 2.0 Pass^3 | 30.34 | 30.34 | 35.96 |
| SWE-Bench-Verified 准确率 | 73.40 | 75.80（TB 相关） | 76.40（SWE 相关） |

准确率变化的任务级配对 bootstrap 区间（表 9）：TerminalBench 2.0 为 +4.86 [3.37, 9.36] 与 +1.87 [1.49, 5.24]；SWE-Bench-Verified 为 +2.40 [0.73, 3.33] 与 +3.00 [1.06, 4.26]。同一个 TB 相关 harness 原样用于其他推理模型时，在 TerminalBench 2.0 上 GLM-5.2 由 59.55 升至 61.80，MiniMax-2.5 由 41.57 升至 44.94（表 2）。换用其他进化模型重跑整个流程：DeepSeek-V4-Flash-0731 由 61.79 升至 67.42，Qwen3.8-Max 由 61.05 升至 64.79（表 8，无区间）。

## 决定收益是否可信的对照实验

- **模块化与不受限进化，轮数匹配（表 3）。** 联合全模块进化与非模块化的整体 harness 进化各跑 16 轮，与 ModularRSI 的总轮数一致，每任务同为 3 次 rollout。在准确率上两者都低于未进化 harness：44.19 与 46.44，而未进化为 47.57，ModularRSI 为 52.43（表 9：−3.38 [−3.74, −1.50]、−1.13 [−2.24, −0.74] 与 +4.86 [3.37, 9.36]）。这一比较只对准确率成立：两者的 Pass^3 也低于未进化（24.72 对 30.34），但 Pass@3 都高于未进化（61.80 与 64.04，对 58.43），非模块化进化的步数也更少（29.03 对 34.70）。ModularRSI 的 Pass@3 只比非模块化高 1.13‡。这里的“预算”指轮数；进化所用的 token、费用或墙钟时间论文没有报告。
- **其他优化器（表 6）。** Meta-Harness 与 AHE 由作者在 Harbor 中适配并复现，从同一个 Terminus-2 出发，在同样的 120 个 TB 相关任务上、用同一模型进化 16 轮：准确率为 49.44 与 49.81，ModularRSI 为 52.43。它们相对未进化 harness 的准确率增益为 +1.87 [-0.07, 2.24] 与 +2.24 [-0.03, 2.62]，两个区间都包含 0；ModularRSI 自己的区间 +4.86 [3.37, 9.36] 高于二者。论文没有对 ModularRSI 与它们做直接检验。TerminalBench 2.0 共 267 次 rollout（89 个任务 × 3），与 AHE 的差距是 7‡ 次成功 rollout（140‡ 对 133‡）。基线的调参预算和方差均未报告。论文也没有说明 Meta-Harness 与 AHE 是否获得了 ModularRSI 所用的函数库管理（函数合并与测试时的任务感知 composer）以及验证门。这一点很重要：表 5 中去掉函数库管理的消融得分为 49.81，数值上与 AHE 相同（见下）。论文称在这一比较中对“所有方法”关闭了网络搜索；论文没有说明表 1 的运行是否同样关闭，尽管 ModularRSI 的 52.43 在两张表中是同一个数字。
- **消融（表 4、表 5）。** 去掉对比轨迹分析得 50.56，去掉函数库管理（合并加任务感知 composer）得 49.81，去掉验证门得 48.31（完整版 52.43，未进化 47.57）。因此函数库管理的消融所对应的 2.62‡ 个点，正好等于 ModularRSI 相对 AHE 的差距。composer 在测试时是一次 LLM 调用；论文没有说明它在 GLM-5.2 或 MiniMax-2.5 上用哪个模型，也没有给出成本。五个单模块 harness 的准确率都已高于未进化版本（49.44 至 50.56），整合后达到 52.43。这些都是单次运行，没有区间。
- **迁移。** 在另一类任务上进化仍有收益（见上），进化出的 harness 对另外两个推理模型也有帮助。跨模型实验中的 harness 只进化了一次，用的是 DeepSeek-V4-Flash-Preview 与 TB 相关数据集，且只测试了另外两个推理模型。
- **泄漏。** 论文的防护措施是构造层面的：只用类别级的基准描述作检索指引、对每个任务做可执行验证、人工审核、与基准的 LLM 相似度筛查，以及在与其他方法的比较中关闭网络搜索。“与基准不相交”是作者的说法；筛查没有量化（没有重叠统计、阈值或被剔除任务数），也没有单独的污染检测。

## 增益缺失或较小之处

- **其他优化器已很接近。** AHE 与 Meta-Harness 已分别带来 +2.24 与 +1.87 个准确率点，区间包含 0；与 ModularRSI 之间剩下的差距是 2.62‡ 与 2.99‡ 个点（比 AHE 多 7‡ 次成功 rollout），基准只有 89 个任务，既没有直接检验，也存在上述 composer 与验证门是否同样提供的疑问。
- **Pass^3 与步数并非总是改善。** SWE 相关 harness 把 TerminalBench 2.0 准确率提高到 49.44，但 Pass^3 仍为 30.34。每次 rollout 的平均步数，ModularRSI 为 35.57，未进化为 34.70（表 3）；单个模块的影响方向不一（Observation Management 为 22.50，Tool Use 为 41.28，表 4）。
- **每种设置只进化一次。** 区间只对任务重采样（每个任务的三次运行取平均并保持在一起，附录 G），对象是固定的 harness；它们不反映不同进化运行之间的波动，论文也没有报告重复进化。区间的不对称性很强，按论文原样列出（例如 SWE 相关 harness 的 +1.87 [1.49, 5.24]，对比 Meta-Harness 的 +1.87 [-0.07, 2.24]）。
- **进化曲线。** 图 6 画的是 TerminalBench 2.0 准确率随代数的变化，一直到第 22 代，而论文其余部分都按 16 轮计（未解释）。正文称提升“基本单调”；曲线并非严格单调（第 12 代附近有回落），末端为 52.2‡，表中为 52.43。
- **SWE-Bench-Verified 的头条数字看起来是两个变体中较好的一个。** 表 10 中，中等难度的 SWE 相关进化集为 76.40，难易两端集中的进化集为 74.20（单次运行；图 5 只覆盖第 0 至 2 轮）。76.40 同时也是表 1 的头条数字；论文没有说明头条 harness 是否从这两者中选出。
- **规模实验每个点只有一次运行。** 单轮、600 个进化任务时 TerminalBench 2.0 达到 57.3‡（未进化 47.6‡；图 2 只标出这两个点）。
- **案例分析。** 作者自己指出，案例分析的运行"包含其他更新，因此这些比较不能分离单个改动的作用"。

## 我们的解读（Our read）

HarnessRSI 评分 **72**，档位 ★★★，证据等级 **retained**：进化出的 harness 在未用于进化的基准上有效，包括另一类任务和其他推理模型。论文报告了与基准不相交的进化数据、双向任务迁移、跨模型迁移、与联合/非模块化进化以及 Meta-Harness、AHE 在轮数匹配下的比较、消融和任务级 bootstrap 区间。论文没有报告不同进化运行之间的方差、进化的算力或 token 成本（含测试时的 composer）、消融以及 ModularRSI 对其他优化器的区间估计，没有说明基线是否获得了同样的函数库管理与验证门，也没有相似度筛查之外的量化污染检测。我们的判定文件把方差和 improver 级比较标为 unclear；完整论文中与其他优化器的轮数匹配比较可能支持后者（见 SOURCE.md）。
