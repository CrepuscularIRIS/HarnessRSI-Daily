离线遥测 · 技能准入 · 日志回放带

日志没法重放，也能给技能库把关

TeleTune 不问“改完技能任务能否成功”，而问“改完之后，代理能否预测出用户当时真正点的那一步”——只有在留出日志上预测更准的编辑才被收下。
TeleTune
UNC Chapel Hill / Microsoft
arXiv 2610.05437v2
主实验代理 GPT-5.4；测试 WorkArena L1/L2 与 Online-Mind2Web
问题

用户遥测里藏着操作经验，但现成的技能学习方法都用不上

没有目标日志只记点了什么，不记为什么点。
不能重放不能请用户为了验证新技能把任务再做一遍，环境也未必可复位。
任务交织一段日志里可能夹着几件事，没有边界标记。

执行式的技能修订（如 SkillOpt）每次编辑都靠在线跑任务验证——这一步在遥测场景里正好缺失。

研究动作

把“预测已记录动作”当作准入信号

先由同一骨干从整段轨迹推一个目标；再让代理带着当前技能库，逐步预测日志里的下一个动作，每步无论对错都把真实记录的动作接进历史（teacher forcing）。逐轨迹的预测准确率称为 skill-guided progress Q。编辑只有让留出 dev 日志上的平均 Q 严格上升才被接受；最终库冻结后，才拿去在线环境做新任务。

任务交织：人工打断训练日志

74.8 对 Random-k 75.9

每 2–5 个动作以概率 q 插入另一任务的片段。q=1.0 时 L1 上 TeleTune 略低于 Random-k，AWM 跌到 49.3；L2 上 TeleTune 62.1 最高。q>0 的格子都是单种子（Table 7）。

离线优化的代价

174M tokens

L1 一次优化共 173.84M token，预测器打分占 99% 以上。若改用在线验证同样 32 个候选，作者估算约 2.8B，即 16 倍；L2 约 75 倍、Mind2Web 约 5 倍——这是反事实估算，不是实测（Table 4）。

推理时更贵

636.9K 对 343–386K

L1 每回合输入 token：库有 56 条技能、约 6.4K token，每步都重发。给 Random-k 加到 30 条示范（504.2K）成功率反而 63.7（§4.2、Table 8）。

限制

  • 没有用真实用户遥测：WorkArena 训练轨迹是 oracle 专家轨迹，Mind2Web 是标注者录制，“交织”是人工构造；WorkArena 的测试题是训练模板的其他种子，不是新任务类型。
  • “离线 Q 与在线成功率同向”只来自 L1 一次运行的 4 个检查点；准入门保证的是“预测更像记录”，不是任务成功的证明。推断目标由整段轨迹写成，可能带入后续信息（作者用提示词限制）。
  • 5–75 倍节省为估算；推理阶段输入 token 比基线多约 65–85%；L2 与 Mistral-3.5 上的优势很小或没有。
