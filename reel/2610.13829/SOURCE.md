## ‡ numbers (computed by us)
Four numbers (the endpoints of two intervals): [-0.40‡, 0.16‡] and [-0.23‡, 0.03‡] are our recomputed two-sided 95% Student-t intervals (n = 5, t = 2.776) for the related-minus-no-prior change in TSR, from the per-seed values in Table D3 (p25): wooden tool changes 0.000, -0.200, -0.400, 0.200, -0.200 (mean -0.120, SD 0.228 gives [-0.403, 0.163]); stone tool changes 0.000, -0.125, -0.125, 0.000, -0.250 (mean -0.100, SD 0.105 gives [-0.230, 0.030]). The paper gives no interval for this change (Table 4 intervals are for GATG only). Every other decimal number in the blogs occurs in the paper text. The integer counts shown in the poster (e.g. "about 1 of 8 stages" for stone-tool TSR 0.150, which is 1.2 stages) are our reading of TSR granularity: the per-seed no-prior stone-tool TSR values in Table D3 are 0.125 (four seeds) and 0.250 (one seed), i.e. one stage of eight for most seeds.

## Notes
- "Reference method" = the JARVIS-1 online extension (Table E1: "the headline reference study ... uses only the JARVIS-1 online extension"). The planner model used in the paired runs is not stated per condition; Table E2 lists gpt-5.4 / gpt-5.6-sol for the standard and relay configurations. We describe the controller only as "a released low-level controller".
- "The paper describes no filter on which records are written" is our reading of Appendix E.2 / G.2 (memory keeps the latest 256 records, written atomically; read-write in source, read-only in target). The paper does not describe any filter on writes.
- Table 5 passed counts: the unrelated wood-species row lists passed=6 and the unrelated stone-tool row passed=1, both with Source TSR 0.000±0.000. Termination counts also exceed episode counts in some rows (episodes are per-seed means over five seeds: related wooden tool 5.00 x 5 = 25 episodes versus 5+12+20 = 37 terminations; related stone tool 8.20 x 5 = 41 versus 5+21+36 = 62), so "passed" looks stage-level. The blogs hedge "34 of 41 passed records" and quote "related is the only condition with nonzero source TSR" as the paper's statement. Earlier note, kept: the unrelated wood-species source row lists passed=6 while its Source TSR is 0.000±0.000 (related: passed=1, Source TSR 0.100). The sums are consistent with the text (34 related + 6 + 1 = 41 passed records). We report it and do not interpret it.
- Table 2 versus appendix: Table 2 lists five planner variants per family (JARVIS-1, Optimus-1), while Section 4.2 / Table F8 / F9 speak of nine direct configurations with one planner (gpt-5.6-sol). We quote Table 2 values as printed.
- Figure 2 labels WGP "World Goal Progress"; the text (Sec. 3.3, App. C.4) says weighted graph progress. Table F10: 0 of 2, 1 and 1 reports that reached the crafting-table stage passed it (STEVE-1, JARVIS-1, Optimus-1 controllers); its 57 reports per configuration cover all 19 chains (19 x 3 seeds), Table 2 only the 12 primary chains. The direct matrix (Fig. 3a / Table F10) is not the paired-probe evidence; the paired stone-tool granularity comes from Table D3.
- Related versus controls on TSR (Table 3): above unrelated in all three probes (0.400/0.200, 0.200/0.160, 0.050/0.025), below shuffled in all three (0.400/0.500, 0.200/0.240, 0.050/0.075). Related planner calls exceed both controls on the wooden and stone probes only (wood species 4.40 vs 5.80 and 4.00).
- Held-out wording: the target world is reset, but source and target use the same public world seed 31, spawn and resource layout (Sec. D.4, A.3).
- Direct-matrix reports: 513 planned units, 505 valid, so some cells average two seeds (Table F9); Table 2 reports no SDs.
- Stone-tool "VMP 0.200 vs 0.533" and the quoted related-minus-no-prior values are from Table 3 and Table 4 as printed (stone WGP change printed as -0.062 although 0.021 - 0.082 = -0.061 from the rounded Table 3 values; rounding).
- Quote used in the blogs: the paper's phrase "should be read against its low execution floor" (Section 4.6, p9).

## Judgment notes
No change to our judgment (batch 2026-10-19-a): budget_matched partial (environment steps matched, planner calls differ), optimizer_cost partial, improver_comparison unclear (one reference method), leakage_guard untested, variance yes (five seeds with 95% intervals), evidence level task (no retained artifact helped). The full paper is consistent with these. Two remarks, no correction needed: (1) the paper is an audit benchmark whose own result for the tested method is a null transfer effect, so the 74 reflects audit rigor, not a measured gain; (2) source and target runs share the public world seed 31 by design, and the stored artifact includes a visible-state summary (Table G1), while the paper states that no source resources, positions, world edits, route information or success markers enter the target (Section 3.1); the paper reports no separate leakage test beyond this protocol design and SHA-256 artifact fingerprints (D.4).
