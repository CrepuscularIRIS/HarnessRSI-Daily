# EvolvingBrain：冻结的多模态智能体自建技能库——相对无技能智能体有提升，但论文未报告方差

*Reel 解读：[arXiv 2610.20786v1](https://arxiv.org/abs/2610.20786v1)（HarnessRSI Daily 评分 68，★★）。作者：Runxuan Liu、Jingqi Shi、Baoxin Wang、Honghong Zhao、Haoyuan Xu、Yueqing Sun、Jiafeng Liang、Tao He、Dayong Wu、Qi Gu、Shijin Wang、Ming Liu、Bing Qin（哈尔滨工业大学、科大讯飞、美团、鹏城实验室）。代码：论文称"代码见补充材料，将在最终版公开"（原文为英文），目前没有公开链接。*

## 系统改变了自己的什么

多模态智能体（Qwen3.8-27B、Kimi-K3 或 GPT-5.6-Sol）本身保持冻结。被改变的是一个外部的、针对具体模型的 **Skill Brain**：Domain、Plan、Action、Trap 四类技能，加上连接它们的图。它离线构建，来源是训练轨迹（第 2.2.1 节称每个冻结模型自己采集；附录 A.1 称在 VAB-Minecraft 上用于技能构建的是“已发布的训练轨迹”，覆盖 90 个不同任务目标，论文没有调和这两种说法）：

1. 采集训练轨迹（按第 2.2.1 节，由冻结模型自己采集），成功和失败的都保留（成功与否来自环境标志）。
2. 由 LLM 提取**程序性模式**（哪些做法推进任务）和**问题性模式**（哪些做法阻碍任务；对多模态原因，会检查相关轮次的图像）。
3. 问题性模式变成 **Trap Skill**：只有机制、根因和修复步骤全部匹配时才复用，否则新建。随后模型带着这些 Trap Skill **从初始状态重试同一任务**；问题持续则修订技能，出现新问题则再迭代，直到任务成功、重试预算用完或不再有可处理的根因。技能进化最多三轮反馈迭代。
4. **保留规则：**只有任务成功、已知问题不再复现且没有发现新问题的轨迹才被接受；否则问题回到重试循环。
5. 被接受的轨迹提炼为 Plan Skill 和 Action Skill（均与现有库比较后复用、更新或新建）。Domain Skill 随后由 Plan、Action、Trap 三类技能推导出来，去除实例细节，四类技能再连成一张图。

测试时技能库冻结。仅含文本的**结构化抽象记忆**（进展、阻碍、无效尝试、重试条件）驱动一个门控，每轮在 none / reuse / retrieve 中选择；检索到的技能（Action 与 Trap 先在当前 Plan Skill 的图邻居中找，不足再全局找）被融合成临时的 Active Guidance，不会写回技能库。

## 论文报告的主要结果

成功率，测试集，"三次运行的平均"（表 2）。VAB = VAB-Minecraft；DW = DiscoveryWorld 域内测试集。

| 骨干模型 | Direct VAB | MMSkills VAB | EvolvingBrain VAB | Direct DW | EvolvingBrain DW |
|---|---|---|---|---|---|
| Qwen3.8-27B | 57.67 | 69.84 | 73.02 | 50.00 | 58.02 |
| Kimi-K3 | 69.84 | 70.37 | 79.37 | 63.58 | 74.07 |
| GPT-5.6-Sol | 68.78 | 70.10 | 78.83 | 61.72 | 68.52 |

三个骨干的推理设置不同（Qwen3.8-27B 与 Kimi-K3 为 xhigh，GPT-5.6-Sol 为 high）。三个骨干平均，论文报告相对直接智能体在 VAB-Minecraft 上提升 11.64 个百分点，在 DiscoveryWorld 上提升 8.44 个百分点；在 VAB-Minecraft 上比 MMSkills 高 6.97 个百分点。按骨干看，相对 Direct 的提升从 6.80‡ 个百分点（GPT-5.6-Sol，DiscoveryWorld）到 15.35‡ 个百分点（Qwen3.8-27B，VAB-Minecraft）。Direct 智能体使用相同的接口、推理设置和交互预算（VAB-Minecraft 为 60 轮；DiscoveryWorld 的 Easy 与 Normal 任务 100 步，Challenge 任务 200 步），只是没有技能。

## 决定收益是否可信的对照实验

- **Trap Skill 检索消融（表 4）。**在测试时关闭 Trap Skill 检索（保留 Domain、Plan、Action，检索机制相同；技能库构建时仍使用 Trap 驱动的重试，所以这并未隔离整个 Trap Skill 机制），VAB / DW 成功率为：Qwen 70.90 / 55.02，Kimi 75.27 / 69.77，GPT 74.58 / 65.72；完整系统为 73.02 / 58.02、79.37 / 74.07、78.83 / 68.52。论文称 Trap Skill 检索平均再带来 3.49（VAB）和 3.37（DW）个百分点。均为单个数值，无标准差。
- **反馈迭代次数（表 6）。**只做一轮时为 68.68 / 54.63（Qwen）、75.29 / 69.44（Kimi）、75.57 / 65.74（GPT）；三轮迭代平均再提高 3.89（VAB）和 3.60（DW）个百分点。
- **检索粒度（表 5，仅 Qwen 与 Kimi）。**相对自适应检索，粗粒度（仅 Domain 层）使 Qwen 损失 6.64 / 4.32 个百分点，细粒度（Plan 与 Action 层）使 Kimi 损失 5.19 / 5.55 个百分点。自适应只比较好的固定深度高 0.96‡ 和 0.61‡ 个百分点（Qwen）、1.16‡ 和 1.23‡ 个百分点（Kimi）。
- **留出主题（表 7，第 3.4 节）。**技能库只用 DiscoveryWorld 的六个训练主题构建，原样在两个留出主题的全部 30 个任务上评测；未使用任何域外轨迹。成功率 Direct → EvolvingBrain：Qwen 36.67 → 46.67，Kimi 48.89 → 60.00，GPT 46.67 → 56.67（+10.00、+11.11、+10.00，平均 +10.37）。从域内到域外的下降，EvolvingBrain 为 12.42，Direct 为 14.36；这 1.94‡ 个百分点的差距小于每次运行一个任务（30 个任务中的 3.33‡ 个百分点），没有标准差，且比较的是不同的任务集（域内测试集对 30 个留出任务），我们视其为噪声范围内。域内测试集与训练集共享主题（和难度），只是变体不同（0–2 训练，3–4 测试）。
- **对比对象。**MMSkills 只在 VAB-Minecraft 上评测，用的是其公开发布的技能；论文没有重建其技能生成流程，也没法在 DiscoveryWorld 上运行。MMSkills 在 Qwen 上提升 12.17 个百分点，在 Kimi 与 GPT 上只提升 0.53 和 1.32；EvolvingBrain 在这两者上提升 9.53 和 10.05。

## 增益缺失、较小或未被验证之处

- **Qwen 上相对 MMSkills 只高 3.18‡ 个百分点**（73.02 对 69.84）；GPT-5.6-Sol 上 MMSkills 的平均得分（0.7741）低于 Direct（0.7869）。MMSkills 是唯一的技能库基线，且未在 DiscoveryWorld 上运行；论文没有与其他自进化或反思类基线比较。
- **没有方差。**只有表 2 和表 4 的标题写明“三次运行平均”（表 5、6、7 没有说明运行次数），所有表都没有标准差或置信区间，论文也没有说明三次运行变化的是什么（重复评测，还是重新进化技能库）。例如自适应与最佳固定深度之间 0.61‡–1.23‡ 个百分点的差距，无法对照噪声判断。
- **留出集很小。**域外测试只有两个主题、30 个任务；10.00 个百分点约相当于每次运行 30 个任务中的 3 个‡。为何选这两个主题，论文没有解释。
- **测试集规模对不上。**附录 A.1 写 VAB-Minecraft 有 116 个官方测试任务，表 3 写 DiscoveryWorld 域内测试有 36 个实例，但表 2 的成功率不落在这些分母上（例如 73.02 = 138/189，58.02 = 94/162‡，为我们的推算；GPT 上 MMSkills 的 70.10 也不在 1/189 的网格上；留出集的数值则符合 1/90 网格）。表 4–6 中还有若干数值（75.27、74.58、66.38、72.06、68.68、54.63）既不符合 1/189 也不符合 1/162 的网格。论文没有解释差异。我们采用表中数值。
- **没有报告成本。**既没有构建技能库的成本或时间，也没有每轮额外 LLM 调用（记忆更新、门控、检索、融合）的开销。"相同交互预算"指相同轮数，不是相同算力。局限性一节只有一句话，谈更广的场景和在线技能进化的效率。
- **未做消融。**结构化抽象记忆、状态门控（对比总是检索）、以及是否使用失败轨迹（对比只用成功轨迹），论文都没有消融。Domain Skill 在每个变体中还同时供记忆更新、门控和融合使用，没有不含 Domain Skill 的变体（表 5 的“粗粒度”一行只检索 Domain Skill，是另一回事）。重试预算的具体数值、以及由哪个 LLM 来写技能和记忆，在我们检索的全文（含附录）中没有给出。
- **表述。**局限性一节谈到“在线技能进化”，而方法在测试时冻结技能库。
- **案例研究。**附录 C 的活塞任务是作为诊断案例挑选的；论文称它用于说明机制，不是统计证据。

## 我们的判断

HarnessRSI 评分 **68**，★★ 档，证据等级 **retained**：被保留的产物（技能库）在留出主题上有帮助。论文报告了留出评测、Trap Skill 消融、迭代次数消融，以及在三个骨干上使用相同交互预算的直接基线。论文没有报告方差、优化或推理成本、算力匹配的对比，也没有在 MMSkills（仅一个基准）之外把进化机制与其他技能学习方法比较；代码已宣布但尚未公开。
