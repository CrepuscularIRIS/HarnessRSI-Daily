Δτ-Bench：工具一直在换，留下的技能跟得上吗？

把大型工具生态的演化做成可执行基准：42 个领域、1,588 个多轮任务、六个依次演化的生态版本。旧接口会退役、拆分、合并，更省的路径会出现——任务成功率会掩盖错过的更短路径。最强模型 / harness 成功率仅 42.3%；现有技能学习方法起步有益，却跟不上后续变化。作者提出 STEWARD：按工具依赖增量维护技能，并在执行中按需供给工具与流程。

01

线路图：同一意图、同一目标状态，六个版本的可用接口不同

每次转换只施加有限个“保能力”的变换：① 一对一（改名、加参数、换格式）② 一拆多 ③ 多合一（只合并已验证轨迹里相邻的调用）。新接口可与旧接口并存（要在重叠中选），也可直接替换（旧流程断掉）。每个版本都校验所有基础能力仍可通过现役接口达成；可选地扰动部分描述，模拟残缺或过期文档。训练 1,191 / 测试 397 个意图 × 6 版本 = 9,528 个任务-生态实例。

02

成功率看不到的损失

参考路径由动态规划在构造出的实现空间内分别求“最少步数”与“最低成本”。只看成功率（终态数据库变化覆盖金标变化）时，继续走旧路的代理不会被扣分；本文另设 SPE（成功加权的路径效率）、IDR（最优路径变短 / 变便宜的任务上是否发现新路）、DAR（最优路径变长时能否恢复）。

04

现有技能方法：起步有益，换站就掉队

同一任务模型（DeepSeek-V3.2）下比较 EvoSkill、AutoSkill、Trace2Skill、SkillOpt 与不用技能。v1 四种方法的成功率与 SPE 都高于不用技能，但：

  • AutoSkill 在 v3、v5 成功率低于不用技能；AutoSkill / EvoSkill 在若干中间版本 SPE 也低于它。
  • 不用技能在 v2 拿到最高 Cost-IDR、在 v5 拿到两项 DAR 最高。
  • SkillOpt 各版本成功率与 SPE 领先，但 IDR / DAR 并不一致领先，技能生成与优化约 3,000K token / 任务，是其他方法的 2–3 倍。
05

STEWARD：把工具和技能当一个系统管

DeepSeek-V3.2 上六个版本成功率都最高，平均 39.04% 对 SkillOpt 36.36%；v2 起其他方法的维护 token 是它的 1.2–5.5 倍。相对每格最强基线，Step / Cost-IDR 平均 +4.04 / +3.69 点，Step / Cost-DAR +5.28 / +4.76 点。

06

对照：同一份 v1 技能库，只换 v2 起的维护方式

两个模型上增量维护在成功率、SPE、IDR、DAR、工具 F1 都最好；比全量重建高 2.22 / 1.82 点，维护 token 少 39.5% / 30.4%。GPT-5.5 上全量重建（38.99）甚至低于直接冻结（39.60）。

供给消融（DeepSeek-V3.2，Fig. 7）：只加技能搜索几乎无提升；只加工具搜索成功率 +8.65、工具 F1 +4.14，但 Step-DAR −2.76；两者合用各项都提升，相对只用工具搜索 DAR 再 +11.41 / +9.30。

均为单次运行，未报告种子方差；1–2 点的差别未必稳定。

07

限制与核对备注

  • 合成生态：服务、任务、变换都由 LLM 在 42 个模拟领域生成并执行校验；一条变化流，不是真实开放 API 的演化。
  • “最优”有边界：参考路径只在构造的实现空间内最优；成本是 LLM 按定义给的 1–10 分，不是实测延迟。
  • 无方差：模型表、技能方法比较、STEWARD 与消融都没有独立种子或置信区间；用户模拟器与技能研究的任务模型都是 DeepSeek-V3.2。
  • 核对备注：Table 2 中 DeepSeek-V3.2 增量维护平均成功率 36.83，与 Fig. 6 中 STEWARD 平均 39.04 口径不同，原文未说明（可能是供给设置或平均范围不同）；本画报两处数字分开引用，不互相推算。
读

本项目读法

能带走的判断：留存技能的价值取决于它跟着工具目录走：过期依赖要能失活、复活；维护最好是局部编辑而非每版重建。评估自演化代理时，只报成功率会漏掉“旧路还能走、新路没发现”的损失，需要像 IDR / DAR 这样以当前可达最优为参照的指标。

问题档位等字段是本项目的阅读判断，不是审稿结论。
