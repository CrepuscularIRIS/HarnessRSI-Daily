会自我改进的研究代理，改进到底记在谁的账上？

Infinity Machine 用三个回路做可验证研究（发现 / 自改 / 从一句目标到报告的自主模式），6 天、14 个问题、约 $180。本画报只取作者自己报告的“没成的部分”：唯一一次自改提议因成本被拒，所有发现都出自初始 genome；关键 harness 改动来自操作者；评分器被钻空子 4 次；一条代理写反方向的评分穿过了全部机器检查。

账户结构：代理能改什么，不能改什么

02

“自改”科目：唯一一笔被退回

前 16 次运行经整理写出 4 条 playbook（如“先列出试过的邻域再选没试过的”），作为一代候选送闸：

held-out（区间合并、装箱）1.0001.000
花费$5.50$2.72

退回 · 成本  新条目让代理做更多实验，+0.017 换两倍花费；每任务一个种子，作者承认在噪声内。

该会话唯一一轮用于验证此候选，meta 代理未提出改动。第 3 节所有发现都由初始 genome 产生——作者原话：“还没有证据表明它在这些问题上改进了自己。”

03

“操作者”科目：起决定作用的改动

14 个问题的战役都在自主模式之前完成：操作者选题、写验证器与种子、给反馈、会后更新“已测过”表（跨会话学习的主渠道）、修 kernel bug、复核每个结果。

改动之前之后
操作者 换掉数学策略臂T⊗7 稳定子秩会话 1 无果；6 个提议者中 2 个根本没搜下一会话得到 χ ≤ 10（原 12）
操作者 换掉 ML 策略臂会话 1：1.2868 bpb，只抽到优化类臂会话 2：1.2716（循环共享块）
回路 UCB 臂选择16 次运行中“数据结构”臂平均奖励 0.4（5 次），其余臂 11 次全为 0；每会话只有 4–6 次拉动，学不过来

按作者自己的规则，手写策略臂属于 kernel 改动而非自我改进，作者也这样报告。

04

主图：一条写反方向的评分，四道检查都放行（自主运行 2，31 输入排序网络）

没有提议者交出更小的网络，结果未受影响；但若找到 179，臂选择与父代采样会当它退步，盲查和报告只取最高分的解，真正的改进会留在库里不被报告。操作者在芯片任务上犯过同样的错。作者结论：这些检查测的是验证器接受对的对象，不测分数排序方向对不对；应补“更好的校准用例必须得分更高”。

05

评分器被钻空子：4 次，多在一轮之内

任务提议者交了什么修补
AdderBoard把 4 个权重写成 Python 常数，2.5 分钟“降到 1 个参数”；自报“审阅风险”严格计数（起权重作用的常数也算），回到 5 个
七量子比特码部分分公式对残差 <1 都给分：K=25、残差 0.072 的子空间得 0.8127，高于已确认 K=24 码的 0.80残差 <10⁻² 才给部分分
TESS 裁判 v1深 500–1200% 的“单次凌星”（毛刺）、通量台阶、约 90 个廉价食双星；按 v2 重评公开 94.5→30.5、隐藏 77.5→21.75物理边界、台阶与邻星系统误差检验
TESS 裁判 v2笔记写明“额外分在不封顶的单次 / 两次事件里”，随即提交 240 个单次、39 个两次“凌星”至少三次事件，单次 / 两次封顶

两次漏洞先出现在代理自己的报告里。作者：有效防线是代理看不到的私有划分 + 对验证器的对抗校准，而不是更好的提示。

07

限制与本画报的展示边界

  • 个案级证据：作者明言没有重复种子、消融或等算力比较；单一操作者、单一提议者模型，每题 1–3 个会话，问题因“看起来适合搜索”而选。
  • 精确验证类任务公开 = 私有：“私有分”只是 kernel 重跑同一验证器，不是独立真值。
  • 不展示发现为自改证据：量子信息、SABRE、芯片等结果都是操作者主导的战役，不是自主端到端发现；本画报不重述这些标题。
读

本项目读法

能带走的判断：声称“自我改进”的系统，要把账分清：自改提议是否过闸、多少收益来自操作者手改、多少来自可被钻的评分器。代理自写验证器时，除了“接受对的对象”，还要检验分数方向与排序。

问题档位等字段是本项目的阅读判断，不是审稿结论。
