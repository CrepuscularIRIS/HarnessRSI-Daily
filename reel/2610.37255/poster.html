用冻结模型挑 harness，
为什么会把更好的那个拒掉？

Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces —— 部署回报 = harness 的上限 − 这份权重的失配。冻结比较把两项混在一起。

01

一个恒等式，两类改动

J = C − M
C 上限：该 harness 下任何策略能拿到的最优（KL 正则）回报，与权重无关
M 失配：这份 checkpoint 沿自己轨迹偏离最优策略所丢的回报（KL 累积）

训练只改 M；换 harness 会同时动 C 和 M。所以“同一权重在新旧 harness 下比分数”，测的是“新 harness 给得多 + 这份权重用得好”的混合。

§2、§5.2 Eq.(8)–(9)；正则化 performance-gap 恒等式（Geist 2019；O’Donoghue 2022）。作者另证：最优策略的 log odds 恰好复原该 harness 诱导的相对动作分数（Prop. 3.1）。

批量点击：冻结时变差，适配后最好

纵轴：KL 正则回报 J（附录 F.3 Table 8 重绘）。山顶 = 上限 C，粉笔点 = 实际回报 J，粉线 = 失配 M。

新 harness 只把上限抬高 0.012，却让冻结权重的失配多出 0.123：冻结比较会拒掉它。两支从同一权重、同预算、同任务抽样出发；在 H1 下适配到失配低于门槛后，既超过源对，也超过 H0 续训。

05

九次被冻结比较拒掉的换装

30 个有序换装里冻结比较拒掉 22 个，其中 9 个门槛 T > 0。抬高上限的 7 个适配后全部超过源对；降低上限的 2 个没有收益。8 个事前登记的预测与实测排序 Spearman ρ = 0.95；冻结时的回报变化只有 ρ = 0.17（只看上限差 ρ = 0.86）。

07

边界

  • 精确结论来自有限 MiniWoB++ 图、单 token 动作菜单、2B 模型；每支训练只跑一次，区间是任务 bootstrap，不是种子方差。
  • 回报差很小（恢复 +0.0084）；成功率与正则回报可以不同向，例如 H2→H5 回报 +0.045 但成功率 −0.5 点。
  • “适配后反超”需要更新权重。对只改 harness、权重永远冻结的闭环，冻结回报就是它实际拿到的；本文改变的是“怎么解读一次冻结比较”。
  • 编码代理部分只验证排序，教师不是最优，C̃ 是上限的下界估计。
本项目读法：harness 改动的评测应把上限与冻结分数并列报告，并在多个 checkpoint 上测；只改呈现方式就可能让后训练模型大幅掉分，先排查读出漂移再下结论。
