判卷模型上线后会“漂”：何时、怎样重调它的提示词？

500 条对话流中，人工参考分数的构成在第 214 条后突变，固定提示词的 judge 误差上升。用陆续到达的参考分数反复重调提示词能把优势找回来，但通常回不到突变前；哪种优化器、什么时候触发，都没有通用答案。

评测协议：每条对话先由当前提示词打分再拿到参考分（“理想、即时、无噪声”的反馈），优化只能用已到达的记录。默认样本选择 NewElements：训练 = 上次更新以来的新记录，开发集 = 上次更新的训练记录。比较对象：同一条流上一直用初始 G-Eval 提示词的静态 judge。

没有通用最优优化器§4.2 · 图 2 · 23 个参数化配置 × 2 后端 × 3 次

  • 两个后端的误差–token 帕累托前沿形状差别很大，两边都在前沿上的只有 Rubric(S) 与 Rubric(M)。
  • GPT：最低平均 MAE 约 0.48 来自 SIMBA(S)→Rubric(M)，不少配置多花 token 却不降误差。
  • Gemma：前沿从三种 Rubric 一直延伸到 SIMBA(M)（约 1870 万 token、MAE 0.5）；SIMBA(L) 用约 2630 万 token 也没更好。
  • Rubric Synthesis 便宜、常上前沿，却在突变后掉得最狠——作者认为像是对突变前反馈“专化”，但明说没有证明因果。

token 只在同一后端内比较；三次重复只够做筛选，不足以给出确定排名。

量程之外：结论不覆盖什么§3、§5、§6

  • 反馈是理想化的：每条对话都立即拿到三人参考分均值；真实部署的稀疏、延迟、噪声、分歧与采集成本都没有模拟。
  • “漂移”是把同一数据集按参考分构成重排造成的，人类评价政策和 judge 模型本身都没变；也没有按构成分层报告误差。
  • 一个基准、500 条流、每种流 3 条采样流、两个 judge 后端；控制器实验更窄。
  • 改进以同一条流上的参考分衡量，没有独立的长期回归标准集，也没有显式回滚 / 作废旧评分的机制。

改变的判断

LLM judge 不是“调好一次就能一直当真值”的组件：被评对象的构成一变，固定提示词的一致性就会下降；用到达的反馈持续重调能找回相对优势，但要同时决定何时触发、用哪些记录、花多少钱，而这些选择因 judge 后端而异。

本项目读法：对把 LLM judge 用作留存 / 晋级信号的自改进系统，这意味着评价器本身也需要随流复核；本文在理想反馈下证明了“可以维护”，没有证明“可以部署”。
