AGENT 技能自演化 · 归因错位问题 · ARXIV 2611.25429 · SKILLPLUMBER

失败是指令写错了，还是 agent 没听指令？

按整条运行结果评失败，分不开这两个成因：写错该改指令，没听该改表述。SkillPlumber 用指令级覆盖标注（follow / not-follow / not-covered）把归因拆开，只在覆盖显示不足处演化技能。

成因 A：指令本身错了

agent 忠实执行了技能里的某条指令，行为与失败直接相连——guidance 本身不正确、误导或在该情境下不充分。

应改：修正 / 删除该条指令

vs
整 run 评判
分不开

成因 B：指令没错，没被遵守

情境出现了、agent 却跳过了正确指引（如“USD 需换算”被无视）。指令可能只需更容易被遵守。

应改：澄清表述 / 适用条件，而非重写

机制：覆盖引导的技能演化管线 每次修订由下一次运行检验；同一 RCA 会话跨修订持久，可撤回没用的改动

① 覆盖判定

不看运行结果，只看轨迹

覆盖 judge 对每条可执行指令标注：follow（情境出现且遵守）/ not-follow（出现未遵守）/ not-covered（情境未出现）。judge 不见 verifier 反馈、不解释失败、不提修改。

输入 技能+任务+轨迹 → 输出 逐指令标签
→

② RCA 诊断提问

持久会话，跨修订累积证据

每类标签转成一个问题：not-follow——遵守会有帮助吗、为何没遵守？follow——指令本身错在哪？not-covered——这任务需要它吗？还查轨迹里技能缺失的指引；可质疑标签本身。

假设+预测 随修订提交，下轮对账
→

③ 修订与检验

新执行器只见技能+任务

修订可澄清指令、纠错、删误导、补缺失步骤或撤回上轮改动；由全新执行器跑一次该任务检验，首过即停（回放复检另测）。

每失败任务 ≤5 轮；预算内自判 Stop
→

④ 跨任务维护

3 任务一批，维护者蒸馏

维护者读批内诊断/修订/结果，更新共享策略库供后续任务参考；RCA 可拒绝不适配的策略。消融显示增益不靠策略库。

执行器与 judge 不接触策略库

限制：覆盖标签来自 LLM judge，可能误标（更强 judge 可直接替换，框架不变）；agentic 修订 token 开销约为基线 2 倍——但每恢复一任务 token 可比（附录 G）；修订设定沿 SkillRevise 的同任务修复协议，技能复用于同一任务，非跨任务泛化；脚本等技能资源未被修订。
