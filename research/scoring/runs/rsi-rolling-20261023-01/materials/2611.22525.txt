arXiv: 2611.22525    title: When Agent Skills Go Stale: Runtime Behavior and Selective Maintenance in Evolving Environments

[abstract]
Agent skills use past experience and current observations to guide decisions and actions on related tasks. This experience is retained in skill state, whose reuse can amortize inference-time reasoning and environment interaction. When environment changes, parts of this state can become outdated while others remain useful. Across four task settings and two models, we compare skill reuse before and after environment changes. Previously beneficial skills can reduce task performance by over 10 percentage points or increase execution cost by nearly 40% relative to no skill. Task success can also remain unchanged while execution savings decline. These effects depend on which environment-specific details become outdated and the agent's ability to compensate using current observations. We introduce selective maintenance, which replays checks from successful executions without additional model calls. It verifies whether observed differences conflict with skill state, repairs affected content, and validates updates, rebuilding when local repair is insufficient. No description of the change is supplied. Relative to reusing stale state, maintenance improves task accuracy by up to 67pp and reduces execution steps by up to 37%. These results suggest that preserving a skill's inference time value as environments evolve requires selectively maintaining its state.

Agent systems increasingly reuse prior experience to guide decisions and actions on related tasks, often through representations referred to as "skills" ( Wang et al., 2023 ; Wang et al., 2024 ; Zheng et al., 2025 ; Jiang et al., 2026 ) . Skills use past experience together with current observations to inform future behavior, while experience dependent information retained across executions forms part of a skill’s state. Reusing this state allows previously learned decisions and procedures to be reused rather than reconstructed from scratch. In this sense, skills instantiate a broader view of learning as amortizing future inference-time computation: experience retained today can reduce the reasoning and environment interaction required on later tasks ( Achille and Soatto, 2026 ) . This amortization, however, depends on the continued validity of the retained skill state as the operating environment evolves. A software update, for example, may rename an API endpoint while preserving the rest of a workflow, so most stored knowledge remains useful although one operational choice has become invalid. Figure 1 illustrates the same phenomenon for a Model Context Protocol (MCP) server: a saved connection setting conflicts with a new communication requirement, while the remainder of the procedure remains applicable. We call skill state stale when an environmental change makes some retained information no longer valid for guiding decisions or actions in the current environment. Reusing stale state can reduce task performance. Alternatively, the agent may detect the mismatch from current observations and compensate through additional reasoning or environment interaction. Such runtime recovery can preserve task success without correcting the retained state for future use. We therefore measure both task performance and execution cost relative to a no-skill baseline , in which the same agent operates without access to the retained skill state. Prior work evaluates reusable skills ( Li et al., 2026b ; Han et al., 2026 ; Liu et al., 2026c ; Lei et al., 2026 ) , studies changing tool interfaces and executable environments ( Chen et al., 2025 ; Liu et al., 2025 ; Guo et al., 2025 ; Li et al., 2026a ) , and examines skill-library evolution ( Liu et al., 2026a ; Pu et al., 2026 ; Shen et al., 2026 ; Fan et al., 2026 ) . Our focus is how an environmental change alters the benefits of reusing the same skill state: when it remains useful, when it increases cost or lowers performance, and whether selective updates can recover the benefits of reuse. We investigate two factors that help explain the effects of stale skill state. The first is which environment-dependent choices the saved state fixes in advance. Instructions can explain how to find a current field identifier or store an identifier found earlier. We call the extent to which choices are fixed in advance operational specificity . Using the same source material, we construct procedural variants that retain inspection and derivation steps, and cache-heavy variants that store resolved values and commands without those discovery steps. The second factor is the agent’s ability to recognize and compensate for outdated state. An agent may follow a saved instruction, inspect the current environment, or revise its action using that evidence. We evaluate two models across four settings: TerminalBench-2 (TB-2) ( Merrill et al., 2026 ) , historical IRS tax forms, AppWorld ( Trivedi et al., 2024 ) , and ScienceWorld ( Wang et al., 2022 ) . Each agent combines an LLM with a harness that manages tool use and execution. For each paired environment change , the task objective remains fixed. Changes include software and configuration updates, revised form fields, renamed API endpoints, and moved objects. For each model, we keep the harness fixed and compare reuse of the same saved state against the no-skill baseline in both versions. Execution cost is measured in agent turns or, for ScienceWorld , environment steps. After a change, saved state can still improve performance while providing smaller cost reductions. It can also lower performance despite reducing cost, or perform worse and cost more than the no-skill baseline. On TB-2 and tax-form completion, cache-heavy variants generally save more work before a change but lose more of their performance benefit afterward. The variants behave similarly on AppWorld and ScienceWorld , where the change affects choices stored by both. In the tax-form analysis, the stronger model more reliably overrides outdated instructions after inspecting the current form. Across our tested conditions, however, outdated state sometimes lowers the stronger model’s performance below its no-skill baseline, while the weaker model continues to benefit from it. These findings show why task success alone cannot establish whether reuse still saves work. The findings also suggest when to maintain skill state.
