arXiv: 2611.23266    title: Skill Roulette: Measuring Skill Invocation Rate Across LLM Coding Agents

[abstract]
Agent skills package procedures for large language model (LLM) coding agents. An agent selects a skill from its name and description before reading the procedure. It may complete the task without invoking a relevant skill. We investigate how reliably coding agents invoke relevant skills and which factors affect that decision. We estimate invocation rates by repeating trials with identical inputs; invocation rate is the proportion of trials in which the agent invokes the relevant skill. We test 9 non-directional hypotheses about skill metadata, competing skills, contextual instructions, and task wording and composition. Eight concern invocation; the ninth tests whether making a skill available changes the occurrence of an action that the task does not request. We use tasks from 4 software engineering categories in a synthetic repository, running each of 4 coding-agent harnesses with 2 models. The planned 20,400 trials include 60 repetitions per Baseline category and configuration, 60 more per category in Claude Code with Sonnet 5.5 that admit each category's task and skill, and 10 per experimental condition. Comparisons are specified before collection and evaluated within each model and harness configuration using Boschloo's exact test.

An agent skill is a file containing a procedure that a large language model (LLM) coding agent should follow for a class of tasks. The agent first reads the skill’s name and description, assesses its relevance, and decides whether to load the body ( Anthropic, 2026e ) . The procedure can guide the agent only after the skill body loads (Figure 1 ). Successful task completion does not establish whether an agent invoked a relevant skill or followed its procedure. A trace can establish whether the skill was invoked, but deciding whether it should have been invoked requires an assessment of its relevance. When a missed invocation matters, a developer can supply the procedure directly or require the agent to invoke the skill. Understanding when such omissions occur is a prerequisite for detecting and correcting them in autonomous workflows. Invocation reliability becomes particularly important when a workflow requires several procedures. If 4 invocation decisions are independent, each has a probability of 0.6, and there is no recovery, the probability that all 4 skills are invoked is about 13%; at 0.5 each, it is about 6%. Dependencies and recovery mechanisms can change these probabilities. This study addresses whether an available, relevant skill is invoked reliably and which changes to its metadata, task, or context affect that decision. We estimate invocation rates by repeating trials with identical inputs. The study tests changes to skill metadata and pool composition (H1–H4), instructions and task wording (H5–H7), and the combination of tasks in a single prompt (H8). H9 asks whether making a skill available changes the occurrence of an unrequested action. We run tasks from 4 software engineering categories under 8 combinations of coding-agent harness and model. Each experimental condition has 10 repeated trials ( ); the Baseline has 60 per category and configuration to check invocation for a clearly relevant skill. We specify the task and skill construction, experimental conditions, and comparisons needed to measure invocation separately from task completion. We will release the repository, skill inventory, and trial records for replication with other harnesses and models.
