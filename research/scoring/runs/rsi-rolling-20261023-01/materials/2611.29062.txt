arXiv: 2611.29062    title: HyperHarness: Learning to Generate Personalized Agent Harnesses from User Histories

[abstract]
Personalized LLM agents rely on an agent harness, the surrounding memory and control code, to connect user history with downstream decisions. Existing methods typically employ either a single shared memory workflow across all users, which is efficient to deploy but cannot adapt how evidence is retrieved and interpreted across diverse histories, or per-user harness optimization, which customizes behavior for each user but requires costly repeated candidate evaluation at deployment and suffers from sparse, noisy supervision in raw logs. To address this trade-off, we present HyperHarness, a framework that learns a shared history-to-harness generator to synthesize executable, user-specific retrieval and answer-guidance code directly from user histories. Given a user's permitted history, HyperHarness prompts a construction LLM to write personalized retrieval and guidance functions, while downstream task scores across training users supervise iterative refinements to the shared generator without reference harnesses or answering-model updates. At deployment, the frozen generator constructs a harness for each unseen user in a single pass from history alone, eliminating per-user task-scored search. Across three benchmarks (PersonaMemv3, Mem-PAL, and MemoryCD) and three answering models (Qwen3.5-9B, Qwen3.8-27B, and GPT-5.6-Luna), HyperHarness achieves the highest aggregate score in seven of nine settings and ranks second in the remaining two, improving over the strongest baselines by up to 5.95 points while cutting matched answer-time tokens by 90.32% over long-context prompting. Analyses show that optimization tailors context allocation to each executor, transfers to unseen user clusters, and amortizes adaptation costs.

Personalization is a core component of user-facing AI systems because it connects raw user behavior with downstream decisions about what content, recommendations, or responses should be presented to each individual ( Tan and Jiang, 2023 ; Kirk et al., 2024 ; Salemi et al., 2024a ; Tan et al., 2024a ) . As large language models (LLMs) evolve from static text generators into interactive agents, adapting to a user involves not only what the model says, but also the execution procedure used to reach an answer: which historical records to consult, how to reconcile conflicting or noisy evidence, and when to restrain personal context ( Chen et al., 2024 ; Cai et al., 2025 ; Yin et al., 2026 ) . In agentic systems, this decision process is governed by an agent harness , the surrounding executable code and instructions that control how memory is stored, retrieved, and applied ( Packer et al., 2023 ; Xu et al., 2025 ) . A central design choice in agent personalization is how to construct the harness that connects a user’s interaction history to runtime execution. Existing approaches mainly follow two paradigms: shared memory workflows and per-user harness optimization. In practice, shared workflows, such as long-context prompting, fixed top- retrieval, or uniform rolling summaries ( Salemi et al., 2024a ; Salemi et al., 2024b ; Richardson et al., 2023 ) , are the dominant choice because they can be deployed immediately to any user without per-user search. However, applying a single fixed procedure to every user overlooks substantial heterogeneity in how users express preferences and how their histories are structured. A compact summary may suffice for stable tastes, whereas shifting or multi-faceted interests require targeted multi-query retrieval and explicit disambiguation; simply packing more raw history into the prompt is token-intensive and frequently distracts the answering model with irrelevant records ( Shi et al., 2023 ) . In contrast, automated agent and harness optimization methods ( Hu et al., 2025 ; Zhang et al., 2025a ; Robeyns et al., 2025 ; Zhang et al., 2025b ; Agrawal et al., 2026 ; Lee et al., 2026a ; Yang et al., 2026 ) offer the flexibility to customize prompts or executable workflows through evaluation feedback. However, running task-scored search separately for each user faces two key challenges. First, repeated candidate generation and evaluation incur heavy token and latency overhead before the agent can serve a new user, often exceeding context budgets as histories grow. More importantly, an individual user’s raw interaction log provides sparse and indirect supervision by mixing enduring preferences, temporary intent, and incidental exposure ( Tan et al., 2025a ; Jiang et al., 2025 ; Tan et al., 2025b ) , and there is no ground-truth reference harness specifying how that user’s evidence should be retrieved or applied. This exposes a clear trade-off between deployment efficiency and user-specific procedural adaptation: shared workflows are lightweight to deploy but rigid across users, whereas per-user search is expressive but costly and difficult to supervise at deployment. We resolve this trade-off by shifting optimization from individual users’ harnesses to a shared construction procedure. We propose HyperHarness , a framework that learns a reusable history-to-harness generator capable of synthesizing executable, user-specific retrieval and answer-guidance code directly from a user’s history (Figure 1 ). Inspired by hypernetworks that generate target network weights ( Ha et al., 2017 ) and generation-based parameter adaptation ( Phang et al., 2023 ; Ivison et al., 2023 ; Tan et al., 2026a ) , HyperHarness extends amortized generation from static profiles or adapter weights to executable procedures that govern both which personal evidence is recalled and how it guides the answering model (Appendix C.5 ). Specifically, given a user’s permitted construction history, HyperHarness organizes the historical records into structured evidence and prompts a frozen construction LLM to write user-specific code for memory retrieval and answer guidance under bounded host validity checks. During training, we keep both the construction and answering models frozen and optimize the shared generator’s code and prompts across training users using downstream task scores. Much as textual user profiles can be optimized through downstream utility without ground-truth summaries ( Gao et al., 2025 ; Tan et al., 2026b ) , supervising the generator via downstream task performance eliminates the need for reference harnesses while allowing the generator to discover which historical patterns call for which retrieval and guidance designs. At deployment, the selected generator is frozen and constructs a personalized harness for an unseen user in a single pass from history alone, requiring no task-scored per-user search and amortizing optimization cost across the user population.
