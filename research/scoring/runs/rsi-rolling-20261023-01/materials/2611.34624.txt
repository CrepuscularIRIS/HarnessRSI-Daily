arXiv: 2611.34624    title: HoMe: Toward Practical Harness Optimization of Memory Systems for AI Assistants

[abstract]
The behavior of memory systems for long-running AI assistants is governed by a harness, which consists of the code, prompts, and configurations for memory construction, maintenance, retrieval, and answer generation. However, optimizing the harness of a memory system remains largely manual, and unrestricted editing alone does not ensure structural improvements. In this paper, we introduce HoMe, an evaluation-driven framework that iteratively evaluates candidate harnesses and derives each new candidate from any previously evaluated harness by editing any part of it. HoMe combines session-level memory versioning with execution traces to identify shared failure mechanisms across cases and localize them to the responsible sessions and harness components. It encourages early structural exploration through candidate gating and reduces evaluation cost through smoke tests, adaptive sampling, and the reuse of constructed memory. We validate HoMe with the open-source memory system ReMe on two large-scale long-horizon memory benchmarks, LongMemEval-S and BEAM. With six formal candidate evaluations per benchmark, after a full initial evaluation, HoMe discovers harnesses that improve end-task performance over the originally strong harness while consuming far fewer query-time tokens. The code is available at https://github.com/agentscope-ai/ReMe.

[intro/head from cached fulltext]
Long-running AI assistants accumulate conversational and episodic experience through continued interaction, and they depend on a memory system to turn that experience into consistent and personalized behavior across sessions ( Packer et al., 2023 ; Chhikara et al., 2025 ; Xu et al., 2025 ; Zhong et al., 2023 ; Wang and Chen, 2025 ) . In practice, memory is not merely persistent storage but a standalone system built around a language model, exposing interfaces for a target agent to store and retrieve information as needed. Many such systems are file-native, i.e., maintaining memory as files ( Zhou et al., 2026 ) . Three components govern the system behavior: the code that implements memory construction, maintenance, retrieval, and answer generation, along with associated evaluation and recovery mechanisms; the prompts that instruct the language model at each stage; and the configurations that determine the memory schemas, indexes, thresholds, etc. We call this collection of code, prompts, and configurations the harness of a memory system. Different AI assistants often have different demands on memory data management. For example, a medical assistant stores symptom histories and medication details that must be preserved faithfully, whereas a scheduling assistant stores event states that are revised repeatedly and should be superseded rather than accumulated ( Wu et al., 2024 ; Wu et al., 2026 ) . Hence, the harness of a memory system must be optimized before deployment to achieve acceptable results on application-specific evaluations ( Yao et al., 2026 ; Zhang et al., 2026 ) . The same effort is required again after deployment, because growing interaction histories and shifting user behavior expose failures that could not be anticipated beforehand. This process is extremely time-consuming due to the huge search space and is still carried out manually, which raises a timely and important question: how can the harness of a memory system be optimized automatically? Prior work has largely treated the harness of a memory system as an artifact to be designed. Most efforts propose new architectures and retrieval strategies ( Packer et al., 2023 ; Gutiérrez et al., 2024 ; Xu et al., 2025 ; Rasmussen et al., 2025 ; Pan et al., 2025 ; Kim et al., 2025 ; Fang et al., 2025 ; Sun et al., 2026 ) , or grant the target agent control over memory operations, such as deciding what to write and when to retrieve ( Zhang et al., 2024 ; Hu et al., 2025 ) . Recent work automates memory harness optimization. EvolveMem ( Liu et al., 2026b ) optimizes retrieval strategies through autonomous research. MemPro ( Liu et al., 2026c ) optimizes memory construction and retrieval, largely delegating failure diagnosis and revision planning to its evolving agent. MStar ( Pan et al., 2026 ) jointly optimizes memory schemas, read and write code, and instructions through population-based search. However, full-harness editing alone does not ensure structural exploration. In our ReMe-based optimization experiments, all candidates proposed by MemPro modify prompts or parameters, despite executable-code edits being permitted. This motivates explicit mechanisms that connect failures across cases to the responsible harness components and guide structural exploration under a limited budget. In this paper, we move one step further and introduce HoMe, an evaluation-driven framework that guides free-form memory-harness optimization through cross-case mechanism diagnosis and early structural exploration. Our framework is inspired by Meta-Harness ( Lee et al., 2026 ) , a general scheme that delegates harness optimization to a code agent, which reads a harness with its evaluation evidence and returns a revised harness. At each iteration, HoMe diagnoses the optimization history, including all the harnesses proposed so far, the memories they constructed, and their evaluation results. It then performs arbitrary edits to propose a new candidate harness and evaluates it accordingly. The loop continues until it reaches the iteration limit and selects a final harness. However, applying such a flexible harness optimization scheme to a memory system for AI assistants is not viable, because the system operates over a long horizon (e.g., exceeding thousands of messages ( Tavakoli et al., 2025 ) ), which raises two challenges . First, accurate diagnosis is essential yet difficult ( Yan et al., 2026 ) . A query is answered from memory accumulated over hundreds of preceding sessions, and a low score may originate in how a session was segmented and written, in a later revision that overwrote relevant content, or in the retrieval procedure that selected what was returned. Without locating the responsible part of the harness, there is little guidance on what to change, and iterations are easily wasted on unrelated edits. Second, evaluation is prohibitively expensive.
